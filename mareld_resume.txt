3. "THE TICK" PIPELINE (lib/environments/ecosystem.py)
================================================================
Random FG order each tick. Per tick - order per Method.pdf Section steg 1-6
(impact mortality applied BEFORE predation):
  _calculate_decisions -> _apply_impact_mortality -> _apply_predation
  -> _apply_movement -> _apply_growth

  1. _calculate_decisions  (batched over all DMs)
     - obs_batch (N_dm, max_in_dim, H, W). Each DM i writes a compact
       per-DM layout in the top per_dm_in_dim[i] slots; remaining slots
       are 0-padded. See Section 4 and Section 41 for the per-DM
       formula driven by the Observability matrix.
     - B_others channels for OTHER DMs use VISIBLE biomass
       B_visible = B_all * (1 - prev_hidden_frac), where
       prev_hidden_frac is the previous tick's pi_rest. ``Rest`` is a
       hide action (Section 41); the rested fraction is invisible to
       other FGs in the next tick. B_own (the observer itself) uses
       FULL biomass; an FG always sees its own full mass.
     - Raw-obs stats accumulated for trainer merge.
     - If env.obs_mean/obs_var set: obs clipped/normalised before forward.
     - All DM policies in one batched torch.bmm forward (weights padded
       to max_in_dim with zero columns for per-DM compact layout).
     - Output: pi_move (N_dm,4,H,W), pi_rest (N_dm,H,W), pi_eat
       (N_dm,N_all,H,W). Masked before renormalisation.
     - After pi_rest is finalised, prev_hidden_frac is rewritten to the
       current tick's pi_rest for use in the NEXT tick's observation.
  2. _apply_impact_mortality
     - Per (FG, impact): linear interpolation in impact_table; clip to
       endpoints. B reduced, R scaled so E=R/B preserved on survivors.
  3. _apply_predation  (fully vectorized)
     - hidden_frac_now = current tick's pi_rest (per DM-prey, NDMs=0).
       B_prey_visible = B_prey_all * (1 - hidden_frac_now). The hidden
       (rested) fraction is fully protected this tick.
     - D = B_pred*pi_eat*max_intake*hunger; with Holling-II,
       a_eff = a / (1 + a*h*B_prey_visible). Demand-cap uses
       B_prey_visible. Predator energy gain buffered to
       temp_energy_gains. See Section 41 for tick-asymmetry rationale.
  Sub-threshold cells: NO move-mask zeroing. Instead env replaces those
  cells' distribution with a one-hot argmax over the full 11-action set.
  See section 20.
  4. _apply_movement  (slice-assign over N_dm)
     - Per-action fraction pays metabolic cost * resting_metabolism.
     - Slice-assign (no np.roll). Energy follows biomass. temp_energy_gains
       added to stayers AFTER metabolism.
  5. _apply_growth
     - NDM: logistic dB = MG*B*(1 - B/CC); B clipped to [0, CC].
     - DM: s=R/(B*ME), u=maintenance_level (default 0.3), q=s-u,
           growth=B*MG*q.
         * Positive: only B updated (Variant B) -> energy dilution.
         * Negative: B and R scaled identically (E preserved).

4. POLICY NETWORK DIMENSIONS
================================================================
Per cell the policy sees the von Neumann neighbourhood (the cell
itself + its 4 cardinal neighbours N, E, S, W) per Method.pdf. Out-
of-bounds neighbours are zero-padded. Neighbour order is fixed
N, E, S, W (matches AccessN/E/S/W in Method.pdf). Built by
lib/environments/ecosystem.py:_build_observation_batch and the
matching dimension calc is train.py:get_dynamic_policy_params.

Input layout (one observation vector per cell, per DM i):

  Let k_i = number of OTHER FGs that DM i observes per the Observability
  matrix (Section 41). Self is always implicitly observed via B_own and
  is NOT counted in k_i. Legacy projects without any _observes_ keys in
  interaction_definitions fall back to k_i = N_all - 1 (sees everyone),
  which is byte-identical to the pre-observability formula.

  center : [B_own, E_own, B_obs (k_i), impacts (n_obs)]
  N      : [B_own,        B_obs (k_i), impacts (n_obs)]
  E      : same shape as N
  S      : same shape as N
  W      : same shape as N

  center_dim_i = 1 + 1 + k_i + n_obs   # B_own + E_own + obs + impacts
  nbr_dim_i    = 1     + k_i + n_obs   # B_own + obs + impacts (no E)
  in_dim_i     = center_dim_i + 4 * nbr_dim_i

  max_in_dim   = max over DMs of in_dim_i (used for batched bmm padding)

Channel semantics:
  B_own      Own-FG biomass at that cell (tonnes; raw, before obs
             normalisation). Tells the policy "how many of me are
             here / next door".
  E_own      Own-FG energy fill ratio s_X = R / (B * ME) at the
             center cell, in [0, 1]. Only on the center (neighbour
             energy is intentionally NOT exposed - Method.pdf).
             Drives hunger: low s_X -> hungrier -> stronger Eat.
  B_obs      Biomass of every OTHER FG the DM is configured to
             observe (k_i channels), in stable global order
             (env.obs_others_idx[i] indexes into global_fg_order).
             Includes both DMs and NDMs that this DM observes;
             excludes self (covered by B_own) and any FG that this
             DM does NOT observe per the Observability matrix.
             Same k_i channels appear on center and on each of the
             4 neighbours so the policy can compare local vs
             one-step-away density. VALUES are visible biomass
             B_visible = B * (1 - prev_hidden_frac) (Section 41):
             the fraction of the observed FG that rested last tick
             is invisible.
  impacts    Values of every impact_id flagged "Observable by
             policy" in the project (one channel per id, e.g.
             windfarm_noise). Raw map values; muted/unobservable
             impacts are excluded from the input but still applied
             in _apply_impact_mortality.

Output layout (one logit vector per cell, per DM):

  out_dim = 5 + N_all_fgs
          = [Move_N, Move_E, Move_S, Move_W, Rest, Eat_<fg1>, ...
             Eat_<fgN>]

  The 4 Move slots correspond to the same N, E, S, W order as the
  neighbour observation channels. The Eat block has one slot per
  FG in global_fg_order; slots outside the predator's menu are
  permanently masked to 0 by the environment (so the network can
  emit them but they never fire). Final action probabilities come
  from softmax(logits / T), with T annealed from --temp_start to
  --temp_end over --temp_anneal_gens generations.

Backwards-compat note: an earlier resume revision listed
  in_dim = 2 + (N_fgs - 1) + n_observable_impacts
which is exactly center_dim above with k_i=N_all-1. That formula
was incomplete - it ignored the 4 * nbr_dim contribution from the
von Neumann neighbours. Current (and correct) formula is the
per-DM one above; setting k_i = N_all - 1 reproduces the legacy
"see everyone" behaviour bit-for-bit.

Batched bmm with per-DM in_dim_i: env._rebuild_batched_weights pads
each DM's W1 to (max_in_dim, hid) with zero rows for the unused
top slots. Since the observation tensor also pads those slots with
0, the padded rows contribute nothing to any DM's forward. Hidden
width and out_dim remain uniform across DMs (out_dim = 5 + N_all).

Checkpoint invalidation: changing the Observability matrix (k_i
shifts), toggling "Observable by policy" on impacts (changing
n_obs), adding/removing an FG (changing N_all), or changing the
grid in a way that affects per-cell layout changes in_dim_i and
invalidates existing .pth checkpoints (full retraining required).
The 4x neighbour expansion means even one new observable impact
bumps in_dim_i by 5, not 1.

7b. REFERENCE GRID & BIOMASS SCALING (project_metadata)
================================================================
Each project stores a reference grid (Rx, Ry) in
project_metadata.reference_grid_width / reference_grid_height. All
biomass values entered in fgconfig (FG editor's initial_biomass_min/
max and the Inference tab's inference_initial_biomass) are defined
for that reference grid.

At runtime in load_project_config:

    biomass_scale = (H_act * W_act) / (Rx * Ry)

* mode='train':  min_b *= scale; max_b *= scale; min_b clamped to
                 >= 1.0 ton; max_b clamped to >= min_b.
* mode='inference': total_b = max(inference_initial_biomass * scale, 1.0).

Legacy projects without reference_grid_* keys fall back to 60x60.
Sub-3 values are rounded up to 3 by _as_pos_int.

9. ARS TRAINER (lib/runners/trainer.py)
================================================================
ARSTrainer(env_builder, policy_params,
           sigma=0.1, lr=0.02, n_deltas=8,
           n_workers=1, alpha=1.0, beta=1.0,
           obs_normalize=True, top_deltas=None,
           entropy_coef=0.0, argmax_penalty=0.0,
           integral_reward=True, uniform_bias_init=False,
           hidden_layers=2, hidden_dim=30, activation="sig",
           survival_bonus=0.0, survival_threshold=0.01)

  survival_bonus / survival_threshold: Section 48 Variant B time-to-
  death bonus. CLI --cappa maps to survival_bonus (default 1.0 in
  train.py; the constructor itself still defaults to 0.0 for legacy
  parity in library users). Adds cappa*(t_survive/n_ticks) to per-FG
  fitness, where t_survive is first tick where biomass drops below
  survival_threshold*b0 (else n_ticks). Plumbed through both
  _evaluate, _evaluate_coevo and the parallel-worker mirrors.

  policies: persistent {fg_id: PolicyNetwork} across generations.
  obs_stats: persistent {fg_id: {mean (D,), var (D,), count}} across
             generations; frozen during a rollout, updated via Welford
             parallel merge after each train_step.
  top_deltas: None -> all n_deltas used.
  _pool: spawn-context Pool when n_workers > 1.

train_step(fg_to_train, n_eval_ticks=2):
  1. Sample n_deltas directions.
  2. Draw pair_seeds[i] (one per delta pair).
  3. Build (N_dm, D) obs_mean/obs_var from obs_stats.
  4. Evaluate +sigma*delta and -sigma*delta with SAME pair_seed (CRN).
  5. Parallel tasks: (fg, weights_snapshot, n_eval_ticks, alpha, beta,
     seed, obs_pack). Return (fitness, samples).
  6. Fitness: delta_b = log((bh+eps)/(b0+eps)), delta_r similar,
              fitness = alpha*delta_b + beta*delta_r
                        + survival_bonus*(t_survive/n_ticks)
              (last term off when survival_bonus=0). See Section 48.
  7. Welford parallel merge of obs_stats.
  8. ARS-V2 update with top-b sigma normalisation.

10. CO-EVOLUTION LOOP (train.py main)
================================================================
Round-robin per species OR joint-rollout coevolution (default).
For each gen:
  - _refresh_world_list_if_needed(gen, iter) (re)samples WorldList =
    [(impact_seed_m, spawn_seed_m), ...] of length M, governed by
    --worlds_refresh (iteration|generation). Published to
    trainer.world_list and exposed as _current_world_list[0] for the
    legacy single-world install path.
  - _install_generation_worlds(gen) consumes _current_world_list[0]
    and builds _EnvBuilder with:
      * impact_seed -> impact map snapshot (impact_maps_snapshot)
      * spawn_seed  -> per-generation spawn snapshot, forwarded into
        load_project_config / setup_full_mareld_mvp so all
        deltas/workers in this generation see identical biomass maps
        per FG.
    _install_generation_maps is kept as a backward-compatible alias.
  - Worker pool rebuilt only when the WorldList actually (re)sampled.
  - For species in target_species: iter_per_gen train_step calls.
    Trainer's M-loop reads trainer.world_list and runs M rollouts per
    (delta, sign) pair with CRN coupling (see Section 28).
  - Generation header prints elapsed wall time, e.g.
    "========== Generation 2/100 (T=1.000) (01:14:55) ==========".
    Elapsed clock starts just before the first generation (after the
    interactive prompt), formatted as HH:MM:SS.
  - _save_checkpoint writes {'state_dict','obs_stats'} per generation.

KeyboardInterrupt handling: train.py calls os.setpgrp() at startup so
the parent process gets its own process group. TTY-delivered SIGINT
then only hits the parent (never the spawn-bootstrapping workers,
which would otherwise each dump a multi-page traceback during their
`import torch`). Workers also install signal.SIG_IGN in _worker_init
as backup. The parent catches KeyboardInterrupt, calls trainer.close()
(terminates pool fast), saves final checkpoints, returns cleanly.

New format (saved by train.py):
    torch.save({'state_dict': policy.state_dict(),
                'obs_stats': {'mean': fp32(D,), 'var': fp32(D,),

                np.float32).copy()

                np.float32).copy()
    else:
        policy.load_state_dict(ckpt)         # legacy file

- obs_stats: each .pth stores only its own species' stats.

20. SPAWN / SUB-THRESHOLD FIX (structural)
================================================================
Discovered cause of seals/porpoises "rest=100%" attractor:
min_split_biomass=50 kg combined with seals total=25 ton / 60x60 grid
= 6.94 kg/cell meant most cells were under-threshold; the old rule
zeroed move-actions, forcing rest=100%.

Two coordinated fixes:

DEL 1 - Cluster-spawn helper _spawn_biomass_distribution (legacy):
  * Eligible cells = allowed_mask>0 (None => full grid).
  * Per-cell floor = 10 * min_split_biomass.
  * Loop: random cell pick, biomass drawn uniformly in
    [floor, min(total_b, remaining)], assign, repeat.
  * Leftover (<floor) merged into a randomly chosen seeded cell.
  * If floor==0 -> legacy uniform Dirichlet.

DEL 1b - Strategy-driven spawn (lib/spawn/):
  When a `spawn:` block exists in project (per-FG) or library
  (per-species default), the helper goes through the new path:
    weights = make_weights(spec, (H,W), context, seed)
    initial_b = distribute_with_floor(weights, total_b,
                                      min_per_cell, allowed_mask=None)
  The allocator's floor semantics are unchanged so existing
  guarantees (no cell under floor; total preserved) still hold.
  See section 26 for the strategies.

DEL 2 - Sub-threshold collapse in ecosystem.py:
  * Removed move-mask zeroing on B < min_split.
  * After softmax, sub_thr_mask = (B>0) & (B<min_split) cells get a
    one-hot argmax over the full 11-action distribution. Whole group
    performs one action (including move) - small groups can migrate
    as a unit ("variant 2").

21. CO-EVOLUTION (default training mode)
================================================================
Implemented in trainer.train_step_coevolution and worker
_evaluate_coevo_task. Default ON.

Mechanics:
  * Per ARS iteration: one independent delta per species; CRN
    rollout seed across the +/- halves.
  * 2*n_deltas joint rollouts with ALL DM policies perturbed
    simultaneously. Each rollout returns one fitness per species.
  * ARS update is per-species, using THAT species' own deltas and
    its own r_pos/r_neg vector. No cross-species delta leakage.
  * Predator/prey feedback materialises in the same rollout instead
    of being averaged out against frozen opponents.

Empirical signature (reproducible):
  * Zooplankton "escape" from rest=100% to ~rs/et=40/60 around gen
    13-20 once pelagic_fish predation pressure ramps up.
  * Seals/porpoises rest=100% attractor: structural, robust to every
    intervention tried.
  * Gadoids reach POSITIVE reward once hacks are off.
  * Pelagic_fish converges to mv-dominant (74-98%) "flee" policy.

Kept eval snapshots: results/coev_5gen_100ticks_eval,
results/coev_20gen_100ticks_eval, results/coev_info_profile_40gen,
results/coev_20gen_noHacks, results/coev_info_20gen_postSpawnFix.

22. DESIGN PRINCIPLE: BIOLOGY DRIVES, NOT ACTION-HACKS
================================================================
Rule of thumb when adding a fix:
  1. If it shapes the action distribution (penalty/bonus on action
     fractions, entropy, temperature, eps-greedy, action bias init) ->
     ACTION-HACK. Hide behind a flag and keep OFF in profiles.
  2. If it changes the biological/structural setup (spawn
     distribution, min_split semantics, food web edges in
     fg_library.yaml, impact mortality tables, integral-reward,
     co-evolution rollout structure) -> STRUCTURAL fix. Prefer these.

The "evaluate by action histogram" lens is officially deprecated.
Quality must be evaluated by biomass trajectories over long inference
rollouts, predator-prey cycles, response to impact fields, and
comparison against Baltic-Sea field data.

23. BIOLOGICAL SANITY CHECK FORMULA
================================================================
Per Strategi.pdf + konvergensproblem.txt "Kritisk insikt 4". For each
DM, compute per-tick energy balance at full hunger (h=1) and require
netto_eat > rest_cost.

IMPORTANT (commit 9317a54): `max_intake_rate` (a) is now on the
species_definitions level (one per predator FG), not per interaction.
Assimilation is captured via per-interaction `assimilation_factor`
[0,1]. The energy intake per (pred, prey) is:

  intake_at_h1 = a_pred * energy_gain_pred_prey *
                 assimilation_factor_pred_prey       # best prey
  feed_cost    = feeding_cost    * resting_metabolism
  rest_cost    = resting_cost    * resting_metabolism  # resting_cost=1
  move_cost    = movement_cost   * resting_metabolism

  netto_eat = intake_at_h1 - feed_cost                 # MUST be > 0
  Hard gate:        netto_eat > rest_cost
  Soft gate (move): netto_eat > move_cost

The numbers below are pre-9317a54 baselines and need recomputation
against the new YAML; the inequalities themselves are unchanged.

Post-update (current YAML):
  zooplankton  netto_eat=+101.4  eat-rest=+98.9   eat-move=+101.4
  pelagic_fish netto_eat=+84.8   eat-rest=+76.8   eat-move=+67.6
  gadoids      netto_eat=+564.5  eat-rest=+558.5  eat-move=+553.4
  porpoises    netto_eat=+95.0   eat-rest=+33.0   eat-move=-91.0 *
  seals        netto_eat=+147.5  eat-rest=+122.5  eat-move=+85.0
  seabirds     netto_eat=+493.5  eat-rest=+403.5  eat-move=+133.5
All DMs pass the hard gate. Porpoises fails the soft gate (move > eat).

26. SPAWN STRATEGIES PACKAGE (lib/spawn/)
================================================================
New subsystem (commit 2ef39f4) replacing the legacy uniform spread
for any FG that ships a `spawn:` YAML block.

Public API (lib/spawn/__init__.py):
  StrategySpec(mode, params, refs, seed)
  make_weights(spec, shape, context=None, project_seed=None) -> (H,W)
  distribute_with_floor(weights, total, min_per_cell,
                        allowed_mask=None) -> (H,W) biomass map

StrategySpec fields:
  mode    : "uniform" | "perlin" | "colony" | "env_driven"
  params  : mode-specific scalar dict (see schema below)
  refs    : list of {name, weight, transform} (env_driven only)
  seed    : optional int; when None, falls back to project_seed
            (which, in train.py's per-generation snapshot mode, is the
            adler32 of (gen_spawn_seed, fg_id)).

Strategies (lib/spawn/strategies.py):
  uniform     : equal weight per cell -> equivalent to legacy Dirichlet.
                No params.
  perlin      : fractal-sum Perlin noise on the cell grid.
                Params: Scale (cells/wavelength), Octaves (1-6),
                Persistence (0-1, amplitude falloff), Lacunarity (~2.0,
                frequency mult), Threshold (clamp-to-zero before
                normalisation). Pure numpy vectorised gradient noise.
  colony      : N Gaussian blobs of width sigma_cells around N random
                anchor cells.
                Params: N_colonies (int), Sigma_cells (float),
                Anchor ("free"|"coast"|"open_water"; reserved - anchor
                cells currently chosen uniformly until depth/coast map
                is wired in).
  env_driven  : weighted sum of existing env layers from `refs:`, plus
                optional Perlin overlay.
                Params: Floor (per-cell minimum before normalisation),
                Noise_amp (overlay amplitude), Noise_scale (overlay
                wavelength). Refs are looked up from
                context['env_layers'] by name; missing refs are filtered
                out at config_loader level.

Allocator (lib/spawn/allocator.py):
  distribute_with_floor implements:
    1. Ignore cells with allowed_mask==0.
    2. Pick n_active = clamp(int(total/min_per_cell), 1, n_eligible)
       cells by weight (deterministic argpartition + RNG tiebreak).
    3. Allocate floor=min_per_cell to each.
    4. Distribute the remainder proportionally to weights[active].
    5. Edge cases handled: total<floor (single cell), zero weights
       (uniform over allowed), allowed_mask all-zero (returns zeros),
       min_per_cell=0 (no floor; pure weighted distribution).
  Invariants verified by tests/test_allocator.py:
    - sum(map) == total (within fp eps)
    - all active cells >= min_per_cell
    - shape == requested shape, dtype float32
    - deterministic under same RNG seed

Integration (lib/config/config_loader.py):
  _build_spawn_spec(spawn_cfg, default_seed) parses YAML -> StrategySpec
  or returns None (legacy path).
  _derive_fg_spawn_seed(base, fg_id) -> adler32(f"{base}::{fg_id}")
  guarantees per-FG diversity under a shared generation-wide seed.
  Both setup_full_mareld_mvp and load_project_config call the same
  helper and accept `spawn_seed`.

Tests:
  tests/test_allocator.py            17 tests
  tests/test_spawn_integration.py     5 tests
  tests/test_uniform_bias_init.py    16 tests
  Total: 38, all green.

27. PER-GENERATION SPAWN SNAPSHOT (train.py)
================================================================
Goal: every delta/worker within ONE generation sees the same biomass
maps per FG (same total AND same spatial layout), analogous to the
impact-map snapshot. Across generations the layout still varies.

Mechanism:
  _EnvBuilder grew a `spawn_seed` attribute. _make_env_builder accepts
  spawn_seed and passes it into both load_project_config and
  setup_full_mareld_mvp.
  _install_generation_maps(gen_idx) now draws two INDEPENDENT seeds:
      gen_seed       = randint(1, 2**31-1)   # impact maps
      gen_spawn_seed = randint(1, 2**31-1)   # spawn snapshot
  The new builder is created with both, then the worker pool is
  rebuilt so spawn-workers receive the updated env_builder.

In load_project_config / setup_full_mareld_mvp:
  spawn_rng_base = spawn_seed if spawn_seed is not None else seed
  fg_spawn_seed  = _derive_fg_spawn_seed(spawn_rng_base, fg_id)
  spawn_spec     = _build_spawn_spec(cfg, default_seed=fg_spawn_seed)
  spawn_rng      = np.random.default_rng(fg_spawn_seed) if spawn_seed
                   else rng
  initial_b      = _spawn_biomass_distribution(grid, total_b,
                       min_per_cell, allowed_mask=None, rng=spawn_rng,
                       spawn_spec=spawn_spec,
                       project_seed=fg_spawn_seed)
When spawn_seed is set, total_b for the FG is also sampled from a
deterministic per-FG RNG so the ENTIRE biomass map (sum + shape) is
identical across rollouts in the generation. Without spawn_seed,
legacy per-rollout behaviour is preserved bit-for-bit.

Verified empirically (sanity script):
  (1) same spawn_seed + different rollout seed -> identical biomass maps.
  (2) different spawn_seed -> maps differ.
  (3) no spawn_seed -> legacy behaviour (maps vary per rollout).
  (4) within one spawn_seed: 28 distinct per-FG layouts across the 8
      FGs of mareld2 (no two FGs share an identical pattern).

Inference mode unchanged: total_b is already deterministic from
inference_initial_biomass, so spawn_seed only affects the spatial
layout via _build_spawn_spec there.

28. MULTI-WORLD AVERAGING PER DELTA (ARS variance reduction)
================================================================
Committed in a1484cd. Implements multi-world averaging per delta to
reduce gradient-estimate variance from the stochastic world
distribution (impact realisation + spawn layout). With M=1 the legacy
single-world path is byte-identical to pre-a1484cd behaviour.

Concept:
  Each ARS iteration draws a WorldList of length M:
      WorldList = [(impact_seed_1, spawn_seed_1), ..., (imp_M, sp_M)]
  For every delta i and every sign in {+, -}, the trainer evaluates
  M independent rollouts (one per world) and averages reward + act
  diagnostics:
      r_pos_i = mean_m R(theta + sigma*delta_i, world_m)
      r_neg_i = mean_m R(theta - sigma*delta_i, world_m)
  CRN coupling: +delta and -delta for the SAME (i, m) pair share the
  SAME world AND the SAME pair_seed[i]. This makes Var(r_pos - r_neg)
  drop faster than 1/M (world-wise anti-correlation).
  Top-b ranking happens on the M-averaged r_pos/r_neg vectors, so it
  is much less brittle than under the world noise of M=1.

CLI (Section 5):
  --rollouts_per_delta M       Static M. Profiles force 3; default 1.
  --worlds_refresh POLICY      "iteration" (default; resample each
                               ARS iter) or "generation" (lock for
                               whole gen).
  --rollouts_per_delta_schedule "M0@G0,M1@G1,..."
                               e.g. "1@0,3@10,5@50". Overrides
                               --rollouts_per_delta.

Seed bookkeeping (train.py):
  _world_rng = np.random.default_rng()  (independent of np global RNG)
  _sample_world_list(M) -> [(impact_seed, spawn_seed), ...] drawn
      from _world_rng (so future --seed plumbing is trivial).
  _resolve_M(gen, args) -> int (schedule lookup or static).
  _parse_M_schedule(spec) -> sorted [(gen_threshold, M), ...].
  _refresh_world_list_if_needed(gen, iter) -> bool
      Returns True iff the WorldList actually (re)sampled. Publishes
      to _current_world_list AND trainer.world_list. Refresh rules:
        * iter == 0 within a generation -> always (re)sample.
        * worlds_refresh == "iteration" -> resample every iter.
        * worlds_refresh == "generation" -> no resample for iter>0.

Trainer integration (lib/runners/trainer.py):
  self.world_list = []                    (populated by train.py)
  _resolve_world_builders(): returns [self.env_builder] when M<=1
      (legacy tuple-task path), otherwise [env_builder.with_world(imp,
      sp) for imp, sp in world_list] -> M sibling builders.
  train_step / train_step_coevolution: M-loop wraps the existing
      (delta_i, sign) loop. Tasks are dict-format when M>1 carrying
      'env_builder' override per task; tuple-format when M==1 for
      byte-identical legacy worker path.
  Averaging helpers (null-tolerant): _avg_act_diags, _avg_act_dicts,
      _avg_fit_dicts. Reward and act_diag are averaged over M; fitness
      shape unchanged so the rest of the ARS update is intact.

Worker (lib/runners/parallel_worker.py):
  _evaluate_task / _evaluate_coevo_task accept BOTH tuple and dict
  task formats. Dict format may carry an 'env_builder' override per
  task; falls back to module-global _ENV_BUILDER (legacy) otherwise.

_EnvBuilder.with_world(impact_seed, spawn_seed):
  Returns a fresh sibling builder with re-sampled impact maps and a
  locked spawn_seed; all other state (grid, project, impact recipe)
  is inherited. Picklable for spawn-context workers.

Profile defaults: sanity / info / deep all set rollouts_per_delta=3.
Override via explicit --rollouts_per_delta on the CLI.

Pre-prompt header (train.py): prints a "Rollouts/Delta" line showing
either the static M (with user/default/profile marking) or the
schedule string, plus the worlds_refresh policy.

Cost: total rollouts per iteration = 2 * n_deltas * M. The worker
pool's _auto_workers cap at 2*n_deltas means M>1 utilises more
parallelism than M=1, so wall-time scales sub-linearly with M up to
the CPU core count.

Open follow-ups (not implemented yet):
  * Adaptive M based on gradient-norm CV or top-b rank instability
    (sketched in Section 28 of the original design discussion).
  * A/B variance-reduction test (M=1 vs M=5) on a deterministic seed
    sequence to quantify the empirical win.
  * --seed plumbing into _world_rng for fully reproducible WorldLists.

36. CALIBRATION NOTE - max_intake_rate IS PHYSIOLOGICAL CEILING
================================================================
Per Method.pdf, `max_intake_rate` (a = I_XY) is defined as a
*physiological 6h ceiling* on intake (ton prey per ton predator per
tick) - the maximum the FG can physically ingest at saturating prey
density, NOT a sustained field average.

For zooplankton_preys_on_phytoplankton:
  max_intake_rate = 0.4   (160 % WW/day maximum)
  handling_time   = 2.5   (canonical Type II: 1/h = a)

The Type II ceiling 1/h is set to equal a so that the saturated
response lands AT the physiological maximum, not above it. Previously
h was 0.1 (1/h = 10, i.e. 25x above the ceiling), which effectively
disabled saturation at all biologically relevant prey densities - the
opposite of the intended Fix 2 effect.

Why a=0.4 is defensible at individual level (max interpretation):
  * Copepod gut throughput at saturation ~30-60 min -> theoretical max
    ~150-180 % WW/day (Frost 1972, Mauchline 1998, Kiorboe 2011 as
    max-capacity estimates, NOT sustained grazing).
  * Earlier "cell-aggregation upscaling" rationalisation was a post hoc
    fit; the max-ceiling interpretation removes the need for it.

Note on literature comparisons:
  * Sustained field grazing averages (5-20 % WW/day for copepods) are
    typically 3-5x lower than physiological maxima (GER/gut throughput).
  * Comparing `a` against sustained averages systematically
    underestimates "rimliga" YAML values by the same 3-5x factor.

Documentation locations:
  * fg_library.yaml: comment block above
    zooplankton_preys_on_phytoplankton explaining max-ceiling rationale.
  * lib/environments/ecosystem.py: comment in _build_static_caches
    documenting the canonical Type II convention (h = 1/a).

Implication for other predation relations in fg_library.yaml:
  * Under max-interpretation, most upper-trophic-level a values
    (pelagic_fish, porpoises, seals, seabirds) are defensible as
    physiological ceilings (3-5x sustained-litt.).
  * `gadoids_preys_on_pelagic_fish` was previously 0.115 (46 %/day,
    ~3x even max-literature for adult cod ~15 %/day) - currently set
    to 0.04 in fg_library.yaml. Still worth A/B-testing if upper
    trophic levels are activated.

Implication for future modifications:
  * If physiological max changes (different species, life stage, temp),
    both `a` and `h = 1/a` must be updated together.
  * Adding horizontal movement only affects realised intake, not the
    ceiling itself.

Sanity-test impact:
  * test_zoo_bounded_in_closed_phyto_zoo_system tolerance widened
    from [0.05, 100] to [0.03, 100] because tighter saturation
    suppresses zoo more after 200 ticks than under h=0.1.

After all fixes in Sections 30-36, the closed phyto+zoo system still
has these biological/architectural deficiencies (documented but NOT
fixed):

  1. DM growth has no logistic cap. Non-DM has (1-B/cc); DM is purely
     energy-bounded. Only constraints on B_zoo upward: q_x<0 (energy
     starvation) and natural_mortality (Fix 3).
  2. q_x saturates: s_x = R/(B*ME) is a normalised fill ratio.
     Once R is full, q_x is decoupled from local prey density. LV
     coupling g(P)*Z is only weakly approximated.
  3. Phyto carrying capacity cc is static per cell; no nutrient
     budget / no nutrient recycling from dead zoo. seed_rate fixes
     the "extinction" symptom but not the underlying open-energy
     issue.
  4. zoo.movement_speed = 0 means no spatial refuge can develop;
     zoo spawns on phyto via env_driven refs (Section 30), so any
     zoo cell is immediately adjacent to its food.
  5. No diapause for zoo (real copepods enter dormancy at low food).
  6. Reward horizon in train.py (--n_eval_ticks default 2, info
     profile 150) is much shorter than zoo collapse timescale
     (~700 ticks in baseline rollouts). Training optimises a horizon
     that doesn't see long-term consequences.

Open follow-up ideas (not implemented):
  * Holling Type II GUI exposure in matrix editor.
  * Strip energy_gain entirely + always read prey.energy_content.
  * Diffusion / horizontal advection of NDM biomass for proper
    spatial refuges.
  * Nutrient pool tied to cc with explicit zoo-mortality -> nutrient
    return flux.

40. LIVE PYGAME VISUALISER (--visual)
================================================================
New optional real-time visualiser for both train.py and inference.py.
Off by default; activated with the --visual CLI flag on either entry
point. Pure additive feature: when disabled (or when pygame is not
installed), zero overhead and zero behavioural change.

Files (all uncommitted at time of writing):
  * lib/viz/__init__.py            - re-exports LiveVisualizer.
  * lib/viz/pygame_viz.py          - the visualiser (~636 lines).
  * train.py                       - adds --visual flag + hooks.
  * inference.py                   - adds --visual flag + viz= arg.

Public API (lib/viz/pygame_viz.py):
  class LiveVisualizer:
      def __init__(fg_ids, grid_shape, mode="train"|"inference",
                   reward_window=500, cell_px=6, fps_cap=30,
                   title=None, plot_fg_ids=None): ...
      def update_biomass(fgs, tick, extra=None): ...
      def update_reward(fg_id, value, step): ...
      def pump_events() -> bool   # False => user requested quit
      def close(): ...

  ``plot_fg_ids`` (optional) restricts the right-pane time-series plot
  + legend to a subset of FGs (heatmaps still cover all FGs).
  train.py passes the DM-only subset so phytoplankton/benthic_community
  don't appear in the "reward" plot legend.

Window layout (one window):
  * Top status bar: mode, tick, gen, iter, T, [PAUSED], hm:log,
    plot:log, solo=<fid>, fps.
  * Heatmap grid (cols=min(4,N), rows=ceil(N/cols)): per-FG
    biomass heatmap, 60x60 cells x cell_px=6, viridis LUT (analytic
    approx, no matplotlib dep). Per-panel title is two lines:
      line 1: display name (e.g. "Pelagic fish" - underscores
              stripped, first letter capitalised)
      line 2: "B0=...  B=..." (rollout-start total + current total)
    Below each heatmap: a colorbar gradient strip with "0" (left)
    and a compact vmax label (right; e.g. "12.3k" or "log1p<=...").
    Normalisation is PER-FG (otherwise phyto/benthos dominate).
  * Right pane: rolling line plot.
      train mode: per-DM ARS reward (means[fid] per ARS iter).
      inference mode: per-FG total biomass over ticks.
    Legend rendered with display names (max 18 chars).

Key bindings (handled in pump_events):
  space     pause / resume
  l         toggle log1p scale on heatmaps
  r         toggle log10 scale on plot
  1..9      solo-focus FG by index (toggle off with same key)
  q / esc   close visualiser (training/inference continues)

Defensive design (do not regress):
  * Headless fallback: __new__ sets SDL_VIDEODRIVER=dummy if DISPLAY
    is unset and SDL_VIDEODRIVER isn't already set.
  * If pygame import fails: __new__ returns a _NullViz singleton with
    no-op methods (so --visual on a box without pygame is a silent
    no-op + one stderr line).
  * Every public method is wrapped in try/except + _log_once; never
    propagates to the training/inference loop.
  * pump_events() returns False on QUIT; callers must respect that
    and set viz=None for the remainder of the run (both train.py and
    inference.py do).

Integration in train.py:
  * Visualiser is instantiated in the MAIN PROCESS ONLY (workers
    never import lib.viz). Lives as `viz` local in main().
  * update_reward(fid, means[fid], step=gen*iter_per_gen+i) after
    every ARS iter (round-robin and coevolution paths both wired).
  * _probe_biomass(...) accepts viz= + viz_extra= and renders the
    deterministic probe rollout tick-by-tick (perfect heatmap source
    since it's CRN-locked).
  * If pump_events() returns False mid-loop, viz.close() is called
    once and viz=None for the rest of the run.

Integration in inference.py:
  * --visual creates LiveVisualizer(mode="inference"); run_inference
    accepts viz= and updates both heatmap (env.fgs) and per-FG
    biomass time series (history[fid]) every tick.
  * Closed in a finally block so the window always tears down cleanly.

Performance budget:
  * fps_cap=30; render only when (now - last_frame_ts) >= 1/fps_cap.
  * 8 heatmaps * 60x60 + line plot @ 30 FPS ~ 2-3 ms/frame.
  * Train: rendering is at probe-tick granularity (already CRN-cheap),
    not per ARS-rollout-tick, so no measurable training slowdown.

Dependency:
  * pygame is NOT in requirements.txt by design; install manually
    (`pip install pygame`) on machines where the visualiser is wanted.
  * Without pygame: --visual prints a one-line stderr warning and
    runs as a no-op (verified path).

Git status for this feature:
  * Committed in 4e45e74 + 06ddda0 (June 2026). All four files
    (lib/viz/__init__.py, lib/viz/pygame_viz.py, train.py,
    inference.py) are tracked. No further action needed.

41. OBSERVABILITY MATRIX + HIDE-ACTION (Rest)
================================================================
New subsystem (uncommitted at time of writing) combining a per-DM
input-space restriction (Observability matrix) with a per-DM hide
behaviour wired to the existing Rest action. Both halves are driven
from fgconfig.py and propagate through config_loader, train.py and
ecosystem.py.

41.1 Observability matrix (GUI)
  * New matrix in fgconfig.py "FG Interactions" tab, rendered
    directly below Predation: "Observability (row observes column)".
    Cell semantics: row_fg observes col_fg if checked.
  * Rows are decision_makers only (NDMs have no policy network and
    no input space); columns are all FGs.
  * Self-cells (row == col) are forced True and disabled - a DM
    always sees its own B_own/E_own by construction.
  * Muting greys out both the row and the column of the muted FG,
    same semantics as Predation (muted == FG does not exist).
  * Linked to Predation: setting x preys_on y forces
    x observes y = True AND disables the corresponding observability
    cell (predator must see its prey). Unchecking predation re-
    enables the observability cell (unless self/muted).
  * Persisted to fg_library.yaml interaction_definitions as
    "<observer>_observes_<target>": {observes: bool} entries.

41.2 Runtime: per-DM input space
  * lib/config/config_loader.py parses _observes_ keys into
    fg.params['observes'] = [target_id, ...] (excludes muted FGs).
    If NO _observes_ keys exist for a DM, params['observes'] is None
    and the legacy "see everyone" fallback is used.
  * train.py::get_dynamic_policy_params returns a per-DM in_dim_i
    based on k_i = number of observed OTHER FGs (Section 4 formula).
  * ecosystem.py::_build_static_caches builds:
      - obs_others_idx[i] : (k_i,) j-indices into global_fg_order
                            for DM i (excluding self).
      - per_dm_in_dim[i]  : int, the compact in_dim_i.
      - max_in_dim        : int, max over all DMs (used for padding).
  * ecosystem.py::_build_observation_batch writes a compact per-DM
    layout into the top per_dm_in_dim[i] slots of a
    (N_dm, max_in_dim, H, W) tensor; remaining slots are 0.
  * ecosystem.py::_rebuild_batched_weights pads each policy's W1
    to (max_in_dim, hid) with zero rows. Since the obs tensor is
    also zero in padding slots, padded rows contribute nothing.
  * trainer.py::_get_dm_ids_and_dim reads env.max_in_dim for
    batched-tensor sizing.

41.3 Hide-action (Rest is also a hide action)
  * "Rest" action 4: pi_rest[i, h, w] is the fraction of DM i's
    biomass that rests in cell (h, w) this tick.
  * Hide semantics: that fraction is (a) FULLY PROTECTED from
    predation this tick AND (b) INVISIBLE to other FGs observing
    this DM in their NEXT tick's observation.
  * Self-observation is NOT attenuated: B_own always uses full
    biomass (a DM knows its own total mass, hidden or not).
  * NDMs have no action policy and therefore never hide - their
    biomass is always fully edible and fully visible.

41.4 Implementation (ecosystem.py)
  * prev_hidden_frac : (N_all, H, W) cache, initialised to 0 in
    _build_static_caches. Indexed by global_fg_order. NDM rows
    stay 0 permanently.
  * _build_observation_batch: B_visible_all = B_all *
    (1 - prev_hidden_frac); B_obs = B_visible_all[obs_others_idx[i]]
    is used for the observer's center + 4 neighbour B-channels.
    B_own is taken from full B_all unmodified.
  * _calculate_decisions (end): prev_hidden_frac is rewritten from
    THIS tick's pi_rest so that the NEXT tick's observation sees
    the just-decided hidden mass.
  * _apply_predation: hidden_frac_now is built from THIS tick's
    pi_rest. B_prey_visible = B_prey_all * (1 - hidden_frac_now).
    Holling-II uses B_prey_visible in a_eff; the demand-cap uses
    B_prey_visible. The hidden fraction never enters predator
    accounting this tick.

41.5 Tick-asymmetry (intentional; only causally consistent ordering)
  Within one tick:
    1. _build_observation_batch uses prev_hidden_frac
       (= pi_rest from tick t-1).
    2. _calculate_decisions produces pi_rest_t.
    3. _apply_predation uses pi_rest_t directly (hidden_frac_now).
    4. prev_hidden_frac <- pi_rest_t (for tick t+1).
  Observers therefore see "what was hidden last tick" while
  protection is determined by the active hide-choice this tick.
  The reverse (observers seeing pi_rest_t) would be circular -
  policies decide pi_rest_t based on the observation that would
  need pi_rest_t as input. Using pi_rest_{t-1} for predation would
  delay the protective effect of hide by one tick (incoherent).
  Edge cases:
    * First tick: prev_hidden_frac = 0 -> nothing hidden, correct
      (no decisions taken yet).
    * Stationary pi_rest*: asymmetry vanishes (pi_rest_t = pi_rest_{t-1}).
    * NDMs: hidden_frac stays 0 in both buffers -> no asymmetry.

41.6 Backwards compatibility
  * Legacy projects (no _observes_ keys, no Rest hide expectation):
    k_i = N_all - 1, prev_hidden_frac stays 0 from the start (it is
    populated only after first _calculate_decisions). Numerically
    the FIRST tick is byte-identical to the pre-hide path; from
    tick 2 onward, observers see attenuated B_obs whenever any DM
    chose nonzero pi_rest in the previous tick. Trained policies
    from before this change are dimensionally compatible only if
    no _observes_ keys are present; the semantic shift of B_obs
    (visible vs raw) generally warrants retraining when hide
    behaviour matters.
  * Checkpoint invalidation: any change to the Observability matrix
    shifts k_i and invalidates .pth files for affected DMs.

41.7 Verification
  * python3 -m pytest tests/ -q -> 42 passed.
  * Manual on mareld2.yaml (10x10 grid):
      - explicit observability (zoo sees only phyto):
        zooplankton.in_dim = 11, pelagic_fish.in_dim = 16,
        max_in_dim = 16, env.step() OK.
      - legacy (no _observes_): in_dim = 16 for all DMs (unchanged).
      - forced pi_rest = 1 for zooplankton: predation biomass delta
        on zooplankton = 0.000 (fully protected).
      - forced pi_rest = 0: predation biomass delta = 0.92 (normal).
      - prev_hidden_frac after one tick: phytoplankton (NDM) mean=0,
        zooplankton (DM) mean=0.505, pelagic_fish (DM) mean=0.181.

41.8 Open follow-ups
  * No GUI editor for the asymmetry (it is hard-coded).
  * Predators cannot anticipate prey hide-decisions in a feed-
    forward policy (no memory) - would need RNN / history-stack.
  * Observability changes invalidate checkpoints; no migration
    helper is provided.

41.9 Imperfect hide via visibility_floor
  Per-DM `visibility_floor` (default 0.0 = legacy perfect hide)
  attenuates the hide effect proportionally:
    visible_frac = 1 - pi_rest * (1 - floor)
  Applied symmetrically in both _apply_predation (predators eat
  floor * pi_rest of hidden mass) and _build_observation_batch
  (observers see floor * prev_hidden of last tick's hidden mass).
  Editable per FG via the FG editor. See Section 51 for full
  details, calibration guidance and verification.

42.4 Live pygame viz responsiveness (--visual)
  Problem: window appeared "not responding" during long blocking
  train_step calls because the SDL event queue was only pumped
  between ARS iterations.
  Fix (final state, after several iterations):
    * lib/runners/trainer.py: new attribute pump_callback (no-arg
      callable) + helper _pool_map(func, tasks) that uses
      pool.map_async + async_res.wait(timeout=0.05) loop, calling
      pump_callback every ~50 ms. Both self._pool.map(_evaluate_task,
      ...) and self._pool.map(_evaluate_coevo_task, ...) go through
      _pool_map. Also _pump() helper called after each _pool_map and
      before each train_step return, so events are drained between
      ARS update / z-score / diagnostics steps too.
    * train.py: after trainer creation, sets
      trainer.pump_callback = _viz_pump where _viz_pump calls
      viz.pump_events() IN THE MAIN THREAD. If the user closes the
      window, the callback is cleared so pumping ceases without
      disturbing training.
    * lib/viz/pygame_viz.py::pump_events:
      pg.event.pump() FIRST (drives OS->SDL transfer), then
      event.get() loop, then on user input reset _last_frame_ts and
      call _maybe_render() once, then pg.event.pump() again to
      catch clicks arriving during the redraw. Without user input,
      _maybe_render still runs but FPS-capped (default 30) so the
      worker pool isn't starved.
  Important rule (re-learned): SDL/X11 requires event handling in
  the thread that created the display - background-thread pumping
  is a no-op. Earlier daemon-thread pump attempt has been REMOVED;
  do not reintroduce it.

  Limitation: sequential path (self._pool is None, e.g.
  --workers 1 or n_deltas==1) does NOT pump mid-rollout - only
  between iterations. Acceptable for the standard --visual use
  case (worker pool > 1).

43. START-ENERGI RANDOMISERING (alt. B, centrerad pa u_X)
================================================================
Replaces the legacy "*0.6"-scaling of s_X(0) in
lib/world/functional_group.py::FunctionalGroup.initialize_state.

Old behaviour (pre-fix):
  s_X(0) ~ Uniform[0, 0.6)  i.i.d. per cell -> E[s_X(0)] = 0.3.
  Comment claimed "0.3 ~ typical u_X" but u_X in mareld2.yaml is 0.5
  for all FGs => E[q_X(0)] = -0.2 (negative drift "for free"), wrong
  signum relative to the original break-even intent. Also collapsed
  obs-support to the lower half of [0,1].

New behaviour (alt. B, w = 0.3):
  s_X(0) ~ Uniform[lo, hi]  i.i.d. per cell, where
    lo = max(0, u_X - 0.3),  hi = min(1, u_X + 0.3)
  u_X = self.maintenance_level (per-FG; mareld2 has u_X=0.5 for all).
  E[q_X(0)] = 0 (break-even, since the clipped interval stays
  symmetric around u_X when u_X in [0.3, 0.7]).
  With u_X = 0.5: s_X(0) ~ Uniform[0.2, 0.8] -> wide symmetric
  obs-support, no environmental-drift ARS bias at t=0.

Properties:
  * Per-FG: uses self.maintenance_level, so the formula auto-adapts
    when different FGs have different u_X in the future.
  * CRN-preserved: same `rng` source as before -> pos/neg-delta of an
    ARS iter still see byte-identical start maps.
  * Checkpoint-compatible: only init-distribution changes, not
    obs/policy shapes. Old .pth files keep loading.
  * Stored field is still R_X(c) = B_X(c) * s_X(0) * ME_X.

Why short rollouts still matter (Section 22 reminder):
  Wider start-support in s_X helps the obs-distribution at t=0 but
  does NOT fix the *transition*-support gap: with n_eval_ticks=2 the
  policy never sees consequences of its own actions (move-then-eat,
  flee-then-survive). The dominant knob remains n_eval_ticks. The
  start-energy fix only removes a separate ARS-bias source at t=0.

44. POLICY NETWORK CLI: --policynetwork LAYERS NODES [ACTIVATION]
================================================================
Extended the --policynetwork flag in train.py to accept an optional
3rd argument: the hidden-layer activation function.

CLI:
  --policynetwork LAYERS NODES [ACTIVATION]   default: 2 30 sig
    LAYERS     int, number of hidden Linear layers (>=1).
    NODES      int, nodes per hidden layer (>=1).
    ACTIVATION optional, one of 'sig' (sigmoid, default/legacy),
               'relu', 'tanh'. Lower-case.

Implementation:
  * train.py::main parses argparse with nargs="+" (variable arity).
    metavar is a SINGLE string "LAYERS NODES [ACTIVATION]" (not a
    tuple) - argparse on Python 3.11 raises
    "length of metavar tuple does not match nargs" if a 3-element
    metavar tuple is paired with nargs="+", so the single-string
    form was the only Py3.11-safe option. The help text still
    documents all three positions.
  * Validates len(args.policynetwork) in {2, 3}, parses ints with
    explicit error messages on bad input, and checks ACTIVATION
    against the {sig, relu, tanh} whitelist (case-insensitive).
  * Plumbs the activation through:
      ARSTrainer.__init__(..., activation="sig")
        -> stores self.activation; passes to PolicyNetwork for the
           parent-side policies AND to _worker_init via initargs.
      _worker_init(env_builder, policy_params, uniform_bias_init,
                   hidden_layers, hidden_dim, activation)
        -> stores _ACTIVATION and constructs each worker-side
           PolicyNetwork with it.
      PolicyNetwork.__init__(..., activation="sig")
        -> selects nn.Sigmoid/nn.ReLU/nn.Tanh; raises ValueError on
           unknown values. Stores self.activation for introspection.
  * Pool rebuild in _install_generation_worlds also forwards
    trainer.activation, so post-WorldList-refresh workers stay in
    sync.

Backwards compatibility:
  * 2-arg usage (--policynetwork 2 30) remains byte-identical to
    the previous default (sigmoid, two hidden layers of 30 nodes).
  * Existing checkpoints load unchanged - layer shapes are not
    affected by activation choice; behaviour will differ when the
    activation differs from what the checkpoint was trained with.

Tuning notes (per the discussion preceding this commit):
  * For 2x64 with tanh, recommended starting point is
      --n_deltas 32 --top_deltas 16 --n_eval_ticks 50
      --sigma 0.05 --lr 0.02 --n_iter 500
  * Sigmoid saturates faster than tanh/relu, esp. with wider
    hidden layers; consider tanh as the first non-default choice.

45. ADAPTIVE BIOMASS FORMATTING IN HEATMAP TITLES (live viz)
================================================================
lib/viz/pygame_viz.py::_draw_one_heatmap renders a per-FG title line
"B0=... B=..." above each heatmap (both train.py and inference.py
share LiveVisualizer.update_biomass).

Old: hardcoded ":,.0f" (always 0 decimals, comma thousands separator).
New (in-function helper _fmt_b):
  abs(v) < 10    -> 2 decimals  (e.g. "0.45", "9.87")
  abs(v) < 100   -> 1 decimal   (e.g. "12.3", "99.9")
  otherwise      -> 0 decimals  (e.g. "1 234", "45 678")
Thousands separator: space (was comma, swapped via .replace).

Rationale: at low totals (small subsystems / sub-threshold cells) the
old "0" rounding hid all variation; at large totals the extra digits
were noise. Adaptive formatting preserves resolution in both regimes
without taking more horizontal space (per-FG headers are tight).

Applies to all live-viz callers (train --visual and inference
--visual); no impact on biomass.jsonl / plots.html content.

46. STARVE_RATE - DECOUPLED CATABOLISM IN _apply_growth (DM)
================================================================
New per-FG attribute on DMs: `starve_rate` (catabolism rate at
q_x < 0). Decouples biomass shrinkage from `growth_rate` (anabolism)
because biological mass build-up happens over years, while
starvation death plays out over days to weeks.

Implementation:
  * lib/world/functional_group.py: FunctionalGroup.__init__ now reads
    `starve_rate` (float, default 0.0). starve_rate=0 means legacy
    behaviour (catabolism uses growth_rate, symmetric).
  * lib/environments/ecosystem.py::_apply_growth DM branch:
        r_pos    = growth_rate
        r_starve = starve_rate if starve_rate > 0 else r_pos
        rate     = where(q_x >= 0, r_pos, r_starve)
        growth   = B * rate * q_x
    Negative-growth handling (biomass + energy reserve drain) is
    unchanged.
  * fgconfig/fgconfig.py: new DM editor field
    "Starve Rate (catabolism, fraction/tick)" between
    Max Growth (MG_X) and Natural Mortality, range [0, 1]. Persisted
    to library + project via the existing generic prop_vars loop.

Baseline values (target T_total within literature range; see
sections 23-24 and the per-FG starvation-tolerance table for the
underlying numbers). The ME_X column reflects the muscle-protein-
inclusive revision (lipid + visceral + mobilisable muscle protein),
not just lipid reserve - see calibration discussion below the table.

  FG            ME_X (rev)  growth_rate  starve_rate  T_total lit
  -----------   ----------  -----------  -----------  -----------
  zooplankton       450        0.01         0.20        3-14 d
  pelagic_fish     2400        0.0004       0.025       30-90 d
  gadoids          2500        0.00025      0.012       90-180 d
  porpoises        2800        0.0001       0.50        3-5 d
  seals            5200        0.0001       0.012       30-60 d
  seabirds         3400        0.0001       0.20        5-14 d

ME_X rationale (vs pre-revision values 375/1300/800/2550/4675/2650):
  Original ME_X represented only the lipid/visceral reserve (phase
  I of starvation). Literature 'time to mortality' for fasted fish
  and seals includes a phase II muscle-protein-catabolism reserve
  (~1500-2200 MJ/ton for gadoids, ~800-1300 MJ/ton for pelagic).
  The revised values fold both phases into one effective ME_X so
  T_1 = ME_X / rm hits literature timescales without forcing
  T_2 / starve_rate to absurdly low values. Largest revision is
  gadoids (3.1x); porpoises/seals/seabirds revisions are within
  10-30%. NOTE: changing ME_X shifts s_X = R / (B*ME_X) in the
  observation vector and invalidates pre-revision checkpoints
  (especially for gadoids and pelagic_fish).

Formula recap (with u_X=0.5 across DMs in mareld2.yaml):
  T_1   = ME_X / (rm * 4)              # days, full reserve, rest only
  T_2   = 1 / (starve_rate * u_X) tick = 2 / starve_rate tick
  T_total (days) ~ T_1/2 + (3*T_2)/4   # starting at half reserve
  (4 tick = 1 day; 1460 tick = 1 year)

Verification: T_total per FG matches literature within tolerance
for 5 of 6 DMs when these values are loaded; seals are 2.2x slow
(T_total ~ 130 d vs literature 30-60 d) - accepted by user as a
remaining open calibration item. Raising seals starve_rate from
0.012 to ~0.030 would bring T_total to ~57 d.

Notes:
  * The values above are the calibration baseline saved here so
    they can be reapplied/tuned against literature without redoing
    the derivation. They live in mareld2.yaml (per-project) after
    being entered via the FG editor in the current session.
  * The decoupling implementation (r_pos vs r_starve, FG editor
    field, functional_group.py attribute) is in place in code.
  * starve_rate is independent of natural_mortality (Section 35.3):
    natural_mortality is density-independent (applied every tick),
    while starve_rate only fires when q_x < 0 (energy-driven).
  * Legacy parity: when starve_rate=0 (or absent in YAML), the
    DM-growth branch is byte-identical to the pre-Section-46 code.
  * Checkpoints are NOT invalidated by this change (no policy
    input/output shape impact).

47. PROBE BIOMASS JSONL: SUBNORMAL-FLOAT CLAMP
================================================================
`_probe_biomass` in train.py now floors `bh` / `eh` (and the
`_rnd` baseline mirrors `bhr` / `ehr`) below 1e-12 to exactly
0.0 before writing the JSONL record. Motivation: after a FG
collapses under starvation (Section 46 calibration) the
multiplicative shrink loop can leave subnormal float32 residue
(~1e-44, e.g. porpoises after ~100 ticks at starve_rate=0.50).
Such values are not biologically meaningful (< 1 microgram of
total biomass), but they pollute biomass.jsonl, plots.html and
downstream analysis with values like 6.4e-44.

Implementation: tiny `_floor(v)` helper inside `_probe_biomass`
returning 0.0 when v is non-finite or v < 1e-12; applied to bh,
eh, bhr, ehr at collection time. The existing ratio/log10_ratio
clamp on the same threshold (`max(bh, 1e-12) / b0`) is unchanged
- the new clamp simply makes the raw bh/eh fields consistent
with that floor instead of leaking the underlying subnormal
value.

48. REWARD-SHAPING AGAINST DEAD-ZONE GRADIENT SATURATION
================================================================
Problem: when a FG collapses early in the rollout (e.g. porpoises
T_total ~5 d = 20 tick under Section 46 calibration) before the
policy can act, every ARS delta variant gives the same "already
dead" reward. The log(bh/b0) term is clipped/saturated identically
across all deltas, so r_pos - r_neg = 0 along that axis -> ARS
gradient = 0 -> policy cannot climb out of the dead-zone. This is
gradient saturation / dead-zone reward.

Current state of the fitness function (lib/runners/trainer.py:617
and the parallel mirrors in parallel_worker.py):

    eps_b = max(1e-6 * b0, 1e-9)
    eps_r = max(1e-6 * r0, 1e-9)
    delta_b = log((bh + eps_b) / (b0 + eps_b))
    delta_r = log((rh + eps_r) / (r0 + eps_r))
    fitness = alpha * delta_b + beta * delta_r

With integral_reward=True (default), bh/rh are tick-MEAN over the
whole rollout (not the final value), so Variant C "log(mean(B)/B0)"
is partially already in place. But the multiplicative form +
1e-6*b0 floor still saturates when collapse is early relative to
n_ticks.

Three candidate improvement-hacks have been discussed and are
recorded here as the menu for future use:

48.A SOFTER FLOOR
  Raise the eps_b/eps_r factor from 1e-6 to ~1e-3 so the clipped
  log-term sits at log(1e-3) = -6.9 instead of log(1e-6) = -14.
  Compresses the dead-zone log-range so saturated FGs don't
  dominate the fitness signal numerically.
    delta_b = log((bh + 1e-3*b0) / (b0 + 1e-3*b0))
  Pro:  one-line change; preserves alpha/beta balance approximately.
  Con:  still saturates when bh = 0 across all deltas (no gradient
        recovery, only magnitude compression).
  Status: NOT implemented.

48.B TIME-TO-DEATH BONUS  (IMPLEMENTED, default ON)
  Add a third additive term to fitness:
    fitness += cappa * (t_survive / n_ticks)
  where ``t_survive`` is the first tick at which biomass drops
  below ``survival_threshold * b0`` (defaults to 1 % of start),
  or n_ticks if the FG never collapses. Even when log-terms are
  flat-clipped across all deltas, the survival fraction in
  [0, 1] differentiates "died tick 50" from "died tick 200" -
  guaranteed nonzero ARS gradient out of the dead-zone.

  Implementation:
    * lib/runners/trainer.py::ARSTrainer.__init__ takes
      ``survival_bonus`` (default 0.0 at constructor-level for
      legacy library users) and ``survival_threshold=0.01``.
    * Both _evaluate (round-robin) and _evaluate_coevo (coevo)
      track t_survive per FG in their tick loop and add the
      bonus once at fitness assembly:
          if survival_bonus > 0 and n_ticks > 0:
              fitness += survival_bonus * (t_survive / n_ticks)
    * lib/runners/parallel_worker.py:: _evaluate_task and
      _evaluate_coevo_task mirror the same logic; values plumbed
      via dict-task fields 'survival_bonus' and 'survival_threshold'
      (tuple-format tasks fall back to 0.0 = off).
    * train.py CLI:
        --cappa FLOAT            (default 1.0, ON)
        --survival_threshold F   (default 0.01)
      Passed into ARSTrainer constructor as survival_bonus, and
      propagated to workers via the existing dict-task path. The
      parameter-summary header at training start prints a dedicated
      line: "Cappa (survive): <value> (threshold=...)" with the
      usual (default)/(user) marking.

  Recommended values: cappa in [0.5, 2.0]. Default 1.0 is enabled
  by default in train.py to break ARS gradient saturation in
  dead-zones for the Section 46 calibrated species. Set --cappa
  0.0 for byte-identical legacy parity.

  Pro:  leaves alpha/beta balance untouched; checkpoint-compatible
        (no policy I/O shape change); biologically motivated
        ("how long the population persists" is a meaningful fitness
        component).
  Con:  another hyperparameter; cappa may need tuning per project;
        large cappa risks a "live but starve" attractor.
  Status: IMPLEMENTED, default ON via train.py --cappa 1.0.

48.C MEAN(LOG) INSTEAD OF LOG(MEAN)  (VARIANT 3 PROPER)
  Current integral_reward path computes log(mean(B)/B0); switch to
  the per-tick average of log(B/B0) instead:
      log_b_sum += log((b_cur + eps_b) / (b0 + eps_b))   # per tick
      delta_b   = log_b_sum / n_ticks
  By Jensen's inequality log(mean) >= mean(log), so this is a
  strictly harsher penalty on early collapses (a single tick with
  B ~ 0 contributes a large negative log that drags down the
  mean). More gradient is preserved in the dead-zone because every
  tick is its own log-evaluation, not a sum first.
  Pro:  cleanest/most principled form of Variant 3; no extra
        hyperparameter; eps clip already present.
  Con:  changes reward magnitude/scale -> may need to re-tune
        alpha/beta and re-run from scratch (existing checkpoints
        trained against log(mean) become sub-optimal).
  Status: IMPLEMENTED as part of the new total-energy reward
          (default), see Section 58. The form used is
          mean(log(E_total/E0)) where E_total = B*ec + R.
          The original alpha*log(mean(B)/B0) + beta*log(mean(R)/R0)
          + cappa*survive path is preserved verbatim behind the
          --legacyreward flag.

Recommendation order if dead-zone gradient becomes a measurable
problem in next training runs (Section 46 calibration with
collapsing porpoises / pelagic_fish):
  1) 48.B is now ON by default (--cappa 1.0). Tune cappa in
     [0.5, 2.0] if the survival-term over- or under-dominates.
  2) If 48.B alone is not enough, combine with 48.A (raise eps
     floor to 1e-3) - cheap and additive.
  3) If still flat, switch to 48.C (mean(log)) and accept the
     re-tuning cost.

49. STARVATION CALIBRATION TOOL (tools/starve_calibration.py)
================================================================
Stand-alone diagnostic that validates Section 46 baselines against
literature without running the full ecosystem. Loads effective per-
FG parameters from project YAML + library (ME_X, rm, growth_rate,
starve_rate, maintenance_level, natural_mortality), then runs a
closed-form numerical integration of the rest-only single-cell
starvation model:
  * _apply_movement contribution: R -= B * rm * cost_rest (clamped
    to R >= 0); cost_rest = 1.0.
  * _apply_growth DM-branch: s_x = R/(B*ME_X), q_x = s_x - u_x,
    rate = r_pos when q_x >= 0 else r_starve, growth = B*rate*q_x,
    B += growth, R scaled with B on q_x < 0.
Replicates ecosystem.py's logic exactly (no policy, no predation,
no impacts) - the cleanest measurement of pure starvation dynamics.

Usage:
  python3 tools/starve_calibration.py --ticks 1500
    [--project mareld2.yaml] [--library fgconfig/fg_library.yaml]
Prints a per-FG table: T_1 (reserve depletion, days), T_total
(95 %% biomass loss, days), and a PASS / TOO SLOW / TOO FAST tag
relative to the literature interval embedded for each FG in
Section 46.

Result on current mareld2.yaml (Section 46 baselines as entered):
  * zooplankton, pelagic_fish, gadoids, porpoises, seabirds: PASS
  * seals: T_total ~130 d vs literature 30-60 d => TOO SLOW (2.2x).
    Accepted by user; raise starve_rate 0.012 -> 0.030 if desired
    (would land T_total ~57 d, mid-interval).

Limitations:
  * Validates the starvation channel in isolation. Full ecosystem
    behaviour (predation, movement, impacts, policy decisions)
    is NOT tested here. Use for parameter calibration only.

50. BIOMASS.JSONL FRESH-START TRUNCATION
================================================================
train.py opens results/<run-name>/biomass.jsonl in append-mode in
_probe_biomass. Re-running train.py with the same --run-name
without --resume previously concatenated the new run's records
onto the existing log, producing mixed-n_ticks / gen-restart files
that were silently misleading for downstream analysis.

Fix: directly after probe_jsonl_path is computed (train.py around
line 1130), the file is removed when args.resume is False and the
file exists. Best-effort: any IO error is swallowed with a WARN
print so it can never block training startup.

Semantics summary:
  * Fresh start (no --resume): biomass.jsonl removed, generations
    log from gen=1. Checkpoints (policy_<fg>.pth) are NOT touched.
  * --resume: biomass.jsonl untouched, append continues. The gen
    counter resumes from the checkpoint's saved generation, so
    appended rows have gen = checkpoint_gen+1, ..., +N where N is
    --generations (interpreted as 'this session', not 'total').
  * plots.html is regenerated from the (possibly-truncated) jsonl
    after each checkpoint save (Section 42), so it always reflects
    the current log state.

Known edge: if --resume is set but --n_ticks (or other params)
changed from the previous run, the appended rows will carry the
new n_ticks while older rows have the old value. This is expected
behaviour: --resume means "continue", not "continue with identical
config". Filter on n_ticks downstream if needed.

51. VISIBILITY FLOOR - IMPERFECT HIDE (PER-DM)
================================================================
Per-DM `visibility_floor` attribute breaks the "perfect hide"
attractor identified in late-session diagnostics (Section 41 +
biomass.jsonl analyses): with the original implementation
visible_frac = 1 - pi_rest could collapse to 0 when a DM converged
to pi_rest -> 1, giving total predation immunity + total invisibility
at zero metabolic premium. Pelagic_fish ended up at pi_rest ~= 0.57
in trained runs (43 %% visible, 57 %% hidden) because hide was a
strictly dominant local optimum.

51.1 Semantics (proportional, active for ANY pi_rest > 0)
  With floor=f, the hide-fraction itself is attenuated by (1-f):
    effective_hidden = pi_rest * (1 - f)
    visible_frac     = 1 - effective_hidden
                     = (1 - pi_rest) + pi_rest * f
  Examples (floor=0.2):
    pi_rest=0.0 -> visible 1.00 (no one hides)
    pi_rest=0.1 -> visible 0.92 (10 %% hides, 20 %% of them seen)
    pi_rest=0.5 -> visible 0.60
    pi_rest=0.57 -> visible 0.544 (vs 0.43 legacy) -> +12 pp
                    exposure even at the trained-policy regime
    pi_rest=0.9 -> visible 0.28
    pi_rest=1.0 -> visible 0.20 (floor active at saturation)
  At floor=0.0 the formula reduces to legacy 1 - pi_rest
  (byte-identical parity). At floor=1.0 hide is fully disabled.
  Earlier draft used max(1 - pi_rest, floor); rejected because it
  only activated at pi_rest > 1 - floor, leaving the dominant
  pelagic_fish regime (rs=0.57) untouched.

51.2 Symmetric: floor also applies to observability
  The floor acts on BOTH sides of hide:
    * Predation (_apply_predation): predators see + can eat
      floor * pi_rest of the hidden mass per tick.
    * Observation (_build_observation_batch): observer DMs see
      floor * prev_hidden of the previous tick's hidden mass
      in the B_obs channels of their neighbours.
  Implementation uses a shared cache `_all_visibility_floor`
  (N_all-vector, 0 for NDMs which never hide). The observation
  formula becomes:
    visible_for_obs = 1 - prev_hidden_frac * (1 - floor)
  Mirroring _apply_predation exactly. Predators with floor>0 prey
  also gain a partial leak in their input distribution, so they
  CAN learn to track/stalk hiding prey instead of treating them
  as truly absent.

51.3 Implementation locations
  * lib/world/functional_group.py::FunctionalGroup.__init__:
    new `self.visibility_floor` attribute, read from
    params.get('visibility_floor', 0.0), clamped to [0, 1].
  * lib/environments/ecosystem.py::__init__:
    `self.dm_visibility_floor` (per-DM) and
    `self._all_visibility_floor` (N_all-aligned, 0 for NDMs)
    caches built once and reused.
  * lib/environments/ecosystem.py::_apply_predation: uses
    `prey_vis_floor` (N_all-vector) to compute
    one_minus_floor = 1 - prey_vis_floor; then
    effective_hidden = hidden_frac_now * one_minus_floor[:,None,None]
    visible_frac     = 1 - effective_hidden
  * lib/environments/ecosystem.py::_build_observation_batch:
    one_minus_floor_obs = 1 - self._all_visibility_floor[:,None,None]
    B_visible_all       = B_all * (1 - prev_hidden_frac
                                       * one_minus_floor_obs)
  * fgconfig/fgconfig.py: new DM editor field
    "Visibility Floor (min visible fraction when hiding)"
    between Starve Rate and Natural Mortality, range [0, 1].
    Persisted via the generic prop_vars loop.

51.4 Defaults & calibration guidance
  Default visibility_floor=0.0 => legacy byte-identical parity
  (perfect hide). Not yet written into fg_library.yaml or
  mareld2.yaml; set per FG via the FG editor for retraining.
  Recommended starting values for biological realism:
    zooplankton    0.10 - 0.20  (swarming, fast detection)
    pelagic_fish   0.10 - 0.20  (schooling does not hide perfectly)
    gadoids        0.05 - 0.15
    porpoises      0.05 - 0.10  (acoustic detection limits)
    seals          0.05 - 0.10
    seabirds       0.10 - 0.20  (visible silhouette)
  Floor only addresses the rs->1 attractor; for milder hide regimes
  (rs ~= 0.5) the marginal exposure increase is modest (+10-15 pp),
  which acts as a soft pressure rather than a hard cap.

51.5 Checkpoint compatibility
  Floor does NOT change policy I/O shapes - existing .pth files
  load unchanged. Behaviour does shift quantitatively when floor>0:
  predators see more of hiding prey (observation distribution
  changes), so pre-floor checkpoints are sub-optimal but still
  runnable. No migration tool needed.

51.6 Verification
  * python3 -m pytest tests/ -q -> 42/42 green (incl. previously
    flaky test_predation_visibly_suppresses_phyto - the floor at
    default 0.0 leaves the legacy code path byte-identical).
  * Manual: with floor=0.2 and forced pi_rest=1.0, predation
    biomass delta on the prey is exactly 0.2 * (legacy with
    pi_rest=0) - confirmed numerically.

52. PER-CAUSE BIOMASS-LOSS TRACKING (predation/starvation/impact)
================================================================
Adds per-FG accumulators in EcosystemEnvironment that decompose
biomass loss by cause over a rollout. Used by training stdout, the
JSONL log, the live pygame viz (header rows + dedicated plot tabs)
and the offline HTML viewer.

52.1 Env accumulators (lib/environments/ecosystem.py)
  Three dicts on the env instance, keyed by fg_id, values in tonnes:
    * loss_starvation  - DM-only; populated in _apply_growth's
                         q_x<0 branch using min(total_loss, biomass)
                         so the clamp at zero is respected.
    * loss_predation   - any prey; populated in _apply_predation as
                         the sum over (predator, grid) of actual
                         intake per prey FG per tick.
    * loss_impact      - any FG with mortality_impact > 0; populated
                         in _apply_impact_mortality, clamped to the
                         pre-impact biomass.
  Never reset during a rollout; since env is freshly built per
  probe/ARS-rollout this naturally yields cumulative totals from
  rollout start to "now".

52.2 Probe path (train.py::_probe_biomass)
  Per-tick: derives fractions
    pr = loss_predation / total
    st = loss_starvation / total
    im = loss_impact     / total
  per FG (total = pr+st+im), pushed to the live viz via
  ``update_loss_breakdown(...)`` so the heatmap header refreshes
  per tick. End-of-probe writes a compact stdout line
    [probe gen=N loss] fid: starv X% / pred Y% / imp Z%
  (only FG with total>0 and ratio<1) and persists a full
  ``loss_breakdown[fid] = {predation, starvation, impact, total}``
  block in biomass.jsonl (fractions 0..1; ``total`` in tonnes).
  Random-action baseline (rnd_env) is mirrored as
  ``rnd_loss_breakdown`` under ``record["rnd"]["loss_breakdown"]``
  so offline HTML can render dashed _rnd traces on the loss tabs.

52.3 Inference path (inference.py::run_inference)
  Same computation per tick from env.loss_* accumulators, pushed via
  ``viz.update_loss_breakdown(...)`` and to the dedicated plot tabs
  (Section 53.3). No JSONL persistence in inference mode.

52.4 Semantics caveat
  Fractions are shares of the SUM of the three loss causes; positive
  growth (q_x>0) is NOT a loss and does not enter the denominator.
  Cells where loss > biomass are clamped (min(loss, biomass)) so the
  reported total never exceeds biologically available mass.

53. LIVE VIZ HEADERS + PLOT TABS (mv/rs/et, pr/st/im, diet)

  percent so y-axes match the live viz. ``_rnd`` traces read

  53.6 below).
  Regen policy (Section 42): plots.html is rebuilt only on
  checkpoint writes (per generation) and once more in the
  KeyboardInterrupt handler. Per-iter regen was tried briefly and
  reverted as unnecessary overhead - the perceived "missing HTML"
  on a short interrupted run turned out to be a stale file view.

53.6 KI-handler robustness (train.py)
  The KeyboardInterrupt branch wraps each cleanup step
  (``trainer.close()``, per-species ``_save_checkpoint``,
  ``_regenerate_biomass_html``) in its own ``try/except
  BaseException`` so a failure in one step (or a second Ctrl+C
  during cleanup) cannot bypass HTML regen. An outer
  ``except KeyboardInterrupt`` attempts one final regen on
  double-Ctrl+C. Prints "Interactive HTML regenerated: <path>" as
  acknowledgement so the log shows HTML actually got written.

54. VIZ PER-CELL DEAD-CLAMP (sub min_split_biomass/2)
================================================================
The global early-exit in inference.py (DEAD_EPS = 0.5 * min positive
``min_split_biomass`` across all FGs, fallback 1e-9) triggers only
when ALL FG totals are below DEAD_EPS. Individual FGs (e.g.
porpoises) can leave float32 subnormal residue (~1e-45) per cell
that keeps the per-FG max-normalised heatmap fluctuating after the
FG has effectively collapsed.

Fix in lib/viz/pygame_viz.py::update_biomass (visual-only):
  Before caching/rendering, each FG's biomass array is passed
  through
    arr = np.where(arr <= dead_eps_fg, 0, arr)
  with ``dead_eps_fg = 0.5 * min_split_biomass`` per FG (fallback
  1e-20 for continuous mode where min_split_biomass=0). This is
  PER CELL, not per FG total - the original intent was that any cell
  below half an indivisible weight is "ghost mass" and should not
  influence the visualisation.

Properties:
  * ``np.where`` returns a new array; the underlying env biomass
    field is NOT mutated. Env stepping, biomass.jsonl logging and
    accumulators remain unaffected.
  * The global ``DEAD_EPS`` early-exit in inference.py is unchanged
    and still applies when EVERY FG has collapsed.
  * Conversion check: min_split_biomass = 0.5 kg in fg_library
    units -> 0.5 / 1000 = 0.0005 ton internally; dead_eps_fg =
    0.5 * 0.0005 = 0.00025 ton = 0.25 kg = 250 g (NOT 0.25 g, as a
    stale comment once read). Far below realistic biomass, many
    orders of magnitude above float32 subnormals (~1e-38).

55. IN-RAM PROBE REPLAY + PLAYBACK BAR
================================================================
Adds an in-memory "film" of the last probe (train) or inference
rollout that the user can re-watch / step through while training
continues in the background. New playback bar sits under the
heatmap grid; plot tabs are intentionally NOT rewound (per user
choice - tabs keep showing global series).

55.1 Frame capture (lib/viz/pygame_viz.py)
  * New state on LiveVisualizer: ``_pending_rollout`` (list of
    frame snapshots, grows during recording), ``_current_rollout``
    (atomically swapped in when recording ends), ``_playback_mode``
    in {"live", "paused", "playing"}, ``_playback_idx``,
    ``_playback_fps`` (adjustable 1..60), ``_playback_blink_until``
    (yellow flash ~3 s when a new film becomes available).
  * Public API: ``begin_rollout_recording()`` /
    ``end_rollout_recording()`` (no-ops on ``_NullViz``). Each
    ``update_biomass`` call during recording deep-copies the
    current per-FG state (biomass, totals, b0, loss_breakdown,
    diet, action_fracs, tick) into ``_pending_rollout``. Cap
    5000 frames per rollout with even decimation if exceeded.
  * ``_render_full`` swaps the snapshot's state into the heatmap
    drawing path when ``_playback_mode != "live"`` so headers +
    pixels match the replayed frame. Plot tabs read their normal
    series (not rewound).

55.2 Playback bar (under heatmaps)
  * Drawn by ``_draw_playback_bar``; ``_win_h += 32`` to fit it.
  * Buttons (all modes): ``<<`` step back, ``|>`` play/pause,
    ``>>`` step forward, ``-`` / ``+`` speed (delta 1 below 10 fps,
    delta 5 at and above), frame indicator ``frame = i / N`` (or
    ``live`` / ``recording...``).
  * Train-mode only buttons: ``live`` / ``replay`` (jump back to
    live view), ``pause train`` / ``resume train`` (toggles
    ``self._paused`` which gates the existing pump_events block in
    train.py between ARS iterations). In inference mode there is
    no live view nor training loop to pause, so both buttons are
    omitted from the bar.
  * Buttons grey out while ``_recording`` is true or no film
    exists; ``toggle_train_pause`` is always active so the user
    can freeze training before the first probe completes.
  * Yellow blink (2 Hz, 3 s) on the whole bar when
    ``end_rollout_recording`` runs and a fresh film replaces the
    previous one. Blink suppresses on first user click.

55.3 Auto-advance (three places must stay in sync)
  Playback auto-advance (advance ``_playback_idx`` by 1 every
  ``1 / _playback_fps`` seconds, switch to ``paused`` on last
  frame) MUST run in three loops:
    * ``pump_events`` (normal train tick).
    * The blocking ``while self._paused`` loop inside
      ``pump_events`` (so playback still works after the user
      clicked ``pause train``).
    * ``wait_for_close`` (inference's post-rollout idle loop -
      without it, pressing play after inference finished did
      nothing).
  Pressing play while ``_playback_idx >= n - 1`` (clip already
  played out) resets ``_playback_idx = 0`` first; otherwise the
  next auto-advance tick would immediately flip back to paused.

55.4 train.py / inference.py wiring
  * ``train.py::_probe_biomass``: calls
    ``viz.begin_rollout_recording()`` before the tick=0 snapshot
    and ``viz.end_rollout_recording()`` after the end-of-probe
    ``update_biomass``. Each per-tick ``update_biomass`` therefore
    becomes a frame in ``_pending_rollout``.
  * ``inference.py::run_inference``: same wrap around the tick
    loop. End-of-recording also runs on early break paths
    (KeyboardInterrupt, ``ecosystem_dead``) so partial films are
    still playable in ``wait_for_close``.

55.5 Design notes
  * Plot tabs are NOT rewound when scrubbing a frame - they show
    global training/inference curves, not per-rollout series.
  * Frame snapshots are dicts of numpy arrays (deep-copied);
    typical Mareld rollout sits comfortably under 100 MB.
  * No multithreading: rendering / replay still runs synchronously
    between ARS iterations via the existing pump_events route.

55.6 Offline-HTML follow-up (tools/biomass_html.py)
  Independent of the replay feature but landed in the same arc:

  ``b0`` and add ``predation`` / ``starvation`` / ``impacts``.

58. TOTAL-ENERGY REWARD (E_total = B*ec + R) + --legacyreward
================================================================
New default reward formulation that replaces the alpha/beta/cappa
linear combination with a single physically-grounded scalar:

    E_total(t) = B(t) * energy_content + R(t)        [MJ]
    fitness    = mean_t [ log( (E_total(t) + eps) / (E0 + eps) ) ]

i.e. the per-tick log-ratio averaged over the rollout (Section
48.C form, "mean(log)"), applied to total chemical energy bound
in the FG. Biomass is now implicit in the reward via the B*ec
structural-energy term - no separate alpha is needed, and the
B*ec floor (as long as the population is alive) naturally
counteracts the eps-saturation that made mean(log(R/R0)) on its
own untenable. See discussion in the chat arc preceding this
section for full motivation; key points:

  * Degenerate "few fat individuals" attractors are eliminated:
    B -> 0 collapses E_total even if E = R/B stays high, because
    B*ec dominates the sum.
  * Variant B-asymmetry in _apply_growth (R scaled with B on
    starvation) no longer "hides" collapse - E_total reacts on
    both terms simultaneously.
  * Predation conserves system-level E_total modulo metabolism +
    assimilation losses: a true co-evolutionary zero-sum signal.

58.1 CLI: --legacyreward
  New flag in train.py:
    --legacyreward (alias --legacy_reward)   default: False
  When False (default): the new total-energy reward is used.
  When True:            the old linear-combination reward
                        (alpha*delta_b + beta*delta_r +
                        cappa*survive) runs byte-identical to
                        pre-Section-58 behaviour.
  The training banner now prints either:
    "Reward: total-energy mean(log(E_total/E0))"
  or, in legacy mode, the existing Alpha/Beta/Cappa lines.

58.2 Implementation
  * lib/runners/trainer.py: ARSTrainer.__init__ takes
    ``legacy_reward`` (default False at constructor-level; train.py
    sets it from args.legacy_reward). Both _evaluate and
    _evaluate_coevo compute BOTH the legacy delta_b/delta_r and
    the new log_e_sum/E0 paths in the rollout loop, then select
    the final fitness via the flag. When ``legacy_reward=True``
    the worker task path stays in tuple-format for byte-identical
    legacy parity; when False, M=1 also uses dict-format tasks
    so the workers can read ``legacy_reward`` per task.
  * lib/runners/parallel_worker.py: both _evaluate_task and
    _evaluate_coevo_task read ``legacy_reward`` (default True in
    the tuple-task code path for back-compat) and per FG:
        ec      = float(env.fgs[fid].params.get('energy_content', 0.0))
        e0      = b0 * ec + r0
        eps_e   = max(1e-6 * e0, 1e-9)
        # accumulated each tick:
        log_e_sum += log((b_cur*ec + r_cur + eps_e) / (e0 + eps_e))
        # final:
        fitness = log_e_sum / n_ticks         # mean(log)
    The legacy branch is unchanged.
  * train.py: --legacyreward parsed, propagated to ARSTrainer,
    and shown in the parameter-summary banner.

58.3 Silent-no-op warning (CLI guardrail)
  Without this guardrail, users specifying --alpha/--beta/--cappa/
  --survival_bonus without also setting --legacyreward would get
  a tyst no-op (values reach the trainer but the new reward path
  ignores them). train.py now prints, directly after argparse:
    [WARNING] Ignoring --alpha=... --beta=...: the new
    total-energy reward (default) does not use alpha/beta/cappa/
    survival_bonus. Add --legacyreward to enable the linear-
    combination reward.
  Detection uses _parser_defaults (compares against argparse
  defaults), so passing the same value as the default is not
  flagged.

58.4 Removal of legacy energy_gain fallback (Section 31 update)
  ``energy_gain`` is no longer readable via any path. Concretely:
    * lib/environments/ecosystem.py _build_static_caches: predation
      energy gain now reads ``prey_fg.params['energy_content']``
      directly (was: interaction's energy_gain with fallback).
    * fgconfig/fgconfig.py hard-gate validator: the energy_gain
      override branch removed; always uses
      species_definitions[prey].energy_content.
    * fgconfig/fgconfig.py FG-save: the auto-sync block that
      previously wrote ``energy_gain`` into all matching
      interactions is replaced by a one-shot CLEANUP pass that
      STRIPS any legacy ``energy_gain:`` field from
      interaction_definitions on every FG save. Old YAMLs
      converge to the new schema automatically.
    * fgconfig/fg_library.yaml: all 8 stale ``energy_gain:`` lines
      removed (all matched preys energy_content, so removal is
      behaviour-neutral).
  Net effect: bytets ``energy_content`` is the single source of
  truth for predation energy transfer; the assimilation_factor

59. MIGRATION MODE (--migration on|off)
================================================================
New opt-in mode that reinterprets out-of-grid movement as biological
migration instead of masking it away. Default OFF preserves the
legacy behaviour byte-for-byte (edge directions of move_mask are
zeroed so pi_move cannot assign mass over the boundary).

59.1 Semantics
  When --migration on:
    * Edge-zeroing of move_mask in ecosystem._build_static_caches
      is skipped. pi_move can therefore route biomass northward
      from row 0, eastward from the last column, etc.
    * In _apply_movement, the slice-assigns that would otherwise
      drop the out-of-grid b_out/r_out slices instead aggregate
      them per DM into emigration totals b_emig, r_emig (one
      scalar per DM, summed over the 4 edge slices).
    * The same totals are immediately redistributed as IMMIGRATION
      across the grid's edge cells, proportionally to
      self._edge_imm_weights (a (H, W) array normalised to sum=1
      over the edge ring; non-edge cells have weight 0).
    * Total biomass per DM is conserved modulo the metabolic cost
      already subtracted in r_after_move_meta (i.e. modulo the
      normal cost-of-moving). Energy reserve R follows biomass.

59.2 Immigration weights
  Built once in _build_static_caches as self._edge_imm_weights:
    edge_mask         = 1 on the outermost ring, 0 elsewhere
    edge_weights      = edge_mask * clip(accessibility, 0, None)
                        (or edge_mask if no accessibility map)
    _edge_imm_weights = edge_weights / sum(edge_weights)
  Fallback (all-zero accessibility on the edge): uniform over
  edge cells via edge_mask / count(edge). The weights are FG-
  independent (one global edge layout); per-FG modulation (e.g.
  seasonal migration directions) is an open follow-up.

59.3 Implementation locations
  * lib/environments/ecosystem.py:
      - __init__ takes new ``migration`` kwarg (default False).
      - _build_static_caches: conditional edge-zeroing of
        move_mask; always builds self._edge_imm_weights.
      - _apply_movement: when self.migration, accumulates
        b_emig / r_emig from the 4 edge slices and adds
        b_emig[:, None, None] * imm_w[None, :, :] to b_total_in
        (same for R).
  * train.py:
      - New module global APPLY_MIGRATION (default False), set
        from args.migration in main().
      - --migration on|off CLI flag (default off).
      - _EnvBuilder, _ProbeEnvBuilder and _make_env_builder all
        accept and propagate ``migration`` (same pattern as
        APPLY_NATURAL_MORTALITY), baked into the instance so
        spawn-context workers don't lose it on re-import.
      - _EnvBuilder.with_world copies the flag to siblings.
  * inference.py:
      - --migration on|off CLI flag (default off).
      - build_env takes ``migration`` and forwards to
        EcosystemEnvironment. All three build_env call sites
        (initial, rerun, rnd_baseline) pass it through.
      - Banner prints ``Migration: on|off`` alongside Mortality.

59.4 Conservation properties
  Per DM, per tick: sum(B_after_move) == sum(B_before_move)
  modulo metabolic cost (the per-action ``cost * rm`` deduction
  applied BEFORE the slice-assigns). The migration loop neither
  amplifies nor leaks mass: emigration is computed as the EXACT
  sum of the slice-assigns that would otherwise be dropped, and
  immigration weights sum to 1 over the edge cells.

59.5 Verification
  * python3 -m py_compile lib/environments/ecosystem.py train.py
    inference.py -> OK.
  * python3 -m pytest tests/ -q -> 42/42 green.
  * Empirical sanity (pi_move[N]=1 forced for all DMs):
      - migration=False: DMs that move toward an edge collapse to
        B ~ 0 over a few ticks (legacy mass-loss to the void).
      - migration=True: total biomass per DM stays essentially
        constant; the only residual decay is metabolic starvation
        (intended), not edge leakage.

59.6 Notes & open follow-ups
  * Immigration is symmetric across all DMs but independent per
    FG: each FG's emigration immigrates back as the SAME FG (no
    cross-FG flows). Per-FG migration patterns (e.g. seasonal
    directionality, FG-specific edge preferences) are out of
    scope for this issue.
  * Migration is independent of the spawn pipeline (Section 26):
    spawn sets up t=0 layouts, migration only acts on the per-
    tick movement flux at the grid edge.
  * No GUI toggle yet; --migration is CLI-only. Per-FG enabling
    (e.g. only zooplankton/pelagic_fish migrate, top-predators
    don't) is an obvious extension.
  * Checkpoint compatibility: no policy I/O shape change.
    Policies trained with migration=off may behave sub-optimally
    when run with migration=on (and vice versa) because the
    effective move_mask differs at the edge, but they load and
    execute without modification.

60. --visual MEMORY LEAK FIXES (SDL/pygame native allocations)
================================================================
Long-running --visual training sessions OOM'd the main process
(~16 GB RSS) on a 32 GB box after many hours. Diagnosis arc went
through psutil per-generation RSS logging, tracemalloc, objgraph,
and finally memray --native --trace-python-allocators. Key data:
with --visual main grew ~0.17 GB/gen linearly; without --visual
main was stable at 0.62 GB over 24 generations. objgraph showed
"(no growth)" - i.e. zero Python-object accumulation. Leak was
100% in the C/SDL layer triggered only by the visualiser.

60.1 Confirmed leak sources (all fixed in lib/viz/pygame_viz.py)

  Fix A - font.render().get_width() antipattern
    Two call sites allocated a full SDL Surface via TTF_Render_
    Internal -> AllocateAlignedPixels -> SDL_malloc just to
    measure text width, then discarded the Surface. SDL never
    returned the pixel buffers.
      * _draw_playback_bar: ~218 MB leaked over the memray run.
        Replaced with self._font.size(s)[0] (returns (w,h) as
        ints, no Surface allocation).
      * _draw_status_bar: ~228 MB leaked. Three render(...).
        get_width() calls replaced with self._font.size(...)[0].

  Fix B - pygame.init() pulls in SDL audio + PulseAudio thread
    memray summary showed ~201 MB across 565 thread creations
    rooted in pa_mainloop_iterate / pa_mainloop_run /
    internal_thread_func / start_thread (pthread_create). The
    PulseAudio mainloop runs in its own thread and leaks per
    iteration on some setups. We never use audio.
    Fix: replaced pygame.init() with pygame.display.init() +
    pygame.font.init() in LiveVisualizer.__init__. SDL audio
    subsystem is now never initialised, so the PulseAudio thread
    never spawns.

  Fix C - SDL2 GL-texture path on display.flip()
    memray summary showed ~230 MB via pg_flip ->
    SDL_UpdateWindowSurface_REAL -> SDL_UpdateWindowTexture ->
    GL_UpdateTexture (278 flips, but only 108 GL_UpdateTexture
    calls returned memory on this driver).
    Fix: pygame.display.set_mode((W, H), pygame.SWSURFACE) forces
    a pure software surface, bypassing the GL-backed window path
    entirely. SDL_UpdateRects is used instead.
    Trade-off: CPU does the per-frame pixel copy on flip. For
    Mareld's small window + low render frequency this is
    invisible; large/high-FPS UIs would feel it. See discussion
    in chat arc for the full downside analysis.

  Fix D - breakdown-dict clear in begin_rollout_recording
    Defensive: self._loss_breakdown / _diet_breakdown /
    _action_fracs were filled via dict.update each tick but
    never cleared between probes. If FG ids vary across
    generations (spawn variants), keys could accumulate. The
    helpers now self.<dict>.clear() at the start of each
    recording. Empirically not the dominant leak source (the
    dicts stayed at 3-4k entries with --visual instrumentation
    on), but cheap insurance.

60.2 Investigation tools (all temporary, all removed)

  Lived in train.py inside a single [MEM_INSTRUMENTATION] block
  tagged in code so it could be grepped out in one sweep:
    * _log_mem(tag)        psutil RSS per generation (main +
                           sum-of-children) -> memlog.txt.
    * _log_viz_sizes       deep sys.getsizeof + recursion over
                           viz._pending_rollout, _current_rollout,
                           _series (deques), _loss_breakdown,
                           _diet_breakdown, _action_fracs etc.
    * _log_objgrowth       objgraph.show_growth(limit=20) since
                           previous baseline -> showed "(no
                           growth)" confirming non-Python leak.
    * _log_tracemalloc     wrapper around tracemalloc.start(n)
                           with snapshot diff; abandoned (~10x
                           slowdown at depth=10, missed C
                           allocations anyway).
  All deleted in the final cleanup (search MEM_INSTRUMENTATION
  in train.py -> ALL CLEAR).

  External tool that actually solved it: memray with
    /home/simon/micromamba/envs/eco-evo-mixed/bin/python3 -m

      --follow-fork --aggregate -o profile_agg.bin train.py

  Followed by either flamegraph --leaks -o leaks.html or

61. PER-CELL EXTINCTION THRESHOLD (0.5 * min_split_biomass)
================================================================
Follow-up on Section 20's sub-threshold semantics. Adds a per-FG,
per-cell extinction threshold that zeros out biomass in cells
where 0 < B < factor * min_split_biomass at the end of each tick.
Motivation: below min_split_biomass action distributions already
collapse to one-hot argmax (Section 20), but the ecosystem engine
did not previously kill off tiny residuals. Predation / starvation
/ impact shrink biomass multiplicatively, so cells can drift into
float32 subnormals (~1e-38 to 1e-45). Those values are not
biologically meaningful (fractions of one indivisible individual)
but they pollute observations, loss-breakdown percentages and
reward. Interpretation: "less than half an indivisible individual
in this cell" -> extinct locally.

61.1 Semantics
  * Applied per FG, per cell, after all shrink steps
    (predation/starvation/impact/movement/accessibility).
  * Threshold: extinction_threshold_factor * min_split_biomass
    (both stored in tonnes internally; min_split_biomass in the
    GUI/YAML is in kg per Section 8).
  * Default factor: 0.5, matching DEAD_EPS in inference.py
    (Section 17, rollout-termination) - "half the minimum
    indivisible unit" is the shared "dead" semantics between
    per-cell (engine) and global (inference loop) mechanisms.
  * Factor = 0.0 disables the mechanism (legacy behaviour).
  * No effect when min_split_biomass == 0 (continuous FGs, e.g.
    plankton) - the check short-circuits at msb <= 0.

61.2 Implementation
  * lib/world/functional_group.py: FunctionalGroup.__init__ reads
    ``extinction_threshold_factor`` from params (default 0.5,
    clamped to >= 0.0). Stored on the FG instance.
  * lib/environments/ecosystem.py:
      - New per-FG accumulator ``self._extinction_events`` (int
        count of cells zeroed during the rollout), initialised
        alongside loss_predation / loss_starvation / loss_impact.
      - New method ``_apply_extinction_threshold()``:
            for fid, fg in self.fgs.items():
                msb    = fg.min_split_biomass
                factor = fg.extinction_threshold_factor
                if msb <= 0 or factor <= 0:
                    continue
                thr  = factor * msb
                dead = (fg.biomass > 0) & (fg.biomass < thr)
                lost = fg.biomass[dead].sum()
                loss_starvation[fid] += lost
                _extinction_events[fid] += dead.sum()
                fg.biomass[dead]        = 0
                fg.energy_reserve[dead] = 0
        Called last in step(), AFTER _apply_accessibility_
        biomass_mask, so nasta ticks observation aldrig ser
        subnormaler.
      - Lost biomass is booked in ``loss_starvation`` (closest
        semantic match: cell has too little mass to be a viable
        unit). No new pr/st/im category is exposed yet - the
        loss-breakdown (Section 52) simply attributes it to st.
  * fgconfig/fgconfig.py: new field in the DM editor's
    ``main_props`` list:
      ("Extinction Threshold (x indiv. weight, 0=off)",
       "extinction_threshold_factor", "entry", 0.0, 5.0)
    ``on_fg_select`` defaults the Entry to "0.5" when the key is
    absent in the project YAML so pre-existing projects show the
    correct default value in the GUI without persisting it.

61.3 Scope
  * Only DMs are exposed in the GUI (main_props is DM-only), in
    line with ``min_split_biomass`` being a DM concept. NDMs
    typically have msb=0 so the mechanism would be a no-op there
    anyway.
  * Per-FG override via YAML/GUI. Set to 0.0 per FG to return to
    legacy behaviour for that species.

61.4 Relationship to DEAD_EPS (inference.py)
  Section 17's DEAD_EPS check is a *rollout-termination* rule:
  when TOTAL biomass across ALL FGs falls below
  0.5 * min(min_split_biomass_positive), the inference loop
  breaks so the visualiser doesn't render meaningless subnormal
  noise. It is:
    * global (sum across all FGs), not per-cell / per-FG,
    * present ONLY in inference.py (never in training - Section 21
      argues an early ``break`` would skew ARS reward variance
      between seeds),
    * complementary to the per-cell threshold, not redundant.
  The DEAD_EPS comment in inference.py was updated to point at
  ``_apply_extinction_threshold`` so future readers don't confuse
  the two.

  Training has NO equivalent global early-exit and should not gain
  one - the per-cell threshold suffices to keep observations clean.

61.5 Design notes / caveats
  * Non-differentiable cliff at the threshold. ARS is gradient-
    free so it doesn't hurt directly, but the reward landscape
    gains a small discontinuity. Mitigated by the low default
    (0.5 * msb) and the fact that starvation reaches that level
    only after significant shrinkage has already occurred.
  * Can hide real bugs: if a FG always collapses to subnormals,
    the mechanism masks the symptom. Track via
    ``_extinction_events`` (diagnostic counter) if you suspect
    excessive triggering.
  * Reproduction / respawn: once a cell is zeroed it stays zero
    unless something else populates it (movement inflow, spawn on
    reset). For FGs with msb=50 kg that's biologically desirable
    (5 kg tumlare can't reproduce locally anyway).
  * Baseline fairness: the mechanism lives in the engine and
    therefore applies uniformly to trainer rollouts, probe
    rollouts, inference rollouts and the random-action rnd
    baseline - no risk of asymmetric treatment.

61.8 Edge-immigration top-k concentration (migration=True)
  When ``self.migration=True`` emigration off the grid edges is
  redistributed over ``self._edge_imm_weights`` (O(H+W) cells).
  A naive split can dilute each recipient cell far below thr,
  which the per-cell extinction check then zeros -> the entire
  emigration silently vanishes as "starvation". Unlike ordinary
  N/E/S/W movement, the recipient distribution is engine-owned
  (not policy-owned), so it is legitimate for the engine to
  concentrate it. In ``_apply_movement`` the emigration branch
  now performs a greedy top-k concentration per DM:
    * Sort edge cells by descending weight (shared across DMs).
    * For each DM with msb>0 and factor>0, pick the largest k
      such that the smallest resulting per-cell inflow
      (``emig * w_sorted[k-1] / cum_w[k-1]``) is >= thr.
    * If no such k exists (emigration itself < thr), leave the
      original imm_w distribution intact; the extinction check
      then books the loss uniformly.
    * If all edge cells qualify, no change (fast path).
    * Otherwise renormalise the kept weights so mass is exactly
      preserved within the chosen subset.
  Rationale: recipients are variable in count and motor-owned,
  the residual ``b_stay`` (policy-driven fragmentation) is left
  untouched. Cost is O(K log K) per tick with K = |edge cells|
  (typically 2*(H+W)); negligible vs the rest of step().
  Does NOT alter mass conservation: either everything moves to
  the concentrated subset, or the original spread stands and
  the extinction check accounts for the losses.

61.6 Verification
  * FunctionalGroup constructor: extinction_threshold_factor=0.5
    default when key absent; explicit 0.0 disables.
  * EcosystemEnvironment._apply_extinction_threshold present as
    method and wired into step().
  * fgconfig.py parses (with utf-8-sig; BOM was pre-existing).
  * No tests added yet for the mechanism itself; the low default

62. RND BASELINE SEMANTICS (--rnd_baseline [all|solo|none])
================================================================
The random-action baseline is a probe-side comparison that overlays
"_rnd"-suffixed traces on the live viz + biomass.jsonl + plots.html
so the trained policy can be visually compared against a policy-free
control in the SAME deterministic probe world.

62.1 CLI semantics
  --rnd_baseline is nargs='?' with choices [all|solo|none] and
  const='all', default='none'. This preserves back-compat: bare
  --rnd_baseline (no arg) is treated as 'all'. Modes:

  * 'all'  (single-env, ALL DMs random)
      One extra probe env is built alongside the main probe env.
      Every DM-FG in that env is bound to RandomPolicy so all DMs
      act uniformly at random SIMULTANEOUSLY. NDMs (phytoplankton,
      benthic_community) have no policy and behave identically to
      the main env; they still get _rnd traces because their
      biomass differs via trophic cascade from the random
      predators/grazers. Interpretation: "ecosystem collapse under
      no learning at all" - worst-case baseline.

  * 'solo' (leave-one-out, N envs)
      For each DM-FG k, a SEPARATE probe env is built where ONLY
      k acts randomly; the other DMs use trainer.policies (with
      frozen obs-norm from the main env, so their behaviour
      matches the main probe env exactly modulo k's actions).
      Only DM-FGs get _rnd traces, each read from its own env_k.
      Interpretation: "how does FG k stand against the trained
      rest?" - fair per-agent ablation. Cost: N extra probe envs
      per iteration where N = len(env.dm_ids).

  * 'none' (default)
      No random baseline. No _rnd traces, no extra envs, no cost.

62.2 Implementation (train.py::_probe_biomass)
  * Signature: _probe_biomass(..., rnd_builder=None, rnd_mode='all').
    Callers pass rnd_builder=probe_builder and rnd_mode=<CLI arg>
    when the mode != 'none'; otherwise rnd_builder=None disables
    the whole block.
  * Helper _make_rnd_env(random_fids) builds one rnd env whose
    dm_ids in random_fids get RandomPolicy and the rest get
    trainer.policies[fid]. Obs-norm: identity for random FGs,
    trainer.obs_stats for trained FGs (so their input distribution
    matches the main probe env).
  * unique_rnd_envs = [envs to .step() per tick]; rnd_env_for_fid
    = {fid: env-to-read-from}. In 'all' mode both contain one
    entry; in 'solo' mode unique_rnd_envs has N envs and
    rnd_env_for_fid maps each DM-FG to its dedicated env_k.
  * Per-tick: step every env in unique_rnd_envs once, then read
    B/R/E_total from each fid's designated env for the _rnd
    trace accumulators (b_sum, e_sum, log_e_sum, t_survive).
  * All downstream pushes (heatmap-header mv/rs/et and pr/st/im,
    plot tabs move/rest/eat/predation/starvation/impacts,
    reward-tab rnd-reward, biomass/energy tabs) filter by fid so
    only the FG that is actually random in each env contributes.
    Prevents duplicating trained-policy fids across N solo envs.

62.3 Viz setup (train.py main)
  * _extra (extra legend ids passed to LiveVisualizer) is chosen
    from rnd_mode:
      'all'  -> [fid + '_rnd' for fid in env.fgs]  (all FGs)
      'solo' -> [fid + '_rnd' for fid in dm_ids]   (DMs only)
      'none' -> None
  * Legend entries for '_rnd' are UNCHECKED at startup (Section 40
    conventions) so the plot is not cluttered by default. User
    toggles them on via legend clicks.

62.4 Reward-tab formula (identical to trainer._evaluate)
  The _rnd reward pushed to the 'reward' tab follows exactly the
  same formula as the trained policy's ARS reward, driven by
  trainer.legacy_reward / trainer.integral_reward /
  trainer.alpha / trainer.beta / trainer.survival_bonus /
  trainer.survival_threshold. See Section 58 for the two branches.
  Same formula-parity holds for both 'all' and 'solo' modes.

62.5 NDM in 'solo' mode
  NDMs (phytoplankton, benthic_community) are NOT included in
  _extra when rnd_mode='solo' because they have no policy to
  randomise; in every env_k the NDM behaves identically to the
  main probe env's NDM (modulo cascade from the one random DM_k),
  making per-env NDM traces ambiguous/misleading. In 'all' mode
  NDMs DO get _rnd traces because "all DMs random" gives one
  well-defined cascade signal per NDM.

62.6 Verification
  * python3 -m py_compile train.py -> OK.
  * Resume run with --rnd_baseline solo (16x16, 1 gen, 1 iter,
    n_eval_ticks=5, n_deltas=2): no probe WARN; N=3 rnd envs
    stepped per tick as expected; plots.html regenerated with
    dashed _rnd traces per DM only.
  * Same command with bare --rnd_baseline (=all) and with the
    flag absent (=none): no tracebacks; legend content matches
    _extra selection above.

62.7 Notes / caveats
  * 'solo' cost scales as N*rollout_ticks per probe. For 3 DMs
    this is ~3x the probe cost of 'all'. Probe is not on the
    ARS training critical path (runs once per iter for
    diagnostics), so wall-time impact is modest.
  * In 'solo' mode, the interpretation of an FG's _rnd trace is
    "this FG random, the rest trained" - NOT "this FG random,
    everything else also random". Documented in the CLI help
    string in train.py.
  * Legacy: pre-Section-62 behaviour ('all' mode via bare
    --rnd_baseline store_true) is preserved as the const default
    when the flag is passed without an argument.

63.1 Type II vs Type III auto-selection (ecosystem.py)
  Per predator, the functional response is chosen structurally
  from the menu size (no YAML flag):
    * n_prey_per_pred == 1 -> Holling Type II (specialist,
      hyperbolic saturation, standard filter feeder).
    * n_prey_per_pred >= 2 -> Holling Type III (generalist,
      sigmoid; models prey switching / search image /
      low-density refuge -> stabilising at low prey).
  Implementation in _build_static_caches:
      n_prey_per_pred = eat_static.sum(axis=1)             # (N_dm,)
      self._type3_pred_mask = (
          (n_prey_per_pred > 1).astype(self.dtype)
          .reshape(self.N_dm, 1, 1, 1)
      )
      self._has_holling3 = bool(np.any(self._type3_pred_mask > 0.0))
  In _apply_predation both a_eff variants are built and mixed via
  the mask:
      a_eff_ii  = a / (1 + a*h*B)          # f_II  = a*B  / (1+ahB)
      a_eff_iii = a*B / (1 + a*h*B*B)      # f_III = a*B^2/(1+ahB^2)
      a_eff = m3*a_eff_iii + (1 - m3)*a_eff_ii
  Same 1/h asymptote for both types; only the low-density slope
  differs. B here is B_prey_visible (Section 41 hide semantics).
  No configuration change needed - a, h and max_intake_rate keep
  their meaning. In mareld2.yaml this puts pelagic_fish + gadoids
  on Type III (multiple prey); zooplankton stays on Type II.
  Verified via tests/test_phyto_zoo_sanity.py (4/4 green).

63.2 handling_time matrix + Auto-fill buttons in FG Editor

  New auto-fill helper panel below the matrix:

    * One "Auto All Rows" button -> runs the row helper for

  Implementation (fgconfig.py):

  Rationale for keeping h as a first-class editable field even

63.3 Phyto calibration recommendation (literature-based)
  For temperate coastal / Baltic pelagial phytoplankton on a
  1 km^2 cell with 6 h tick (mareld2.yaml defaults):
    growth_rate         = 0.0375   (net mu ~ 0.15/day, HELCOM avg)
    seasonal_amplitude  = 0.7      (5-6x seasonal mu ratio)
    seasonal_period     = 1460     (365 days x 4 tick/day)
  Motivation:
    * growth_rate 0.125/tick (~0.5/day) is Eppley physiological
      max, not sustained net - drives phyto to CC and masks
      grazing signal. 0.0375 lands in the middle of HELCOM /
      Behrenfeld-Falkowski net growth for temperate zones.
    * seasonal_period 500 has no biological analogue; the year
      cycle is the dominant timescale (spring/autumn blooms).
    * seasonal_amplitude 0.7 gives winter mu ~ 0.011/tick
      (~0.045/day) and summer peak ~ 0.064/tick (~0.26/day) -
      matches Baltic 5-6x seasonal biomass variation (after CC
      damping). Avoid A>=1.0 (negative growth in winter breaks
      logistic recovery).
  Companion recommendation: keep handling_time = 4.0 for
  zooplankton_preys_on_phytoplankton (matches Auto-fill from
  max_intake_rate = 0.25), consistent with Section 36.

63.4 Cell-area caveat
  a, h and max_intake_rate in the code are tick-normalised rates
  in ton_per_cell units (not ton/m^2). The 1 km^2 cell mapping
  works for the current a=0.25/h=4/CC=27 numbers by coincidence
  of calibration - halving cell area breaks the density-based
  dynamics because a stays constant while B scales with area.
  If cell area is ever changed, a and CC must be re-derived from
  ton/m^2 literature values, not just re-used. Future refactor:
  store a in ton/(g_prey/m^2 * day) and multiply by cell_area *
  tick_days in ecosystem.py:847. Not implemented.

63.5 Diagnosed failure mode: zoo starves at phyto=CC
  NOTE (superseded in part by Section 64): the "pelagic starves
  when zoo is abundant" symptom that motivated much of this
  section turned out to be caused primarily by a sign-inverted
  Holling II/III attack-rate formula in ``_apply_predation``
  (see Section 64). The policy-parameter mismatch discussion
  below is still valid for legacy checkpoints, but the DOMINANT
  cause of the observed starvation-at-abundance was the missing
  ``B_prey`` factor in ``a_eff``, not policy staleness alone.
  Retraining after the Section 64 fix is required for meaningful
  inference on any pre-fix checkpoint.

  Symptom: with the Section 63.3 calibration applied and a
  legacy checkpoint (pzpg248ed) trained under the OLD parameters
  (growth_rate=0.125, h=0, no season), zoo dies of starvation
  during inference even after phyto stabilises at CC across the
  whole grid.
  Root cause chain (verified against code, not hypothetical):
    1. Legacy policy learnt pi_eat ~= 1 everywhere - trivial
       optimum under Holling I + always-saturated phyto.
    2. hunger clamp in functional_group.py::get_hunger:
         hunger = max(0, 1 - s_x/0.8)   with s_x = R/(B*ME)
       Above s_x=0.8, hunger=0 => intake=0 regardless of pi_eat
       (D = B_pred * pi_eat * a_eff * hunger).
    3. In _apply_movement, feeding_cost * resting_metabolism is
       paid proportionally to pi_eat_sum, NOT proportionally to
       actual intake. So a "trying to eat" cell with hunger=0
       still pays feed_cost = 1.2 * rm per tick.
    4. Reserve overshoots 80%, hunger drops, intake stops, but
       pi_eat is still ~1 (frozen policy). Net drain 4.2 MJ/tick
       vs 0 intake pulls s_x below 0.8; hunger reappears at
       epsilon level, insufficient to compensate.
    5. When s_x < u_x = 0.5, q_x < 0 and starve_rate = 0.2 in
       _apply_growth begins shrinking biomass (Section 46).
       Combined with natural_mortality = 0.0025/tick (when
       --mortality on), zoo collapses over ~hundreds of ticks
       despite phyto being at 100% availability.
  Not a bug in the ecology code - the mechanics are correct.
  The issue is policy-parameter mismatch: pzpg248ed was trained
  in a world where hunger=0 was rare (fast phyto recovery, so
  pi_eat=1 didn't waste feeding_cost in empty cells).
  Recommended remedies (in order):
    (A) Retrain the policy under the new phyto parameters +
        Holling II - the only genuine fix. A fresh policy learns
        pi_rest -> 1 when s_x is near 1.0.
    (B) Diagnostic instrumentation: log medians of s_x, hunger,
        pi_eat, and count "eating with hunger=0" cells for the
        first N ticks (snippet in Section 51/63 discussion).
    (C) Consider making feeding_cost scale with actual intake
        rather than pi_eat (ecosystem.py::_apply_movement rad
        ~968-971). This would make suboptimal policies robust
        against paying-for-nothing, but changes the training
        landscape - requires retraining anyway. Discussed, NOT
        implemented.
    (D) Sanity-run without season first (seasonal_amplitude=0)
        and check spawn.min_frac_of_max for phyto to guarantee
        food at t=0 during transition.

64. HOLLING II/III BUGFIX - MISSING B_prey FACTOR IN a_eff
================================================================
Structural bug in ``lib/environments/ecosystem.py::_apply_predation``
diagnosed and fixed this session. The Holling II/III attack-rate
expressions were sign-inverted in the prey-density dependence:
``a_eff`` FELL toward 0 at high prey density instead of saturating
toward the physiological ceiling ``1/h``. Symptom that led to
diagnosis: pelagic_fish starving to an asymptote near 25 % of
starting energy during inference on run ``pzpg248hmovf0``, even
with gadoids=0 (no top-down pressure), phyto/zoo at max spawn
biomass, and a trained policy at pi_eat ~= 1.

64.1 What the code did (wrong)

At the Holling II/III branch of _apply_predation the attack-rate
per predator-unit was built as:

    a_eff_ii  = a / (1 + a*h*Bp)              # WRONG: missing *Bp
    a_eff_iii = (a*Bp) / (1 + a*h*Bp2)        # WRONG: missing one *Bp

with predator demand:

    D = B_pred * pi_eat * a_eff * hunger

The comment directly above these lines stated the INTENDED form:
``f(B) = a*B / (1 + a*h*B)`` (Type II) and ``f(B) = a*B^2 / (1 +
a*h*B^2)`` (Type III), i.e. classical Holling. Code and comment
were inconsistent - the code had lost the B_prey numerator factor.

64.2 Consequences

With the buggy Type II expression ``a_eff = a/(1 + a*h*B)``:
  * B_prey -> 0    ==> a_eff -> a        (full "trying to eat"
                                          signal in empty cells)
  * B_prey -> inf  ==> a_eff -> 0        (ZERO try when abundant -
                                          exact opposite of saturation)

For pelagic_fish (a=0.04, h=25, energy_content_zoo=4500,
assim=0.8, feeding_cost=1.5, resting_metabolism=8) at a typical
zoo colony B_prey ~= 100 ton/cell:
  * a_eff_old = 0.04 / (1 + 0.04*25*100) = 0.04/101 ~ 3.96e-4
  * Energy in per ton_pred/tick
      ~ pi_eat * a_eff * assim * ec = 1 * 3.96e-4 * 3600 ~ 1.4 MJ
  * Feeding cost per ton_pred/tick
      = pi_eat * feeding_cost * rm = 1 * 1.5 * 8 = 12 MJ
  * Net: -10.6 MJ/tick - exact match for the rapid energy decay
    the user observed.

The 25 % asymptote arises when s_x drops below 0.8 (hunger
clamp in get_hunger) and hunger starts rising linearly, partially
compensating the vanishing a_eff. The two effects balance at a
low, stable energy fraction (~25 % in the observed run).

zooplankton -> phytoplankton escaped the symptom in visible
training because a*h = 0.25*4 = 1 gave milder scaling in
practice, but the same bug was present there too.

64.3 Fix

In ``lib/environments/ecosystem.py::_apply_predation`` (post-fix):

    a_eff_ii  = (a * Bp)  / (1.0 + a * h * Bp)     # canonical Type II
    a_eff_iii = (a * Bp2) / (1.0 + a * h * Bp2)    # canonical Type III

Numerical verification for a=0.04, h=25 (asymptote 1/h = a = 0.04):

    B_prey   a_eff_II (fix)   a_eff_III (fix)
    0.01     0.00040          0.00000004
    1.0      0.02000          0.02000
    10.0     0.03636          0.03960
    100.0    0.03960          0.04000

a_eff now saturates toward 1/h = a at high B (canonical Section
36 calibration) and drops toward 0 at low B (as intended). At
B_prey ~= 100 ton/cell pelagic_fish now gets ~143 MJ/ton_pred/tick
in intake vs 12 MJ in feeding_cost - a comfortable positive
energy budget.

Type I branch (``else: a_eff = a``) is unchanged. Demand
formula ``D = B_pred * pi_eat * a_eff * hunger`` is now
consistent: Type I attempts linear ``a*B_pred`` (hard-capped by
``scale`` against ``B_prey_visible`` later), Type II/III attempts
saturated ``f(B_prey)*B_pred``.

    "BUGGFIX: tidigare implementering saknade *Bp i taljaren

    till avsedd mattnad. Symptom: pelagisk fisk svalt vid

65. ACTION-COST SCALING BY POLICY FRACTION (pi_eat_sum / pi_move_sum)
================================================================
Semantic fix in lib/environments/ecosystem.py::_apply_movement so
that eat/move metabolic costs are paid only by the sub-population
that actually performs the action. Motivated by user clarification
of move semantics: movement_cost is a per-action transport cost,
not a continuous cruise overhead; pi_move / pi_eat represent the
fractions of the cell population that choose those actions.

65.1 Pre-fix behaviour (asymmetric, inconsistent with rest branch)

  * rest branch: m_rest = B * pi_rest * rm * cost_rest * cost_factor
                 -> cost correctly scaled with pi_rest.
  * eat  branch: r_eat_tot = pi_eat_sum * max(0, R - B * scale_eat) + TG
                 -> full B-cost dragged off R FIRST, then pi_eat_sum
                    applied to what remained.
  * move branch: r_after_move_meta = max(0, R - B * scale_move); then
                 r_move_choices = pi_move * r_after_move_meta[..., None, :, :]
                 -> same "full B-cost first, scale later" pattern.
                 dm_v (movement_speed) irrelevant for cost.

Effect: total metabolic cost per ton biomass was independent of
whether the policy actually chose eat/move, breaking the semantic
"only actors pay". Especially harmful for pi_rest > 0 strategies
in prey species: pelagic_fish / zooplankton paid full activity
cost even when the policy tried to have them rest.

65.2 Post-fix (this session)

  * eat:  m_eat        = B * pi_eat_sum  * rm * cost_eat  * cost_factor
          r_eat_tot    = max(0, R * pi_eat_sum  - m_eat)   + TG
          b_eat_tot    = B * pi_eat_sum
  * move: pi_move_sum  = pi_move.sum(axis=1)
          m_move       = B * pi_move_sum * rm * cost_move * cost_factor
          r_move_pool  = max(0, R * pi_move_sum - m_move)
          safe_sum     = where(pi_move_sum > 0, pi_move_sum, 1.0)
          move_dir_frac= pi_move / safe_sum[:, None, :, :]
          r_move_choices = move_dir_frac * r_move_pool[:, None, :, :]
          b_move_choices = pi_move * B[:, None, :, :]         # unchanged
  * rest branch: unchanged.
  * flux (dm_v) : unchanged - deliberately left OUT of cost scaling
                  per user instruction ("lamna dm_v utanfor tills
                  vidare"). movement_speed still governs only the
                  fraction that leaves the cell (b_out / r_out).

Divide-by-zero guard: safe_sum replaces pi_move_sum with 1.0 in
cells where no direction was chosen; since r_move_pool is also
zero there, the resulting r_move_choices contribution is zero.

65.3 Semantic table (post-fix)

  Action  | Metabolic cost scaled by
  --------|-------------------------
  rest    | pi_rest
  eat     | pi_eat_sum
  move    | pi_move_sum (sum over N/E/S/W)

feeding_cost / movement_cost multipliers are now biologically
interpretable as PER-ACTION SMR overhead rather than fixed
per-tick activity fees. This restores consistency between the
YAML parameter semantics (Section 23-24) and the actual runtime.

65.4 A/B verification (ab_test_action_cost.py, this session)

Script monkey-patches _apply_movement with the exact pre-fix
variant (Section 65.1) and runs mareld2.yaml untrained for
1500 ticks x 3 seeds, comparing per-FG biomass trajectories.

Result: PRE and POST are bit-identical for every FG:
  zooplankton   mean/b0=0.634  end/b0=0.486  min~4255  turns=0
  pelagic_fish  mean/b0=0.212  end/b0=0.001  min~2.4   turns=0  (extinct)
  gadoids       mean/b0=0.365  end/b0=0.001  min~0.9   turns=0
  phytoplankton mean/b0=1.180  end/b0=1.194  min~18700 turns=0

Interpretation (expected, not a script bug):
  * Untrained/uniform policies concentrate probability mass on a
    single action per state (softmax over initialised logits is
    typically near-argmax). At pi_eat_sum ~= 1 (or ~= 0) the
    pre-fix formula PRE = pi_eat_sum * max(0, R - B*scale) and
    post-fix formula POST = max(0, R*pi_eat_sum - B*pi_eat_sum*scale)
    collapse to the same value. Same argument for move.
  * The fix's effect is a strict TRAINING ARTEFACT: it only
    matters when ARS learns to blend actions (in particular
    pi_rest > 0 for prey under predation pressure). Uniform
    rollouts show no delta.

Consequences:
  * Fix is safe (no regression, no NaN, no negative reserves,
    bit-identical baseline). Checkpoint-compatible.
  * Verification of biological effect REQUIRES a real training
    run (e.g. 30-50 gens x 10 iter x 1000 tick) to compare
    per-FG mean/b0 with vs without the fix.
  * The A/B script is retained as ab_test_action_cost.py for
    future regression testing if _apply_movement is touched.
