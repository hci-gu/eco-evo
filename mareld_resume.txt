3. "THE TICK" PIPELINE (lib/environments/ecosystem.py)
================================================================
Random FG order each tick. Per tick - order per Method.pdf Section steg 1-6
(impact mortality applied BEFORE predation):
  _calculate_decisions -> _apply_impact_mortality -> _apply_predation
  -> _apply_movement -> _apply_growth

  1. _calculate_decisions  (batched over all DMs)
     - obs_batch (N_dm, max_in_dim, H, W). Each DM i writes a compact
       per-DM layout in the top per_dm_in_dim[i] slots; remaining slots
       are 0-padded. See Section 4 and Section 41 for the per-DM
       formula driven by the Observability matrix.
     - B_others channels for OTHER DMs use VISIBLE biomass
       B_visible = B_all * (1 - prev_hidden_frac), where
       prev_hidden_frac is the previous tick's pi_rest. ``Rest`` is a
       hide action (Section 41); the rested fraction is invisible to
       other FGs in the next tick. B_own (the observer itself) uses
       FULL biomass; an FG always sees its own full mass.
     - Raw-obs stats accumulated for trainer merge.
     - If env.obs_mean/obs_var set: obs clipped/normalised before forward.
     - All DM policies in one batched torch.bmm forward (weights padded
       to max_in_dim with zero columns for per-DM compact layout).
     - Output: pi_move (N_dm,4,H,W), pi_rest (N_dm,H,W), pi_eat
       (N_dm,N_all,H,W). Masked before renormalisation.
     - After pi_rest is finalised, prev_hidden_frac is rewritten to the
       current tick's pi_rest for use in the NEXT tick's observation.
  2. _apply_impact_mortality
     - Per (FG, impact): linear interpolation in impact_table; clip to
       endpoints. B reduced, R scaled so E=R/B preserved on survivors.
  3. _apply_predation  (fully vectorized)
     - hidden_frac_now = current tick's pi_rest (per DM-prey, NDMs=0).
       B_prey_visible = B_prey_all * (1 - hidden_frac_now). The hidden
       (rested) fraction is fully protected this tick.
     - D = B_pred*pi_eat*max_intake*hunger; with Holling-II,
       a_eff = a / (1 + a*h*B_prey_visible). Demand-cap uses
       B_prey_visible. Predator energy gain buffered to
       temp_energy_gains. See Section 41 for tick-asymmetry rationale.
  Sub-threshold cells: NO move-mask zeroing. Instead env replaces those
  cells' distribution with a one-hot argmax over the full 11-action set.
  See section 20.
  4. _apply_movement  (slice-assign over N_dm)
     - Per-action fraction pays metabolic cost * resting_metabolism.
     - Slice-assign (no np.roll). Energy follows biomass. temp_energy_gains
       added to stayers AFTER metabolism.
  5. _apply_growth
     - NDM: logistic dB = MG*B*(1 - B/CC); B clipped to [0, CC].
     - DM: s=R/(B*ME), u=maintenance_level (default 0.3), q=s-u,
           growth=B*MG*q.
         * Positive: only B updated (Variant B) -> energy dilution.
         * Negative: B and R scaled identically (E preserved).

4. POLICY NETWORK DIMENSIONS
================================================================
Per cell the policy sees the von Neumann neighbourhood (the cell
itself + its 4 cardinal neighbours N, E, S, W) per Method.pdf. Out-
of-bounds neighbours are zero-padded. Neighbour order is fixed
N, E, S, W (matches AccessN/E/S/W in Method.pdf). Built by
lib/environments/ecosystem.py:_build_observation_batch and the
matching dimension calc is train.py:get_dynamic_policy_params.

Input layout (one observation vector per cell, per DM i):

  Let k_i = number of OTHER FGs that DM i observes per the Observability
  matrix (Section 41). Self is always implicitly observed via B_own and
  is NOT counted in k_i. Legacy projects without any _observes_ keys in
  interaction_definitions fall back to k_i = N_all - 1 (sees everyone),
  which is byte-identical to the pre-observability formula.

  center : [B_own, E_own, B_obs (k_i), impacts (n_obs)]
  N      : [B_own,        B_obs (k_i), impacts (n_obs)]
  E      : same shape as N
  S      : same shape as N
  W      : same shape as N

  center_dim_i = 1 + 1 + k_i + n_obs   # B_own + E_own + obs + impacts
  nbr_dim_i    = 1     + k_i + n_obs   # B_own + obs + impacts (no E)
  in_dim_i     = center_dim_i + 4 * nbr_dim_i

  max_in_dim   = max over DMs of in_dim_i (used for batched bmm padding)

Channel semantics:
  B_own      Own-FG biomass at that cell (tonnes; raw, before obs
             normalisation). Tells the policy "how many of me are
             here / next door".
  E_own      Own-FG energy fill ratio s_X = R / (B * ME) at the
             center cell, in [0, 1]. Only on the center (neighbour
             energy is intentionally NOT exposed - Method.pdf).
             Drives hunger: low s_X -> hungrier -> stronger Eat.
  B_obs      Biomass of every OTHER FG the DM is configured to
             observe (k_i channels), in stable global order
             (env.obs_others_idx[i] indexes into global_fg_order).
             Includes both DMs and NDMs that this DM observes;
             excludes self (covered by B_own) and any FG that this
             DM does NOT observe per the Observability matrix.
             Same k_i channels appear on center and on each of the
             4 neighbours so the policy can compare local vs
             one-step-away density. VALUES are visible biomass
             B_visible = B * (1 - prev_hidden_frac) (Section 41):
             the fraction of the observed FG that rested last tick
             is invisible.
  impacts    Values of every impact_id flagged "Observable by
             policy" in the project (one channel per id, e.g.
             windfarm_noise). Raw map values; muted/unobservable
             impacts are excluded from the input but still applied
             in _apply_impact_mortality.

Output layout (one logit vector per cell, per DM):

  out_dim = 5 + N_all_fgs
          = [Move_N, Move_E, Move_S, Move_W, Rest, Eat_<fg1>, ...
             Eat_<fgN>]

  The 4 Move slots correspond to the same N, E, S, W order as the
  neighbour observation channels. The Eat block has one slot per
  FG in global_fg_order; slots outside the predator's menu are
  permanently masked to 0 by the environment (so the network can
  emit them but they never fire). Final action probabilities come
  from softmax(logits / T), with T annealed from --temp_start to
  --temp_end over --temp_anneal_gens generations.

Backwards-compat note: an earlier resume revision listed
  in_dim = 2 + (N_fgs - 1) + n_observable_impacts
which is exactly center_dim above with k_i=N_all-1. That formula
was incomplete - it ignored the 4 * nbr_dim contribution from the
von Neumann neighbours. Current (and correct) formula is the
per-DM one above; setting k_i = N_all - 1 reproduces the legacy
"see everyone" behaviour bit-for-bit.

Batched bmm with per-DM in_dim_i: env._rebuild_batched_weights pads
each DM's W1 to (max_in_dim, hid) with zero rows for the unused
top slots. Since the observation tensor also pads those slots with
0, the padded rows contribute nothing to any DM's forward. Hidden
width and out_dim remain uniform across DMs (out_dim = 5 + N_all).

Checkpoint invalidation: changing the Observability matrix (k_i
shifts), toggling "Observable by policy" on impacts (changing
n_obs), adding/removing an FG (changing N_all), or changing the
grid in a way that affects per-cell layout changes in_dim_i and
invalidates existing .pth checkpoints (full retraining required).
The 4x neighbour expansion means even one new observable impact
bumps in_dim_i by 5, not 1.

7b. REFERENCE GRID & BIOMASS SCALING (project_metadata)
================================================================
Each project stores a reference grid (Rx, Ry) in
project_metadata.reference_grid_width / reference_grid_height. All
biomass values entered in fgconfig (FG editor's initial_biomass_min/
max and the Inference tab's inference_initial_biomass) are defined
for that reference grid.

At runtime in load_project_config:

    biomass_scale = (H_act * W_act) / (Rx * Ry)

* mode='train':  min_b *= scale; max_b *= scale; min_b clamped to
                 >= 1.0 ton; max_b clamped to >= min_b.
* mode='inference': total_b = max(inference_initial_biomass * scale, 1.0).

Legacy projects without reference_grid_* keys fall back to 60x60.
Sub-3 values are rounded up to 3 by _as_pos_int.

  species_definitions:
    <fg_id>:
      display_name, is_decision_maker
      initial_biomass                      (library-default fallback only)
      growth_rate, max_carrying_capacity   (NDM only)
      seed_rate                            (NDM only; fraction of cc/tick)
      max_energy_reserve, energy_content,
      resting_metabolism, movement_speed,
      maintenance_level                    (u_X, default 0.3)
      feeding_cost, movement_cost          (resting_cost is hardcoded to
                                            1.0; stripped from YAML)
      max_intake_rate                      (DM only; a, physiological
                                            ceiling, ton prey / ton pred /
                                            tick; moved from interaction in
                                            commit 9317a54)
      natural_mortality                    (DM only; fraction/tick;
                                            density-independent, see
                                            --mortality flag, default OFF)
      min_split_biomass                    (DM only; kg, 0 = continuous)
      menu: [prey_id, ...]                 (DM only)
      spawn:                               # OPTIONAL library default
        mode: uniform|perlin|colony|env_driven
        # mode-specific params (Scale, Octaves, N_colonies, Sigma_cells,
        # Floor, Noise_amp, Noise_scale, ...)
        # seed: <int>                      # optional pin
  interaction_definitions:
    "<observer>_observes_<target>": {observes: bool}
        # Per-(observer, target) bit driving the policy input space.
        # Section 41. Self-pairs are implicitly True and not
        # editable in the GUI. Muted observer or target is excluded
        # entirely (muting == FG does not exist) - same semantics
        # as predation. If NO _observes_ keys exist for an observer
        # at all, legacy fallback applies (sees every other FG).
    "<predator>_preys_on_<prey>":  {preys_on, energy_gain,
                                    assimilation_factor (0..1, default 1.0),
                                    handling_time (h; 0 = pure Type I)}
        # max_intake_rate has been MOVED to species_definitions.<predator>
        # (commit 9317a54). Effective intake per (predator,prey) is:
        #   intake = a_pred * pi_eat * hunger * B_pred,
        # with energy gain = energy_gain * assimilation_factor.
        # When handling_time>0 anywhere, Type II saturation kicks in
        # globally (see Section 35.2).
    "<fg>_impacted_by_<impact>":   {impact_affects: bool,
                                    impact_table: [{value, biomass_factor,
                                                    energy_factor}, ...]}
        # impact_table: sorted by value; linear interpolation, clip to
        # endpoints. Old `impact_sensitivity` scalar removed everywhere.
  impact_definitions:  bottom_trawling, pelagic_trawling, hunting, logging,
                       chemicals, windfarm_noise, ship_traffic, turbidity.

9. ARS TRAINER (lib/runners/trainer.py)
================================================================
ARSTrainer(env_builder, policy_params,
           sigma=0.1, lr=0.02, n_deltas=8,
           n_workers=1, alpha=1.0, beta=1.0,
           obs_normalize=True, top_deltas=None,
           entropy_coef=0.0, argmax_penalty=0.0,
           integral_reward=True, uniform_bias_init=False)

  policies: persistent {fg_id: PolicyNetwork} across generations.
  obs_stats: persistent {fg_id: {mean (D,), var (D,), count}} across
             generations; frozen during a rollout, updated via Welford
             parallel merge after each train_step.
  top_deltas: None -> all n_deltas used.
  _pool: spawn-context Pool when n_workers > 1.

train_step(fg_to_train, n_eval_ticks=2):
  1. Sample n_deltas directions.
  2. Draw pair_seeds[i] (one per delta pair).
  3. Build (N_dm, D) obs_mean/obs_var from obs_stats.
  4. Evaluate +sigma*delta and -sigma*delta with SAME pair_seed (CRN).
  5. Parallel tasks: (fg, weights_snapshot, n_eval_ticks, alpha, beta,
     seed, obs_pack). Return (fitness, samples).
  6. Fitness: delta_b = log((bh+eps)/(b0+eps)), delta_r similar,
              fitness = alpha*delta_b + beta*delta_r.
  7. Welford parallel merge of obs_stats.
  8. ARS-V2 update with top-b sigma normalisation.

10. CO-EVOLUTION LOOP (train.py main)
================================================================
Round-robin per species OR joint-rollout coevolution (default).
For each gen:
  - _refresh_world_list_if_needed(gen, iter) (re)samples WorldList =
    [(impact_seed_m, spawn_seed_m), ...] of length M, governed by
    --worlds_refresh (iteration|generation). Published to
    trainer.world_list and exposed as _current_world_list[0] for the
    legacy single-world install path.
  - _install_generation_worlds(gen) consumes _current_world_list[0]
    and builds _EnvBuilder with:
      * impact_seed -> impact map snapshot (impact_maps_snapshot)
      * spawn_seed  -> per-generation spawn snapshot, forwarded into
        load_project_config / setup_full_mareld_mvp so all
        deltas/workers in this generation see identical biomass maps
        per FG.
    _install_generation_maps is kept as a backward-compatible alias.
  - Worker pool rebuilt only when the WorldList actually (re)sampled.
  - For species in target_species: iter_per_gen train_step calls.
    Trainer's M-loop reads trainer.world_list and runs M rollouts per
    (delta, sign) pair with CRN coupling (see Section 28).
  - Generation header prints elapsed wall time, e.g.
    "========== Generation 2/100 (T=1.000) (01:14:55) ==========".
    Elapsed clock starts just before the first generation (after the
    interactive prompt), formatted as HH:MM:SS.
  - _save_checkpoint writes {'state_dict','obs_stats'} per generation.

KeyboardInterrupt handling: train.py calls os.setpgrp() at startup so
the parent process gets its own process group. TTY-delivered SIGINT
then only hits the parent (never the spawn-bootstrapping workers,
which would otherwise each dump a multi-page traceback during their
`import torch`). Workers also install signal.SIG_IGN in _worker_init
as backup. The parent catches KeyboardInterrupt, calls trainer.close()
(terminates pool fast), saves final checkpoints, returns cleanly.

20. SPAWN / SUB-THRESHOLD FIX (structural)
================================================================
Discovered cause of seals/porpoises "rest=100%" attractor:
min_split_biomass=50 kg combined with seals total=25 ton / 60x60 grid
= 6.94 kg/cell meant most cells were under-threshold; the old rule
zeroed move-actions, forcing rest=100%.

Two coordinated fixes:

DEL 1 - Cluster-spawn helper _spawn_biomass_distribution (legacy):
  * Eligible cells = allowed_mask>0 (None => full grid).
  * Per-cell floor = 10 * min_split_biomass.
  * Loop: random cell pick, biomass drawn uniformly in
    [floor, min(total_b, remaining)], assign, repeat.
  * Leftover (<floor) merged into a randomly chosen seeded cell.
  * If floor==0 -> legacy uniform Dirichlet.

DEL 1b - Strategy-driven spawn (lib/spawn/):
  When a `spawn:` block exists in project (per-FG) or library
  (per-species default), the helper goes through the new path:
    weights = make_weights(spec, (H,W), context, seed)
    initial_b = distribute_with_floor(weights, total_b,
                                      min_per_cell, allowed_mask=None)
  The allocator's floor semantics are unchanged so existing
  guarantees (no cell under floor; total preserved) still hold.
  See section 26 for the strategies.

DEL 2 - Sub-threshold collapse in ecosystem.py:
  * Removed move-mask zeroing on B < min_split.
  * After softmax, sub_thr_mask = (B>0) & (B<min_split) cells get a
    one-hot argmax over the full 11-action distribution. Whole group
    performs one action (including move) - small groups can migrate
    as a unit ("variant 2").

21. CO-EVOLUTION (default training mode)
================================================================
Implemented in trainer.train_step_coevolution and worker
_evaluate_coevo_task. Default ON.

Mechanics:
  * Per ARS iteration: one independent delta per species; CRN
    rollout seed across the +/- halves.
  * 2*n_deltas joint rollouts with ALL DM policies perturbed
    simultaneously. Each rollout returns one fitness per species.
  * ARS update is per-species, using THAT species' own deltas and
    its own r_pos/r_neg vector. No cross-species delta leakage.
  * Predator/prey feedback materialises in the same rollout instead
    of being averaged out against frozen opponents.

Empirical signature (reproducible):
  * Zooplankton "escape" from rest=100% to ~rs/et=40/60 around gen
    13-20 once pelagic_fish predation pressure ramps up.
  * Seals/porpoises rest=100% attractor: structural, robust to every
    intervention tried.
  * Gadoids reach POSITIVE reward once hacks are off.
  * Pelagic_fish converges to mv-dominant (74-98%) "flee" policy.

Kept eval snapshots: results/coev_5gen_100ticks_eval,
results/coev_20gen_100ticks_eval, results/coev_info_profile_40gen,
results/coev_20gen_noHacks, results/coev_info_20gen_postSpawnFix.

     distribution, min_split semantics, food web edges in
     fg_library.yaml, impact mortality tables, integral-reward,

rollouts, predator-prey cycles, response to impact fields, and

23. BIOLOGICAL SANITY CHECK FORMULA
================================================================
Per Strategi.pdf + konvergensproblem.txt "Kritisk insikt 4". For each
DM, compute per-tick energy balance at full hunger (h=1) and require
netto_eat > rest_cost.

IMPORTANT (commit 9317a54): `max_intake_rate` (a) is now on the
species_definitions level (one per predator FG), not per interaction.
Assimilation is captured via per-interaction `assimilation_factor`
[0,1]. The energy intake per (pred, prey) is:

  intake_at_h1 = a_pred * energy_gain_pred_prey *
                 assimilation_factor_pred_prey       # best prey
  feed_cost    = feeding_cost    * resting_metabolism
  rest_cost    = resting_cost    * resting_metabolism  # resting_cost=1
  move_cost    = movement_cost   * resting_metabolism

  netto_eat = intake_at_h1 - feed_cost                 # MUST be > 0
  Hard gate:        netto_eat > rest_cost
  Soft gate (move): netto_eat > move_cost

The numbers below are pre-9317a54 baselines and need recomputation
against the new YAML; the inequalities themselves are unchanged.

Post-update (current YAML):
  zooplankton  netto_eat=+101.4  eat-rest=+98.9   eat-move=+101.4
  pelagic_fish netto_eat=+84.8   eat-rest=+76.8   eat-move=+67.6
  gadoids      netto_eat=+564.5  eat-rest=+558.5  eat-move=+553.4
  porpoises    netto_eat=+95.0   eat-rest=+33.0   eat-move=-91.0 *
  seals        netto_eat=+147.5  eat-rest=+122.5  eat-move=+85.0
  seabirds     netto_eat=+493.5  eat-rest=+403.5  eat-move=+133.5
All DMs pass the hard gate. Porpoises fails the soft gate (move > eat).

26. SPAWN STRATEGIES PACKAGE (lib/spawn/)
================================================================
New subsystem (commit 2ef39f4) replacing the legacy uniform spread
for any FG that ships a `spawn:` YAML block.

Public API (lib/spawn/__init__.py):
  StrategySpec(mode, params, refs, seed)
  make_weights(spec, shape, context=None, project_seed=None) -> (H,W)
  distribute_with_floor(weights, total, min_per_cell,
                        allowed_mask=None) -> (H,W) biomass map

StrategySpec fields:
  mode    : "uniform" | "perlin" | "colony" | "env_driven"
  params  : mode-specific scalar dict (see schema below)
  refs    : list of {name, weight, transform} (env_driven only)
  seed    : optional int; when None, falls back to project_seed
            (which, in train.py's per-generation snapshot mode, is the
            adler32 of (gen_spawn_seed, fg_id)).

Strategies (lib/spawn/strategies.py):
  uniform     : equal weight per cell -> equivalent to legacy Dirichlet.
                No params.
  perlin      : fractal-sum Perlin noise on the cell grid.
                Params: Scale (cells/wavelength), Octaves (1-6),
                Persistence (0-1, amplitude falloff), Lacunarity (~2.0,
                frequency mult), Threshold (clamp-to-zero before
                normalisation). Pure numpy vectorised gradient noise.
  colony      : N Gaussian blobs of width sigma_cells around N random
                anchor cells.
                Params: N_colonies (int), Sigma_cells (float),
                Anchor ("free"|"coast"|"open_water"; reserved - anchor
                cells currently chosen uniformly until depth/coast map
                is wired in).
  env_driven  : weighted sum of existing env layers from `refs:`, plus
                optional Perlin overlay.
                Params: Floor (per-cell minimum before normalisation),
                Noise_amp (overlay amplitude), Noise_scale (overlay
                wavelength). Refs are looked up from
                context['env_layers'] by name; missing refs are filtered
                out at config_loader level.

Allocator (lib/spawn/allocator.py):
  distribute_with_floor implements:
    1. Ignore cells with allowed_mask==0.
    2. Pick n_active = clamp(int(total/min_per_cell), 1, n_eligible)
       cells by weight (deterministic argpartition + RNG tiebreak).
    3. Allocate floor=min_per_cell to each.
    4. Distribute the remainder proportionally to weights[active].
    5. Edge cases handled: total<floor (single cell), zero weights
       (uniform over allowed), allowed_mask all-zero (returns zeros),
       min_per_cell=0 (no floor; pure weighted distribution).
  Invariants verified by tests/test_allocator.py:
    - sum(map) == total (within fp eps)
    - all active cells >= min_per_cell
    - shape == requested shape, dtype float32
    - deterministic under same RNG seed

Integration (lib/config/config_loader.py):
  _build_spawn_spec(spawn_cfg, default_seed) parses YAML -> StrategySpec
  or returns None (legacy path).
  _derive_fg_spawn_seed(base, fg_id) -> adler32(f"{base}::{fg_id}")
  guarantees per-FG diversity under a shared generation-wide seed.
  Both setup_full_mareld_mvp and load_project_config call the same
  helper and accept `spawn_seed`.

  tests/test_spawn_integration.py     5 tests
  tests/test_uniform_bias_init.py    16 tests
  Total: 38, all green.

27. PER-GENERATION SPAWN SNAPSHOT (train.py)
================================================================
Goal: every delta/worker within ONE generation sees the same biomass
maps per FG (same total AND same spatial layout), analogous to the
impact-map snapshot. Across generations the layout still varies.

Mechanism:
  _EnvBuilder grew a `spawn_seed` attribute. _make_env_builder accepts
  spawn_seed and passes it into both load_project_config and
  setup_full_mareld_mvp.
  _install_generation_maps(gen_idx) now draws two INDEPENDENT seeds:
      gen_seed       = randint(1, 2**31-1)   # impact maps
      gen_spawn_seed = randint(1, 2**31-1)   # spawn snapshot
  The new builder is created with both, then the worker pool is
  rebuilt so spawn-workers receive the updated env_builder.

In load_project_config / setup_full_mareld_mvp:
  spawn_rng_base = spawn_seed if spawn_seed is not None else seed
  fg_spawn_seed  = _derive_fg_spawn_seed(spawn_rng_base, fg_id)
  spawn_spec     = _build_spawn_spec(cfg, default_seed=fg_spawn_seed)
  spawn_rng      = np.random.default_rng(fg_spawn_seed) if spawn_seed
                   else rng
  initial_b      = _spawn_biomass_distribution(grid, total_b,
                       min_per_cell, allowed_mask=None, rng=spawn_rng,
                       spawn_spec=spawn_spec,
                       project_seed=fg_spawn_seed)
When spawn_seed is set, total_b for the FG is also sampled from a
deterministic per-FG RNG so the ENTIRE biomass map (sum + shape) is
identical across rollouts in the generation. Without spawn_seed,
legacy per-rollout behaviour is preserved bit-for-bit.

Verified empirically (sanity script):
  (1) same spawn_seed + different rollout seed -> identical biomass maps.
  (2) different spawn_seed -> maps differ.
  (3) no spawn_seed -> legacy behaviour (maps vary per rollout).
  (4) within one spawn_seed: 28 distinct per-FG layouts across the 8
      FGs of mareld2 (no two FGs share an identical pattern).

Inference mode unchanged: total_b is already deterministic from
inference_initial_biomass, so spawn_seed only affects the spatial
layout via _build_spawn_spec there.

28. MULTI-WORLD AVERAGING PER DELTA (ARS variance reduction)
================================================================
Committed in a1484cd. Implements multi-world averaging per delta to
reduce gradient-estimate variance from the stochastic world
distribution (impact realisation + spawn layout). With M=1 the legacy
single-world path is byte-identical to pre-a1484cd behaviour.

Concept:
  Each ARS iteration draws a WorldList of length M:
      WorldList = [(impact_seed_1, spawn_seed_1), ..., (imp_M, sp_M)]
  For every delta i and every sign in {+, -}, the trainer evaluates
  M independent rollouts (one per world) and averages reward + act
  diagnostics:
      r_pos_i = mean_m R(theta + sigma*delta_i, world_m)
      r_neg_i = mean_m R(theta - sigma*delta_i, world_m)
  CRN coupling: +delta and -delta for the SAME (i, m) pair share the
  SAME world AND the SAME pair_seed[i]. This makes Var(r_pos - r_neg)
  drop faster than 1/M (world-wise anti-correlation).
  Top-b ranking happens on the M-averaged r_pos/r_neg vectors, so it
  is much less brittle than under the world noise of M=1.

CLI (Section 5):
  --rollouts_per_delta M       Static M. Profiles force 3; default 1.
  --worlds_refresh POLICY      "iteration" (default; resample each
                               ARS iter) or "generation" (lock for
                               whole gen).
  --rollouts_per_delta_schedule "M0@G0,M1@G1,..."
                               e.g. "1@0,3@10,5@50". Overrides
                               --rollouts_per_delta.

Seed bookkeeping (train.py):
  _world_rng = np.random.default_rng()  (independent of np global RNG)
  _sample_world_list(M) -> [(impact_seed, spawn_seed), ...] drawn
      from _world_rng (so future --seed plumbing is trivial).
  _resolve_M(gen, args) -> int (schedule lookup or static).
  _parse_M_schedule(spec) -> sorted [(gen_threshold, M), ...].
  _refresh_world_list_if_needed(gen, iter) -> bool
      Returns True iff the WorldList actually (re)sampled. Publishes
      to _current_world_list AND trainer.world_list. Refresh rules:
        * iter == 0 within a generation -> always (re)sample.
        * worlds_refresh == "iteration" -> resample every iter.
        * worlds_refresh == "generation" -> no resample for iter>0.

Trainer integration (lib/runners/trainer.py):
  self.world_list = []                    (populated by train.py)
  _resolve_world_builders(): returns [self.env_builder] when M<=1
      (legacy tuple-task path), otherwise [env_builder.with_world(imp,
      sp) for imp, sp in world_list] -> M sibling builders.
  train_step / train_step_coevolution: M-loop wraps the existing
      (delta_i, sign) loop. Tasks are dict-format when M>1 carrying
      'env_builder' override per task; tuple-format when M==1 for
      byte-identical legacy worker path.
  Averaging helpers (null-tolerant): _avg_act_diags, _avg_act_dicts,
      _avg_fit_dicts. Reward and act_diag are averaged over M; fitness
      shape unchanged so the rest of the ARS update is intact.

Worker (lib/runners/parallel_worker.py):
  _evaluate_task / _evaluate_coevo_task accept BOTH tuple and dict
  task formats. Dict format may carry an 'env_builder' override per
  task; falls back to module-global _ENV_BUILDER (legacy) otherwise.

_EnvBuilder.with_world(impact_seed, spawn_seed):
  Returns a fresh sibling builder with re-sampled impact maps and a
  locked spawn_seed; all other state (grid, project, impact recipe)
  is inherited. Picklable for spawn-context workers.

Profile defaults: sanity / info / deep all set rollouts_per_delta=3.
Override via explicit --rollouts_per_delta on the CLI.

Pre-prompt header (train.py): prints a "Rollouts/Delta" line showing
either the static M (with user/default/profile marking) or the
schedule string, plus the worlds_refresh policy.

Cost: total rollouts per iteration = 2 * n_deltas * M. The worker
pool's _auto_workers cap at 2*n_deltas means M>1 utilises more
parallelism than M=1, so wall-time scales sub-linearly with M up to
the CPU core count.

Open follow-ups (not implemented yet):
  * Adaptive M based on gradient-norm CV or top-b rank instability
    (sketched in Section 28 of the original design discussion).
  * A/B variance-reduction test (M=1 vs M=5) on a deterministic seed
    sequence to quantify the empirical win.
  * --seed plumbing into _world_rng for fully reproducible WorldLists.

36. CALIBRATION NOTE - max_intake_rate IS PHYSIOLOGICAL CEILING
================================================================
Per Method.pdf, `max_intake_rate` (a = I_XY) is defined as a
*physiological 6h ceiling* on intake (ton prey per ton predator per
tick) - the maximum the FG can physically ingest at saturating prey
density, NOT a sustained field average.

For zooplankton_preys_on_phytoplankton:
  max_intake_rate = 0.4   (160 % WW/day maximum)
  handling_time   = 2.5   (canonical Type II: 1/h = a)

The Type II ceiling 1/h is set to equal a so that the saturated
response lands AT the physiological maximum, not above it. Previously
h was 0.1 (1/h = 10, i.e. 25x above the ceiling), which effectively
disabled saturation at all biologically relevant prey densities - the
opposite of the intended Fix 2 effect.

Why a=0.4 is defensible at individual level (max interpretation):
  * Copepod gut throughput at saturation ~30-60 min -> theoretical max
    ~150-180 % WW/day (Frost 1972, Mauchline 1998, Kiorboe 2011 as
    max-capacity estimates, NOT sustained grazing).
  * Earlier "cell-aggregation upscaling" rationalisation was a post hoc
    fit; the max-ceiling interpretation removes the need for it.

Note on literature comparisons:
  * Sustained field grazing averages (5-20 % WW/day for copepods) are
    typically 3-5x lower than physiological maxima (GER/gut throughput).
  * Comparing `a` against sustained averages systematically
    underestimates "rimliga" YAML values by the same 3-5x factor.

Documentation locations:
  * fg_library.yaml: comment block above
    zooplankton_preys_on_phytoplankton explaining max-ceiling rationale.
  * lib/environments/ecosystem.py: comment in _build_static_caches
    documenting the canonical Type II convention (h = 1/a).

Implication for other predation relations in fg_library.yaml:
  * Under max-interpretation, most upper-trophic-level a values
    (pelagic_fish, porpoises, seals, seabirds) are defensible as
    physiological ceilings (3-5x sustained-litt.).
  * `gadoids_preys_on_pelagic_fish` was previously 0.115 (46 %/day,
    ~3x even max-literature for adult cod ~15 %/day) - currently set
    to 0.04 in fg_library.yaml. Still worth A/B-testing if upper
    trophic levels are activated.

Implication for future modifications:
  * If physiological max changes (different species, life stage, temp),
    both `a` and `h = 1/a` must be updated together.
  * Adding horizontal movement only affects realised intake, not the
    ceiling itself.

Sanity-test impact:
  * test_zoo_bounded_in_closed_phyto_zoo_system tolerance widened
    from [0.05, 100] to [0.03, 100] because tighter saturation
    suppresses zoo more after 200 ticks than under h=0.1.

37. ZOO+PHYTO SYSTEM-LEVEL UNRESOLVED PROBLEMS
================================================================
After all fixes in Sections 30-36, the closed phyto+zoo system still
has these biological/architectural deficiencies (documented but NOT
fixed):

  1. DM growth has no logistic cap. Non-DM has (1-B/cc); DM is purely
     energy-bounded. Only constraints on B_zoo upward: q_x<0 (energy
     starvation) and natural_mortality (Fix 3).
  2. q_x saturates: s_x = R/(B*ME) is a normalised fill ratio.
     Once R is full, q_x is decoupled from local prey density. LV
     coupling g(P)*Z is only weakly approximated.
  3. Phyto carrying capacity cc is static per cell; no nutrient
     budget / no nutrient recycling from dead zoo. seed_rate fixes
     the "extinction" symptom but not the underlying open-energy
     issue.
  4. zoo.movement_speed = 0 means no spatial refuge can develop;
     zoo spawns on phyto via env_driven refs (Section 30), so any
     zoo cell is immediately adjacent to its food.
  5. No diapause for zoo (real copepods enter dormancy at low food).
  6. Reward horizon in train.py (--n_eval_ticks default 2, info
     profile 150) is much shorter than zoo collapse timescale
     (~700 ticks in baseline rollouts). Training optimises a horizon
     that doesn't see long-term consequences.

Open follow-up ideas (not implemented):
  * Holling Type II GUI exposure in matrix editor.
  * Strip energy_gain entirely + always read prey.energy_content.
  * Diffusion / horizontal advection of NDM biomass for proper
    spatial refuges.
  * Nutrient pool tied to cc with explicit zoo-mortality -> nutrient
    return flux.

    biomass heatmap, 60x60 cells x cell_px=6, viridis LUT (analytic
    approx, no matplotlib dep). Per-panel title is two lines:
      line 1: display name (e.g. "Pelagic fish" - underscores
              stripped, first letter capitalised)
      line 2: "B0=...  B=..." (rollout-start total + current total)
    Below each heatmap: a colorbar gradient strip with "0" (left)
    and a compact vmax label (right; e.g. "12.3k" or "log1p<=...").
    Normalisation is PER-FG (otherwise phyto/benthos dominate).
  * Right pane: rolling line plot.
      train mode: per-DM ARS reward (means[fid] per ARS iter).
      inference mode: per-FG total biomass over ticks.
    Legend rendered with display names (max 18 chars).

Key bindings (handled in pump_events):
  space     pause / resume
  l         toggle log1p scale on heatmaps
  r         toggle log10 scale on plot
  1..9      solo-focus FG by index (toggle off with same key)
  q / esc   close visualiser (training/inference continues)

Defensive design (do not regress):
  * Headless fallback: __new__ sets SDL_VIDEODRIVER=dummy if DISPLAY
    is unset and SDL_VIDEODRIVER isn't already set.
  * If pygame import fails: __new__ returns a _NullViz singleton with
    no-op methods (so --visual on a box without pygame is a silent
    no-op + one stderr line).
  * Every public method is wrapped in try/except + _log_once; never
    propagates to the training/inference loop.
  * pump_events() returns False on QUIT; callers must respect that
    and set viz=None for the remainder of the run (both train.py and
    inference.py do).

Integration in train.py:
  * Visualiser is instantiated in the MAIN PROCESS ONLY (workers
    never import lib.viz). Lives as `viz` local in main().
  * update_reward(fid, means[fid], step=gen*iter_per_gen+i) after
    every ARS iter (round-robin and coevolution paths both wired).
  * _probe_biomass(...) accepts viz= + viz_extra= and renders the
    deterministic probe rollout tick-by-tick (perfect heatmap source
    since it's CRN-locked).
  * If pump_events() returns False mid-loop, viz.close() is called
    once and viz=None for the rest of the run.

Integration in inference.py:
  * --visual creates LiveVisualizer(mode="inference"); run_inference
    accepts viz= and updates both heatmap (env.fgs) and per-FG
    biomass time series (history[fid]) every tick.
  * Closed in a finally block so the window always tears down cleanly.

Performance budget:
  * fps_cap=30; render only when (now - last_frame_ts) >= 1/fps_cap.
  * 8 heatmaps * 60x60 + line plot @ 30 FPS ~ 2-3 ms/frame.
  * Train: rendering is at probe-tick granularity (already CRN-cheap),
    not per ARS-rollout-tick, so no measurable training slowdown.

Dependency:
  * pygame is NOT in requirements.txt by design; install manually
    (`pip install pygame`) on machines where the visualiser is wanted.
  * Without pygame: --visual prints a one-line stderr warning and
    runs as a no-op (verified path).

41. OBSERVABILITY MATRIX + HIDE-ACTION (Rest)
================================================================
New subsystem (uncommitted at time of writing) combining a per-DM
input-space restriction (Observability matrix) with a per-DM hide
behaviour wired to the existing Rest action. Both halves are driven
from fgconfig.py and propagate through config_loader, train.py and
ecosystem.py.

41.1 Observability matrix (GUI)
  * New matrix in fgconfig.py "FG Interactions" tab, rendered
    directly below Predation: "Observability (row observes column)".
    Cell semantics: row_fg observes col_fg if checked.
  * Rows are decision_makers only (NDMs have no policy network and
    no input space); columns are all FGs.
  * Self-cells (row == col) are forced True and disabled - a DM
    always sees its own B_own/E_own by construction.
  * Muting greys out both the row and the column of the muted FG,
    same semantics as Predation (muted == FG does not exist).
  * Linked to Predation: setting x preys_on y forces
    x observes y = True AND disables the corresponding observability
    cell (predator must see its prey). Unchecking predation re-
    enables the observability cell (unless self/muted).
  * Persisted to fg_library.yaml interaction_definitions as
    "<observer>_observes_<target>": {observes: bool} entries.

41.2 Runtime: per-DM input space
  * lib/config/config_loader.py parses _observes_ keys into
    fg.params['observes'] = [target_id, ...] (excludes muted FGs).
    If NO _observes_ keys exist for a DM, params['observes'] is None
    and the legacy "see everyone" fallback is used.
  * train.py::get_dynamic_policy_params returns a per-DM in_dim_i
    based on k_i = number of observed OTHER FGs (Section 4 formula).
  * ecosystem.py::_build_static_caches builds:
      - obs_others_idx[i] : (k_i,) j-indices into global_fg_order
                            for DM i (excluding self).
      - per_dm_in_dim[i]  : int, the compact in_dim_i.
      - max_in_dim        : int, max over all DMs (used for padding).
  * ecosystem.py::_build_observation_batch writes a compact per-DM
    layout into the top per_dm_in_dim[i] slots of a
    (N_dm, max_in_dim, H, W) tensor; remaining slots are 0.
  * ecosystem.py::_rebuild_batched_weights pads each policy's W1
    to (max_in_dim, hid) with zero rows. Since the obs tensor is
    also zero in padding slots, padded rows contribute nothing.
  * trainer.py::_get_dm_ids_and_dim reads env.max_in_dim for
    batched-tensor sizing.

41.3 Hide-action (Rest is also a hide action)
  * "Rest" action 4: pi_rest[i, h, w] is the fraction of DM i's
    biomass that rests in cell (h, w) this tick.
  * Hide semantics: that fraction is (a) FULLY PROTECTED from
    predation this tick AND (b) INVISIBLE to other FGs observing
    this DM in their NEXT tick's observation.
  * Self-observation is NOT attenuated: B_own always uses full
    biomass (a DM knows its own total mass, hidden or not).
  * NDMs have no action policy and therefore never hide - their
    biomass is always fully edible and fully visible.

41.4 Implementation (ecosystem.py)
  * prev_hidden_frac : (N_all, H, W) cache, initialised to 0 in
    _build_static_caches. Indexed by global_fg_order. NDM rows
    stay 0 permanently.
  * _build_observation_batch: B_visible_all = B_all *
    (1 - prev_hidden_frac); B_obs = B_visible_all[obs_others_idx[i]]
    is used for the observer's center + 4 neighbour B-channels.
    B_own is taken from full B_all unmodified.
  * _calculate_decisions (end): prev_hidden_frac is rewritten from
    THIS tick's pi_rest so that the NEXT tick's observation sees
    the just-decided hidden mass.
  * _apply_predation: hidden_frac_now is built from THIS tick's
    pi_rest. B_prey_visible = B_prey_all * (1 - hidden_frac_now).
    Holling-II uses B_prey_visible in a_eff; the demand-cap uses
    B_prey_visible. The hidden fraction never enters predator
    accounting this tick.

41.5 Tick-asymmetry (intentional; only causally consistent ordering)
  Within one tick:
    1. _build_observation_batch uses prev_hidden_frac
       (= pi_rest from tick t-1).
    2. _calculate_decisions produces pi_rest_t.
    3. _apply_predation uses pi_rest_t directly (hidden_frac_now).
    4. prev_hidden_frac <- pi_rest_t (for tick t+1).
  Observers therefore see "what was hidden last tick" while
  protection is determined by the active hide-choice this tick.
  The reverse (observers seeing pi_rest_t) would be circular -
  policies decide pi_rest_t based on the observation that would
  need pi_rest_t as input. Using pi_rest_{t-1} for predation would
  delay the protective effect of hide by one tick (incoherent).
  Edge cases:
    * First tick: prev_hidden_frac = 0 -> nothing hidden, correct
      (no decisions taken yet).
    * Stationary pi_rest*: asymmetry vanishes (pi_rest_t = pi_rest_{t-1}).
    * NDMs: hidden_frac stays 0 in both buffers -> no asymmetry.

41.6 Backwards compatibility
  * Legacy projects (no _observes_ keys, no Rest hide expectation):
    k_i = N_all - 1, prev_hidden_frac stays 0 from the start (it is
    populated only after first _calculate_decisions). Numerically
    the FIRST tick is byte-identical to the pre-hide path; from
    tick 2 onward, observers see attenuated B_obs whenever any DM
    chose nonzero pi_rest in the previous tick. Trained policies
    from before this change are dimensionally compatible only if
    no _observes_ keys are present; the semantic shift of B_obs
    (visible vs raw) generally warrants retraining when hide
    behaviour matters.
  * Checkpoint invalidation: any change to the Observability matrix
    shifts k_i and invalidates .pth files for affected DMs.

41.7 Verification
  * python3 -m pytest tests/ -q -> 42 passed.
  * Manual on mareld2.yaml (10x10 grid):
      - explicit observability (zoo sees only phyto):
        zooplankton.in_dim = 11, pelagic_fish.in_dim = 16,
        max_in_dim = 16, env.step() OK.
      - legacy (no _observes_): in_dim = 16 for all DMs (unchanged).
      - forced pi_rest = 1 for zooplankton: predation biomass delta
        on zooplankton = 0.000 (fully protected).
      - forced pi_rest = 0: predation biomass delta = 0.92 (normal).
      - prev_hidden_frac after one tick: phytoplankton (NDM) mean=0,
        zooplankton (DM) mean=0.505, pelagic_fish (DM) mean=0.181.

41.8 Open follow-ups
  * No GUI editor for the asymmetry (it is hard-coded).
  * Predators cannot anticipate prey hide-decisions in a feed-
    forward policy (no memory) - would need RNN / history-stack.
  * Observability changes invalidate checkpoints; no migration
    helper is provided.

42. OFFLINE INTERACTIVE PLOTS (plots.html) + VIZ RESPONSIVENESS
================================================================
Late-session arc covering (a) what biomass.jsonl now contains, (b)
the offline HTML viewer tools/biomass_html.py, (c) automatic HTML
regeneration from train.py, and (d) the live pygame viz
responsiveness fix during long blocking train_step calls.

42.1 biomass.jsonl - extended fields
  train.py::_probe_biomass now persists the SAME series the live
  pygame viz exposes as tabs, so the offline HTML can reconstruct
  the live experience from a single jsonl file. One JSON record per
  probe rollout (one per ARS iter), with fields:
    gen, iter, n_ticks                                  (scalars)
    b0, bh, ratio, log10_ratio                          (per FG)
    energy_ratio                                        (per FG)
    move_frac, rest_frac, eat_frac                      (per DM,
        in PERCENT of active ticks - same formula as
        inference._push_action_fracs: 100*sum/active_ticks)
    rnd: {ratio, energy_ratio, move_frac, rest_frac,
          eat_frac}                                     (random-action
        baseline; only present when rnd_env is active)
  Old jsonl files (without these new fields) are still readable -
  the HTML generator skips tabs that have no data.

42.2 tools/biomass_html.py - the offline viewer
  Pure-Python (no third-party deps); Plotly is loaded from CDN by
  the produced HTML. CLI:
      python3 tools/biomass_html.py <run_dir> [-o <out_path>]
  Default output: <run_dir>/plots.html (renamed from biomass.html).

  Tabs (in this order, only included when data is present):
    reward (log10_ratio), biomass (ratio), energy (energy_ratio),
    move, rest, eat (action fractions), bh, b0.
  One trace per FG per tab; when ``rnd`` baseline exists, an
  additional dashed ``<fid>_rnd`` trace is added per FG with
  ``visible: "legendonly"``.

  Legend toggling: showlegend=true, itemclick="toggle",
  itemdoubleclick="toggleothers", hovermode="closest". Each trace
  has its own ``legendgroup`` so every series is independently
  clickable in the legend (matches live viz's per-FG checkboxes).

  Per-FG colours match the live pygame viz EXACTLY:
    * Helper _fg_colour_rgb(idx) replicates
      lib/viz/pygame_viz.py::_fg_colour_for: golden-ratio hue
      (idx*0.61803398875 mod 1), HSV(hue, 0.65, 0.95) -> RGB.
    * Helper _fg_rnd_colour_for(idx) applies the same per-channel
      max(0, c-90) darkening that pygame_viz uses for the random
      baseline (so dashed _rnd traces are the dimmed sibling
      colour of the main FG).
    * Global colour_index built from the ``b0`` field's first-seen
      order (fallback bh -> ratio), because b0 is written by
      _probe_biomass by iterating env.fgs -> matches env.fg_ids
      insertion order used by the live viz. Extra ids (e.g.
      rnd-only) are unioned in afterwards.

42.3 train.py auto-regeneration
  New helper _regenerate_biomass_html(run_dir):
    * Lazy imports tools/biomass_html.py via importlib (so a missing
      or broken tool can never break train.py).
    * Reads <run_dir>/biomass.jsonl and writes <run_dir>/plots.html
      using _build_html. Silent no-op when the jsonl is missing or
      empty. All exceptions caught and reported with a one-line
      WARN to stdout.
  Called on three paths so the file is ALWAYS fresh:
    * After the coev branch's _save_checkpoint loop.
    * After the round-robin branch's per-species _save_checkpoint.
    * In the KeyboardInterrupt handler after the "Final checkpoint"
      saves -> Ctrl+C also leaves a fresh plots.html behind.
  Typical regen time <1s for normal jsonl sizes; could throttle for
  very long runs but not done yet.

42.4 Live pygame viz responsiveness (--visual)
  Problem: window appeared "not responding" during long blocking
  train_step calls because the SDL event queue was only pumped
  between ARS iterations.
  Fix (final state, after several iterations):
    * lib/runners/trainer.py: new attribute pump_callback (no-arg
      callable) + helper _pool_map(func, tasks) that uses
      pool.map_async + async_res.wait(timeout=0.05) loop, calling
      pump_callback every ~50 ms. Both self._pool.map(_evaluate_task,
      ...) and self._pool.map(_evaluate_coevo_task, ...) go through
      _pool_map. Also _pump() helper called after each _pool_map and
      before each train_step return, so events are drained between
      ARS update / z-score / diagnostics steps too.
    * train.py: after trainer creation, sets
      trainer.pump_callback = _viz_pump where _viz_pump calls
      viz.pump_events() IN THE MAIN THREAD. If the user closes the
      window, the callback is cleared so pumping ceases without
      disturbing training.
    * lib/viz/pygame_viz.py::pump_events:
      pg.event.pump() FIRST (drives OS->SDL transfer), then
      event.get() loop, then on user input reset _last_frame_ts and
      call _maybe_render() once, then pg.event.pump() again to
      catch clicks arriving during the redraw. Without user input,
      _maybe_render still runs but FPS-capped (default 30) so the
      worker pool isn't starved.
  Important rule (re-learned): SDL/X11 requires event handling in
  the thread that created the display - background-thread pumping
  is a no-op. Earlier daemon-thread pump attempt has been REMOVED;
  do not reintroduce it.

  Limitation: sequential path (self._pool is None, e.g.
  --workers 1 or n_deltas==1) does NOT pump mid-rollout - only
  between iterations. Acceptable for the standard --visual use
  case (worker pool > 1).
