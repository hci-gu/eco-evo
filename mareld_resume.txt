3. "THE TICK" PIPELINE (lib/environments/ecosystem.py)
================================================================
Random FG order each tick (random.sample). Per tick:
  1. _calculate_decisions  (batched over all DMs)
     - obs_batch (N_dm, H*W, D) built once. D = 2 + (N_fgs - 1) + 1.
     - All DM policies in ONE batched torch.bmm forward (3 stacked weight
       tensors built once in _build_static_caches: (N_dm, in, hid),
       (N_dm, hid, hid), (N_dm, hid, out)). No per-DM loop, no numpy roundtrip.
     - Output: pi_move (N_dm,4,H,W), pi_rest (N_dm,H,W),
       pi_eat (N_dm,N_all,H,W).
     - Mask BEFORE renormalization:
         * Move masked by precomputed move_mask (accessibility + edges).
         * Eat masked by static eat_mask AND (prey.biomass > 0).
     - Renormalize across remaining actions.
  2. _apply_predation  (fully vectorized)
     - Stacked B (N_all,H,W), pi_eat (N_dm,N_all,H,W).
     - max_intake_mat, energy_gain_mat: (N_dm,N_all) constants from init.
     - D = B_pred[:,None]*pi_eat*max_intake[:,:,None,None]*hunger[:,None]
     - total_demand=D.sum(0); scale=min(1, B_prey/(total_demand+eps))
     - actual=D*scale; predator gain=(actual*energy_gain).sum(1)
     - temp_energy_gains buffered (added AFTER metabolism on stayers).
     - Prey biomass reduced; R scaled with B (R/B preserved).
  3. _apply_movement  (slice-assign, vectorized over N_dm)
     - Each cell's biomass split by action probs.
     - Each fraction pays own metabolic cost * resting_metabolism *
       (1 + sens*noise).
     - Slice-assign instead of np.roll (no copies, no wrap-around;
       edges already zeroed in _calculate_decisions).
     - flux = clip(v, 0, 1). Energy follows biomass.
     - temp_energy_gains added to stayers AFTER metabolism.
  4. _apply_growth_and_impact
     - NDM (phyto/benthos): logistic dB = MG*B*(1 - B/CC).
     - DM: s=R/(B*ME), u=0.3, q=s-u, B_new=B*(1+MG*q).
     - Mortality: B reduced by sensitivity*impact_map; R scaled with B.

9. ARS TRAINER (lib/runners/trainer.py)
================================================================
ARSTrainer(env_builder, policy_params,
           sigma=0.1, lr=0.03, n_deltas=10,
           n_workers=1, alpha=1.0, beta=1.0)
  policies: persistent {fg_id: PolicyNetwork} — co-evolution-safe
            (weights kept across generations).
  _pool: spawn-context Pool when n_workers > 1.
         close() uses pool.terminate()+join() (robust on Ctrl+C).

train_step(fg_to_train, n_eval_ticks=2):
  1. Sample n_deltas directions (torch.randn).
  2. Draw pair_seeds[i] from np.random (one per delta pair).
  3. For each i: evaluate +sigma*delta and -sigma*delta with the SAME
     pair_seeds[i] — Common Random Numbers, variance reduction.
  4. Sequential: in-process; restore parent weights after.
     Parallel: 2*n_deltas tasks =
       (fg, weights_snapshot_dict, n_eval_ticks, alpha, beta, seed)
     dispatched via pool.map. base_weights snapshot includes ALL policies
     so opponents are at current co-evolved state.
  5. Fitness (in _evaluate / _evaluate_task):
       b0,r0 = trained FG biomass.sum(), energy.sum() (post-build)
       run env.step() n_eval_ticks times
       bh,rh = same, post-run
       delta_b = log((bh+eps)/(b0+eps)); delta_r similar
       fitness = alpha*delta_b + beta*delta_r
  6. Gradient: step = sum_i (r_pos[i]-r_neg[i]) * delta[i],
              w_new = w + (lr/(n_deltas*sigma_f)) * step,
              sigma_f = std([r_pos..., r_neg...]) + 1e-8.

10. CO-EVOLUTION LOOP (train.py main)
================================================================
Round-robin (Variant A):
  for gen in count() [or range(generations)]:
      for species in target_species:
          for i in range(iter_per_gen):
              trainer.train_step(species, n_eval_ticks=...)
          torch.save(policy_state, results/policy_<species>.pth)   # per gen

KeyboardInterrupt (Ctrl+C):
  - Workers ignore SIGINT (set in _worker_init); only parent catches it.
  - On Ctrl+C: trainer.close() (terminates pool fast), save final
    checkpoints per species, print "Training interrupted; partial
    progress saved", return cleanly (exit 0).

13. PERFORMANCE NOTES (already optimized — don't redo without measuring)
================================================================
Implemented:
  - Batched policy inference for all DMs via torch.bmm.
  - Vectorized predation over (N_dm, N_all, H, W) tensors.
  - Slice-assign movement (no np.roll).
  - Preallocated/cached masks (move_mask, eat_static_mask).
  - float32 throughout hot path.
  - Parallel rollouts via multiprocessing.Pool (spawn).
  - OMP/MKL/OPENBLAS/torch threads = 1 in workers (without this,
    BLAS contention can make parallel SLOWER than sequential).
  - CRN: same world for +delta and -delta in each ARS pair; different
    seeds between pairs.

Measured (60x60, 6 DMs):
  - 100 ticks: 1.257s -> 0.824s (1.53x).
  - 15 iter pelagic_fish: 11.9s seq -> 5.34s @ 16 workers (24-core machine).

Intentionally NOT done:
  - Numba: hot path is numpy/torch vectorized; would win only at much
    larger grids or for agent-based reformulation.
  - GPU: too small (host-device copy dominates).
  - Synchronous Nash-Q-like co-evolution snapshot.
