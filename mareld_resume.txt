3. "THE TICK" PIPELINE (lib/environments/ecosystem.py)
================================================================
Random FG order each tick (random.sample). Per tick — order follows
Method.pdf §steg 1–6 (impact mortality applied BEFORE predation so
predators see the post-impact prey biomass):
  _calculate_decisions → _apply_impact_mortality → _apply_predation
  → _apply_movement → _apply_growth

  1. _calculate_decisions  (batched over all DMs)
     - obs_batch (N_dm, H*W, D) built once.
       D = 2 + (N_fgs - 1) + n_observable_impacts, where
       n_observable_impacts = len(env.observable_impact_vars).
       Channel layout per DM: [B_own, E_own, B_others...,
                               <one channel per observable impact, in order>].
       Missing impact maps default to zero fields so the layout is stable.
     - Raw-obs stats accumulated (sum, sumsq, count) for trainer merge.
     - If env.obs_mean/obs_var set: obs <- clip((obs-mean)/sqrt(var+eps),
       -10, 10) BEFORE the policy forward.
     - All DM policies in ONE batched torch.bmm forward (3 stacked weight
       tensors built once in _build_static_caches: (N_dm, in, hid),
       (N_dm, hid, hid), (N_dm, hid, out)).
     - Output: pi_move (N_dm,4,H,W), pi_rest (N_dm,H,W),
       pi_eat (N_dm,N_all,H,W).
     - Mask BEFORE renormalization:
         * Move masked by precomputed move_mask (accessibility + edges).
         * Eat masked by static eat_mask AND (prey.biomass > 0).
     - Renormalize across remaining actions.
  2. _apply_impact_mortality  (Method.pdf step before predation)
     - For each FG and each active impact map: look up
       (biomass_factor, energy_factor) via linear interpolation in
       the per-(fg, impact) `impact_table` (clip to endpoints; no
       extrapolation).
       Old scalar `impact_sensitivity` is fully removed.
     - Apply direct mortality m_X^Impact: B reduced, R scaled
       proportionally to the biomass loss (so E = R/B is preserved
       for the surviving fraction).
     - Implemented in _compute_impact_mortality + _apply_impact_mortality.

  3. _apply_predation  (fully vectorized)
     - Stacked B (N_all,H,W), pi_eat (N_dm,N_all,H,W).
     - max_intake_mat, energy_gain_mat: (N_dm,N_all) constants from init.
     - D = B_pred[:,None]*pi_eat*max_intake[:,:,None,None]*hunger[:,None]
     - total_demand=D.sum(0); scale=min(1, B_prey/(total_demand+eps))
     - actual=D*scale; predator gain=(actual*energy_gain).sum(1)
     - temp_energy_gains buffered (added AFTER metabolism on stayers).
     - Prey biomass reduced; R scaled with B (R/B preserved).
  Sub-threshold cells (0 < B_dm[i] < dm_min_split[i]) are NO LONGER
  mask-restricted (move was previously zeroed and policy renormalised
  to rest/eat — that hard rule turned out to be the dominant cause of
  the seals/porpoises "rest=100%" attractor). Instead, after softmax
  the env replaces those cells' distribution with a one-hot argmax
  over the full 11-action set; the whole sub-threshold group performs
  one action on 100% of the cell biomass (variant 2 — small groups
  may migrate as a unit). Units: dm_min_split is in tonnes (converted
  from kg at FunctionalGroup input). See section 20.

  4. _apply_movement  (slice-assign, vectorized over N_dm)
     - Each cell's biomass split by action probs.
     - Each fraction pays own metabolic cost * resting_metabolism.
     - Slice-assign instead of np.roll (no copies, no wrap-around;
       edges already zeroed in _calculate_decisions).
     - flux = clip(v, 0, 1). Energy follows biomass.
     - temp_energy_gains added to stayers AFTER metabolism.
  5. _apply_growth  (runs LAST; impact mortality has moved out)
     - NDM (phyto/benthos): logistic dB = MG*B*(1 - B/CC); B clipped
       to [0, CC]. R not updated for NDMs.
     - DM: s = R/(B*ME), u = fg.maintenance_level (per-FG, default 0.3),
       q = s - u, growth = B*MG*q.
         * Positive growth: only B is updated (R unchanged) → implicit
           energy dilution (Variant B): E(t+1) = R^mov / (B^mov + growth).
           R = B·E is strictly conserved across the growth step; per-ton
           energy is diluted by new biomass, which feeds back into q next
           tick (self-regulating growth).
         * Negative growth: B and R are scaled by the same factor so E
           is preserved for the shrinking cell.

4. POLICY NETWORK DIMENSIONS
================================================================
  Input  = 2 + (N_fgs - 1) + n_observable_impacts
           = n_fgs + 1 + n_observable_impacts
  Output = 5 + N_all_fgs   (non-prey slots eat-masked)
  Computed in train.py:get_dynamic_policy_params(fgs, n_observable_impacts).
  n_observable_impacts = number of impacts with ``observable: true`` in the
  project's impact_variables list (mute-aware, order = project order).
  Toggling the Impact Editor's "Observable by policy" checkbox changes
  in_dim and therefore invalidates all existing .pth checkpoints — the
  GUI shows an info dialog stating that retraining is required.
  .pth files NOT portable across projects with different FG counts or
  different observable-impact counts/orders.

9. ARS TRAINER (lib/runners/trainer.py)
================================================================
ARSTrainer(env_builder, policy_params,
           sigma=0.1, lr=0.02, n_deltas=8,
           n_workers=1, alpha=1.0, beta=1.0,
           obs_normalize=True, top_deltas=None)
  policies: persistent {fg_id: PolicyNetwork} — co-evolution-safe
            (weights kept across generations).
  obs_stats: persistent {fg_id: {mean (D,), var (D,), count}} across
             generations. Used to feed env.obs_mean/obs_var per rollout
             (frozen during rollout). Updated via Welford parallel merge
             after each train_step from samples returned by every rollout.
  top_deltas: None -> all n_deltas used. When set, only the top-b pairs
              (sorted by max(r_pos,r_neg)) contribute to gradient AND to
              sigma_f.
  _pool: spawn-context Pool when n_workers > 1.
         close() uses pool.terminate()+join() (robust on Ctrl+C).

train_step(fg_to_train, n_eval_ticks=2):
  1. Sample n_deltas directions (torch.randn).
  2. Draw pair_seeds[i] from np.random (one per delta pair).
  3. Build current (N_dm, D) obs_mean/obs_var arrays from obs_stats
     (ordered by env.dm_ids); pack with dm_ids list.
  4. For each i: evaluate +sigma*delta and -sigma*delta with the SAME
     pair_seeds[i] — Common Random Numbers, variance reduction.
  5. Sequential: in-process; restore parent weights after.
     Parallel: 2*n_deltas tasks =
       (fg, weights_snapshot_dict, n_eval_ticks, alpha, beta, seed, obs_pack)
     dispatched via pool.map. base_weights snapshot includes ALL policies
     so opponents are at current co-evolved state.
     Each task returns (fitness, samples) where samples =
       (sum (N_dm,D) f64, sumsq (N_dm,D) f64, count int).
  6. Fitness (in _evaluate / _evaluate_task):
       b0,r0 = trained FG biomass.sum(), energy.sum() (post-build)
       run env.step() n_eval_ticks times
       bh,rh = same, post-run
       delta_b = log((bh+eps)/(b0+eps)); delta_r similar
       fitness = alpha*delta_b + beta*delta_r
  7. Merge all rollout samples into obs_stats via Welford parallel:
       n = n_a + n_b
       new_mean = mean_a + (mean_b - mean_a) * n_b/n
       M2 = M2_a + M2_b + (delta**2) * (n_a*n_b/n)
       var = max(M2/n, 1e-8)
  8. ARS update (ARS-V2 with top-b):
       pair_scores = max(rewards_pos, rewards_neg)
       top_idx = argsort(-pair_scores)[:b]
       sigma_f = std(concat(r_pos[top], r_neg[top])) + 1e-8
       step = sum_{i in top_idx} (r_pos[i]-r_neg[i]) * delta[i]
       w_new = w + (lr/(b*sigma_f)) * step
     With b==n_deltas this is exactly ARS-V1 behaviour (no truncation).

10. CO-EVOLUTION LOOP (train.py main)
================================================================
Round-robin (Variant A):
  for gen in count() [or range(generations)]:
      for species in target_species:
          for i in range(iter_per_gen):
              trainer.train_step(species, n_eval_ticks=...)
          _save_checkpoint(trainer, species,
                           f"results/policy_{species}.pth")        # per gen

_save_checkpoint writes:
  {'state_dict': policy.state_dict(),
   'obs_stats': {'mean': fp32 (D,), 'var': fp32 (D,), 'count': int}}

KeyboardInterrupt (Ctrl+C):
  - Workers ignore SIGINT (set in _worker_init); only parent catches it.
  - On Ctrl+C: trainer.close() (terminates pool fast), save final
    checkpoints per species, print "Training interrupted; partial
    progress saved", return cleanly (exit 0).

11. KNOWN DISCREPANCIES vs Strategi.pdf / Method.pdf (still open)
================================================================
  1. Observable impacts are now opt-in per project via the
     "Observable by policy" flag (one obs channel per flagged impact).
     Non-flagged impacts still affect the world but are invisible to
     the policy. No longer a hardcoded windfarm_noise channel.
  2. Memory term N(c, t-1) not implemented.
  3. Movement speed v > 1 not supported (cap 1.0; accepted by user).
  4. Positive "Påverkansdelta" (stocking) not supported (accepted).
  5. accessibility map only used for movement masking.
  6. No persistent M*-layers; ARS scaling wins over Method.pdf where
     they differ. Suit_X(c) and four AccessN/E/S/W_X(c) layers
     intentionally skipped for now.
  7. No runtime slider 0–5 + back-scaling pipeline yet. The plan is
     to take 5× headroom in training-map sampling and in the highest
     impact_table breakpoint so explicit back-scaling becomes
     unnecessary for linear impacts (dB impacts still need a
     log/intensity conversion if a true 5× slider is wanted).

13. PERFORMANCE NOTES (already optimized — don't redo without measuring)
================================================================
Implemented:
  - Batched policy inference for all DMs via torch.bmm.
  - Vectorized predation over (N_dm, N_all, H, W) tensors.
  - Slice-assign movement (no np.roll).
  - Preallocated/cached masks (move_mask, eat_static_mask).
  - float32 throughout hot path.
  - Parallel rollouts via multiprocessing.Pool (spawn).
  - OMP/MKL/OPENBLAS/torch threads = 1 in workers (without this,
    BLAS contention can make parallel SLOWER than sequential).
  - CRN: same world for +delta and -delta in each ARS pair; different
    seeds between pairs.
  - ARS-V2 obs normalisation: stats accumulated in env on raw obs,
    merged across all rollouts via Welford parallel formula.
  - ARS-V2 top-b deltas: reduces noise from low-reward pairs.

Measured (60x60, 6 DMs):
  - 100 ticks: 1.257s -> 0.824s (1.53x).
  - 15 iter pelagic_fish: 11.9s seq -> 5.34s @ 16 workers (24-core machine).

Intentionally NOT done:
  - ARS reward baseline subtraction: a no-op for the diff-based update
    (r' = r - b yields (r'+ - r'-) = (r+ - r-)) and std is translation-
    invariant. Sigma_f normalisation already does the job.
  - Numba: hot path is numpy/torch vectorized; would win only at much
    larger grids or for agent-based reformulation.
  - GPU: too small (host-device copy dominates).
  - Synchronous Nash-Q-like co-evolution snapshot.

16. CHECKPOINT FORMAT COMPATIBILITY
================================================================
New format (saved by train.py via _save_checkpoint):
    torch.save({'state_dict': policy.state_dict(),
                'obs_stats': {'mean': fp32(D,), 'var': fp32(D,), 'count': int}},
               path)

Legacy format (older runs, before ARS-V2):
    torch.save(policy.state_dict(), path)     # a plain OrderedDict

Recommended loader pattern (apply to run_mareld_mvp.py and
compare_scenarios.py when they need updating — currently still load as
plain state_dict and ignore obs_stats):

    ckpt = torch.load(path, weights_only=False)
    if isinstance(ckpt, dict) and 'state_dict' in ckpt:
        policy.load_state_dict(ckpt['state_dict'])
        os = ckpt.get('obs_stats')
        if os is not None and apply_obs_norm:
            env.obs_mean = np.broadcast_to(os['mean'], (N_dm, D)).astype(np.float32).copy()
            env.obs_var  = np.broadcast_to(os['var'],  (N_dm, D)).astype(np.float32).copy()
    else:
        policy.load_state_dict(ckpt)         # legacy file
        # No obs_stats available; env will run un-normalised obs.

Notes:
- obs_stats are per-fg in the trainer's dict, but each .pth file stores
  only one fg's stats (the file's own species). When loading multiple
  policies for inference, fold each fg's stats into env.obs_mean/var
  ordered by env.dm_ids.
- During inference (no further updates), keep obs_stats frozen.
- "warm-up": first iteration of a fresh training run sees obs_mean=0,
  obs_var=1 (i.e. effectively un-normalised). Stats become meaningful
  after the first train_step's Welford merge.

17. INFERENCE RUNNER (inference.py)
================================================================
Invoked as `python3 inference.py` with optional flags:
  --project <path>     Project YAML (default: built-in MVP setup).
  --run-name <name>    Loads from results/<name>/ (default "default").
  --checkpoints <dir>  Explicit override of the checkpoint dir; if set,
                       it trumps --run-name.
  --grid n*m           Grid dims (default: 60*60).
  --ticks N            Number of env.step() ticks (default: 100).
  --seed N             Seed for deterministic initial biomass.
  --output PATH.npz    Save per-FG biomass history.
  --quiet              Suppress progress prints.

Impact-map .npz loader (_load_impact_map_npz) is key-agnostic:
  1. If the requested impact_id is a key in the archive AND that array
     is 2-D, use it.
  2. Otherwise pick the first 2-D array in the archive and use it
     (prints a small [info] note naming the actual key).
  3. Only fall back to a zero field when the archive contains no 2-D
     arrays at all.
This means impact-map .npz files in the project YAML can use any
internal key; the mapping is YAML-id -> file, not -> key-inside-file.

Key behaviours (takes the known pitfalls into account):
  - Loads each DM's checkpoint, supports both new format
    ({'state_dict','obs_stats'}) and legacy bare state_dict.
  - Builds (N_dm, D) obs_mean/obs_var aligned to env.dm_ids via per-DM
    lookup (not positional) so reordering between training & inference is
    safe.
  - Falls back to mean=0, var=1 for DMs with missing/empty obs_stats and
    warns loudly (signals likely-degenerate policy behaviour).
  - Calls env._build_static_caches() and env._rebuild_batched_weights()
    so the batched torch.bmm fast path is used.
  - Does NOT update obs_stats during inference (frozen); sigma_f is
    irrelevant since no ARS updates are performed.
  - Untrained DMs (no checkpoint) get a fresh PolicyNetwork and mean=0/
    var=1; warning printed.

Intentionally NOT included yet (extension points):
  - Plotting / scenario comparison (just biomass-history .npz output).
  - Map loading (uses zero impact maps like train.py's env_builder).
  - Multi-seed averaging or batch inference.

18. RUN-NAME / CHECKPOINT ISOLATION
================================================================
Both train.py and inference.py accept --run-name (default "default").
Effect:
  - train.py saves every per-generation checkpoint to
      results/<run-name>/policy_<fg>.pth
    (created if missing). KeyboardInterrupt save and --resume read
    from the same directory. There is NO timestamp/uid in the path:
    re-running with the same --run-name OVERWRITES.
  - inference.py loads from results/<run-name>/ unless --checkpoints
    is given explicitly (then --checkpoints trumps --run-name).
  - Old loose checkpoints at results/policy_*.pth (pre-run-name) are
    NOT auto-migrated. Move them to results/default/ if you want them

  - Backup-by-move pattern (`mkdir results/_backup_pre_X && mv
    results/policy_*.pth ...`) is OBSOLETE — use a fresh --run-name
    instead, that's the whole point of the flag.

19. ACTION-HACK FLAGS + PROFILES (action-distribution shaping)
================================================================
The trainer can apply four "action-distribution hacks" on top of the
biology-driven fitness (alpha*delta_b + beta*delta_r). Per
konvergensproblem.txt's "INSIKT 2" these are symptom-painting and
should NOT be the main force; the profiles therefore disable all of
them and let biology drive.

Flags (all live in train.py, all behave as no-ops when zero/off):
  --argmax_penalty F        Subtract F * argmax_fraction from fitness.
                            CLI default 0.3; profiles force 0.0.
  --entropy_coef F          Add F * (H/H_max) to fitness. CLI default
                            0.1; profiles force 0.0.
  --temp_start T0
  --temp_end   T1
  --temp_anneal_gens G      Softmax temperature linearly annealed from
                            T0 to T1 over G generations, then held at
                            T1. CLI defaults 3.0/1.0/10; profiles
                            force T0=T1=1.0 (no shaping).
  --uniform_bias_init       PolicyNetwork.__init__ zeros the output
                            bias and multiplies the output weights by
                            0.01, so gen-1 softmax is ~uniform across
                            actions. Verified to change seals gen-1
                            sampling from rs=84-92% to rs=27% — but
                            does NOT prevent the rest-attractor from
                            reforming over a few ARS iterations.
                            Tests: tests/test_uniform_bias_init.py
                            (16/16). Off by default; profiles keep off.

Profiles (--profile sanity|info|deep) — recommended hyperparameter
stacks; profile values trump explicit conflicting flags after a
[Y/n] override prompt that lists each overridden value:
  sanity  generations=10, iter_per_gen=15, n_deltas=16,
          n_eval_ticks=100, temp_anneal_gens=8
  info    generations=40, iter_per_gen=20, n_deltas=16,
          n_eval_ticks=150, temp_anneal_gens=30
  deep    generations=80, iter_per_gen=20, n_deltas=20,
          n_eval_ticks=200, temp_anneal_gens=60
All three set coevolution=True, argmax_penalty=0.0, entropy_coef=0.0,
temp_start=temp_end=1.0, uniform_bias_init=False.

20. SPAWN / SUB-THRESHOLD FIX (structural, not action-hack)
================================================================
Discovered cause of the seals/porpoises "rest=100%" attractor:
min_split_biomass=50 kg in fg_library.yaml for seals AND porpoises
combined with seals total=25 ton / 60x60 grid = 6.94 kg/cell means
the vast majority of seal cells were under-threshold from tick 1.
The OLD rule zeroed the 4 move-actions in those cells; the rest/eat
renormalisation, plus the zero-total fallback (forced rest=1 in cells
without prey), made rest=100% a HARD RULE, not a learned policy.

Two coordinated fixes implemented:

DEL 1 — Cluster-spawn in lib/config/config_loader.py:
  New helper _spawn_biomass_distribution(grid, total_b, min_per_cell,
  allowed_mask, rng):
    * Eligible cells = allowed_mask>0 (None => full grid).
    * Per-cell floor = 10 * min_split_biomass (so predation/mortality
      doesn't immediately drop a cell under the threshold).
    * Loop: random cell pick (no replacement), biomass drawn uniformly
      in [floor, min(total_b, remaining)], assign, repeat while
      remaining >= floor.
    * Leftover (<floor) is merged into a randomly chosen already-
      seeded cell — total biomass exactly preserved.
    * Edge cases: if floor==0 (e.g. zooplankton/gadoids), falls back
      to legacy uniform-Dirichlet spread. If no seed could be placed
      (total < floor), dumps everything in one random cell.
  allowed_mask is currently passed as None (mareld2.yaml has no
  accessibility map yet); the hook is wired and ready.
  Both setup_full_mareld_mvp and load_project_config use the helper.

DEL 2 — Sub-threshold collapse in lib/environments/ecosystem.py:
  * Removed the 4-action move-mask zeroing on B < min_split.
  * After softmax, compute sub_thr_mask = (B>0) & (B<min_split),
    take argmax over the full 11-action distribution per such cell,
    and replace that cell's distribution with a one-hot. Whole group
    performs one action on 100% of the cell biomass (including move,
    so small groups CAN migrate together — "variant 2" in design).
  * Reward path unchanged (eat still grants energy, move still moves
    biomass, etc.).

Verified empirically (20-gen, no action-hacks, --profile info-ish):
  seals gen-1 iter-1 sampling: 44/28/28 H=54% (move-dominant!) vs
  pre-fix 08/12/84-92 H=07%. Mechanically the fix works. However
  ARS still drags seals to rs=100% from gen 2 onward — proving the
  remaining attractor is STRUCTURAL (no predator above seals = no
  channel-b feedback; slow population dynamics = weak channel-a),
  not mask-driven. Same for porpoises after the fix.

21. CO-EVOLUTION (default training mode)
================================================================
Implemented in lib/runners/trainer.py::train_step_coevolution and
lib/runners/parallel_worker.py::_evaluate_coevo_task. Default ON
(--no_coevolution to fall back to round-robin).

Mechanics:
  * Per ARS iteration: sample one independent delta per species, share
    a common rollout seed (CRN) across the +/- halves.
  * Build 2*n_deltas joint rollouts where ALL DM policies are
    perturbed simultaneously (+sigma*delta_fid for the + half,
    -sigma*delta_fid for the - half). Each rollout returns one
    fitness per species.
  * ARS update is per-species, using THAT species' own deltas and
    its own r_pos/r_neg vector. No cross-species delta leakage.
  * Effect (vs round-robin): predator/prey feedback materialises
    inside the same rollout instead of being averaged out against a
    frozen opponent. Documented "channel (b)" in konvergensproblem.txt.

Empirical signature (reproducible across hyperparameter configs):
  * Zooplankton "escape" from rest=100% to ~rs/et=40/60 around gen
    13-20 once pelagic_fish predation pressure ramps up. Observed
    in 3+ independent runs (with and without action-hacks, with and
    without spawn-fix). The mechanism is robust.
  * Seals/porpoises rest=100% attractor: structural, robust to every
    intervention tried (argmax_penalty, entropy_coef, temp, uniform-
    bias-init, spawn-fix, adding pelagic_fish as seal prey). Likely
    a genuine ARS optimum for a sated top-predator on 150-tick
    rollouts without a predator above them.
  * Gadoids reach POSITIVE reward (+0.04..+0.07) once hacks are off
    — the only species that does, indicating they have a sustainable
    rest/eat mix on the current biology.
  * Pelagic_fish converges to mv-dominant (74-98%) "flee" policy;
    the exact level depends on co-evolution kaskad effects (mildare
    with longer rollouts and other species' policies in flux).

Kept eval snapshots: results/coev_5gen_100ticks_eval,
results/coev_20gen_100ticks_eval, results/coev_info_profile_40gen,
results/coev_20gen_noHacks, results/coev_info_20gen_postSpawnFix.

22. DESIGN PRINCIPLE: BIOLOGY DRIVES, NOT ACTION-HACKS
================================================================
Crystallised in konvergensproblem.txt (read that file for the long
story; this section is the operational summary).

Rule of thumb when adding a fix:
  1. If it shapes the action distribution (penalty/bonus on action
     fractions, entropy, temperature, eps-greedy, action bias init)
     it is an ACTION-HACK. Hide behind a flag and keep OFF in
     profiles. Use only for diagnostics, never as the primary force.
  2. If it changes the biological/structural setup (spawn
     distribution, min_split rule semantics, food web edges in
     fg_library.yaml, impact mortality tables, integral-reward
     formulation, co-evolution rollout structure) it is a
     STRUCTURAL fix. Prefer these.

The "evaluate by action histogram" lens (mv/rs/et fractions =
quality) is officially deprecated. Quality must be evaluated by
biomass trajectories over long inference rollouts, predator-prey
cycles, response to impact fields, and comparison against
Baltic-Sea field data. The next major work item is building that
ecosystem-validation pipeline, NOT more hyperparameter sweeps.

Known open structural items (likely worth attacking next):
  * benthic_community grows 27x over 10000-tick inference because no
    DM predates it and its K is soft — an fg_library.yaml/ecology
    question, not training. Still present after the latest YAML
    update (all `*_preys_on_benthic_community: false`).
  * No predator above seals/porpoises in mareld2.yaml -> top-
    predator rest-attractor is mechanistically rational. Either
    accept as biology (verify with long-rollout biomass plots) or
    add a hunting/disease impact map.
  * accessibility map exists in code (movement masking) but is NOT
    yet threaded to _spawn_biomass_distribution.allowed_mask. Hook
    is ready in lib/config/config_loader.py.
  * min_split_biomass=50 kg still set for porpoises and seals in the
    current fg_library.yaml. Cluster-spawn + sub-threshold collapse
    (section 20) mitigates the old hard rest-attractor, but the
    one-hot argmax fallback is still constantly active for top
    predators if typical per-cell biomass < threshold.
  * Dead parameter: `seals_preys_on_pelagic_fish` has
    `preys_on: false` but a leftover `max_intake_rate: 0.012` —
    harmless at runtime, worth cleaning for clarity.

23. BIOLOGICAL SANITY CHECK FORMULA (one-liner gate before training)
================================================================
Per Strategi.pdf + konvergensproblem.txt "Kritisk insikt 4". For each
DM species, compute per-tick energy balance at full hunger (h=1) and
require netto_eat > rest_cost; otherwise `rest` is the structural
global optimum regardless of how ARS is trained ("rest-always-
collapse"). Cross-check `move` for top predators too.

  intake_at_h1 = max_intake_rate * energy_gain         # of best prey
  feed_cost    = feeding_cost    * resting_metabolism
  rest_cost    = resting_cost    * resting_metabolism  # resting_cost=1
  move_cost    = movement_cost   * resting_metabolism  # per tick moving

  netto_eat = intake_at_h1 - feed_cost                 # MUST be > 0
  Hard gate:        netto_eat > rest_cost
  Soft gate (move): netto_eat > move_cost              (else move always
                                                        suboptimal vs rest+eat)

History on mareld2.yaml / fg_library.yaml:
  * Pre-update (see previous review): porpoises -148, seabirds -133,
    seals -38.75 (all MJ/tick at h=1). Eat structurally worse than
    rest -> rest=100% attractor was a parameter bug, not an ML bug.
  * Post-update (current YAML, sanity script in section 24):
        zooplankton  netto_eat=+101.4  eat-rest=+98.9   eat-move=+101.4
        pelagic_fish netto_eat=+84.8   eat-rest=+76.8   eat-move=+67.6
        gadoids      netto_eat=+564.5  eat-rest=+558.5  eat-move=+553.4
        porpoises    netto_eat=+95.0   eat-rest=+33.0   eat-move=-91.0 *
        seals        netto_eat=+147.5  eat-rest=+122.5  eat-move=+85.0
        seabirds     netto_eat=+493.5  eat-rest=+403.5  eat-move=+133.5
    All DMs pass the hard gate (eat > rest). PORPOISES fails the
    soft gate (move 186 > eat 95) — a single move tick costs more
    than a single eat tick yields, so move is only justified by
    paying back over several eat ticks in a better cell. Risk of
    blocked exploration on short rollouts. Not a rest-collapse but
    worth watching.

24. SANITY-CHECK SNIPPET (run before every training session)
================================================================
Standalone python snippet (paste into a shell). Pull I, E_prey,
feeding_cost, resting_metabolism, resting_cost, movement_cost from
fg_library.yaml for each DM and its best prey:

  rows = [
    # (name, I, E_prey, feeding_cost, SMR, resting_cost, movement_cost)
    ('zooplankton',  0.175, 600,  1.45, 2.5, 1.0, 0.0 ),
    ('pelagic_fish', 0.04,  2500, 1.9,  8.0, 1.0, 2.15),
    ('gadoids',      0.115, 5000, 1.75, 6.0, 1.0, 1.85),
    ('porpoises',    0.05,  5000, 2.5,  62., 1.0, 3.0 ),
    ('seals',        0.05,  4000, 2.1,  25., 1.0, 2.5 ),
    ('seabirds',     0.15,  5000, 2.85, 90., 1.0, 4.0 ),
  ]
  for n,I,E,fc,smr,rc,mc in rows:
      intake = I*E; feed = fc*smr; netto = intake - feed
      rest = rc*smr; move = mc*smr
      print(f"{n:14} netto={netto:8.1f} eat-rest={netto-rest:8.1f} "
            f"eat-move={netto-move:8.1f}")

Acceptance criterion: every line must have netto>0 and eat-rest>0.
eat-move<0 is a warning, not a stop, but flag it.

25. RUNNING TRAINING/INFERENCE NON-INTERACTIVELY (gotcha)
================================================================
train.py has TWO interactive prompts that block in any non-tty
environment (CI, agent bg shell, nohup without redirected stdin):
  * train.py:418  "Continue with profile values? [Y/n]:" — only fires
                  when explicit flags conflict with --profile.
  * train.py:542  "Continue with these parameters? [Y/n]:" — always
                  fires after the session header.
Both default to "yes" on empty Enter. If you launch the process
without a real stdin you'll see the header, the prompt line, and
then NOTHING (process sleeps in `input()` at ~0.8% CPU, no workers
spawned). Workaround for unattended runs:

    yes "" | python -u train.py --profile info --project mareld2.yaml \
                                --run-name <name>

  * `yes ""` feeds an endless stream of empty lines (each accepted as
    the default "yes").
  * `python -u` is REQUIRED — otherwise stdout is fully buffered
    when stdout is a pipe and no progress is visible until the
    buffer fills (hundreds of MB later).

EXPLICIT FLAGS CAN'T OVERRIDE A PROFILE: profile values are applied
unconditionally after the [Y/n] override prompt. To run "info" with
a different generation count, EDIT the PROFILES dict in train.py
(around line 345) — not the CLI flag. Example: changed
PROFILES["info"]["generations"] from "40" to "10" for the 10-gen
sanity inference session.

Inference (inference.py) has no interactive prompts; safe to run
non-interactively with default stdin.
