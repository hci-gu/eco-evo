Mareld Codebase Report

A short map of the repo: what it is, how to run it, where code belongs, how training and inference work, and exactly where network actions become world changes.

What this is

An ecosystem simulator called Mareld. It trains small neural policies for decision-making functional groups on a 2D biomass grid.

Core idea

Each species has biomass and energy per cell. Policies choose action fractions per cell. The environment applies those fractions to predation, action energy costs, movement, population change, and cleanup.

Main files

train.py, inference.py, lib/environments/ecosystem_env/, lib/runners/trainer.py, lib/config/config_loader.py.

Common commands 
# edit YAML project
python fgconfig/fgconfig.py

# train, then press Enter to confirm
python train.py --project mareld2.yaml --run-name myrun --profile sanity

# run inference from checkpoints
python inference.py --project mareld2.yaml --run-name myrun --ticks 100 --visual

# HTTP API
python api.py --host 127.0.0.1 --port 8000

Checkpoint note: inference needs results/<run-name>/policy_*.pth files that match the active decision makers, observability matrix, and policy architecture.

What is trained

Only functional groups with is_decision_maker: true get policies. Current mareld2.yaml keeps gadoids, pelagic_fish, and zooplankton active as decision makers; porpoises, seabirds, seals, and benthic community are muted in that project file.

Policy shape

Each policy sees a compact observation window: own biomass and energy, observed other groups, and the same biomass context for the four neighbor cells. Output is always 5 + number_of_functional_groups: move north/east/south/west, rest, and one eat slot per global functional group.

Environment Logic: How Actions Become World Changes

The key point: the environment loop is now explicit. Callers build an observation, run a policy/controller forward pass, then pass ActionProbabilities into env.step(actions).

flowchart TD O["env.get_observation()"] --> OB["ObservationBatch: features + masks"] OB --> PF["policy_controller.forward(observation)"] PF --> AP["ActionProbabilities: move, rest, eat"] AP --> ST["env.step(actions)"] ST --> PR["Predation and temporary energy gains"] PR --> EC["apply_energy_costs: rest/eat/move costs"] EC --> AS["ActionSettlement"] AS --> MV["apply_movement: spatial transfer + migration"] MV --> PC["apply_population_change"] PC --> CL["threshold biomass cleanup + empty-cell energy cleanup"] CL --> HS["update_hidden_state for next observation"]
Where this lives
  • lib/environments/ecosystem.py is only a compatibility shim.
  • ecosystem_env/environment.py owns public orchestration and tick order.
  • ecosystem_env/observations.py builds raw observation features.
  • ecosystem_env/decisions.py builds masks, normalizes observations, converts probabilities to actions, and updates hidden-state memory.
  • ecosystem_env/policies.py owns batched policy forward and fallback logits.
  • ecosystem_env/predation.py applies predation and predator energy gains.
  • ecosystem_env/movement.py applies action costs, movement, and migration.
  • ecosystem_env/population_change.py applies biomass growth/starvation and final cleanup.
World state

Every functional group owns two main grids: biomass and energy_reserve. These are NumPy arrays with shape (height, width). Grid maps such as accessibility and uploaded API rasters live in env.grid.maps.

Pressure effects are not part of the current environment transition.

Action Interpretation, Step by Step

StepPlain meaningCode
1. Observe For each decision maker and cell, gather own biomass, own energy, visible observed species, and neighbor-cell versions. The returned ObservationBatch also carries the action mask. environment.get_observation; decisions.build_observation; observations.build_observation_batch
2. Policy forward The controller runs policy logits for move N/E/S/W, rest, and eat-each-FG. Illegal actions are masked before softmax. policies.PolicyController.forward; decisions.masked_softmax
3. Action object The softmax output becomes ActionProbabilities: move, rest, and eat. The old env.pi_move, env.pi_rest, and env.pi_eat fields no longer exist. state.ActionProbabilities; decisions.actions_from_probabilities
4. Hiding rest also means hiding. Current predation uses actions.rest directly, and the same rest fraction is stored after the step as prev_hidden_frac for the next observation. interactions.visible_biomass_from_hide; decisions.update_hidden_state
5. Predation Predator demand is based on predator biomass, eat fraction, hunger, max intake, and optional Holling Type II handling time. Demand is capped by visible prey biomass. Prey loses biomass/energy; predator gets temporary energy gain. predation.apply_predation
6. Energy costs Rest, eat, and move fractions pay their respective energy costs. Eat fractions also receive temporary energy gains from predation. The result is an ActionSettlement. movement.apply_energy_costs; state.ActionSettlement
7. Movement Only the already-settled moving partition is transported across grid cells according to movement speed. If migration is on, edge outflow re-enters through weighted edge cells. movement.apply_movement
8. Population change Non-decision makers follow carrying-capacity dynamics with optional seasonality and seeding. Decision makers grow or starve from energy level relative to maintenance level, with optional natural mortality. population_change.apply_population_change
9. Cleanup Final population cleanup clips biomass below extinction_threshold_factor * min_split_biomass to zero and clears energy in empty biomass cells. This no longer records extinction events or adds cleanup loss to starvation diagnostics. population_change._clip_biomass_based_on_min_thresholds; population_change._zero_energy_in_empty_cells

Action Space

action index:
0 = move north
1 = move east
2 = move south
3 = move west
4 = rest / hide
5.. = eat functional group in sorted global_fg_order

The softmax runs over this entire vector at once for every decision-maker and every cell. After softmax, the vector becomes:

actions.move
  shape: decision_maker x 4 directions x height x width

actions.rest
  shape: decision_maker x height x width

actions.eat
  shape: decision_maker x prey_slot x height x width

This means a cell can do several things proportionally in the same tick. If a cell has actions.move east = 0.30, actions.rest = 0.20, and actions.eat zooplankton = 0.50, then 30% of that biomass enters the moving partition, 20% rests/hides, and 50% enters feeding. Movement is further scaled by species movement speed, and eating is further limited by hunger, max intake, prey availability, and predation caps.

Eat slots exist for every functional group so all policies share one output layout, but non-menu slots are permanently masked out before softmax. Invalid movement directions and eat actions with no prey present are also masked before softmax.
